このアプリについて

何をどこから引いていて、それをどう解釈して A / B / C になっているか。 判定の基準・データの参照元・そしてどこで妥協しているかをまとめてあります。

← アプリに戻る

これは予報であって、保証ではありません。 A / B / C は気象庁のモデルが出した数値をいくつかの閾値と比べているだけで、 現地の地形・積雪・体力・装備は見ていません。⚠ 山の天気は急変します。 最終的な判断はご自身で。どこまで信用してよいかは「4. どこで妥協しているか」に書きました。

1. データはどこから来ているか

すべて公開されている情報源です。独自の観測や独自の予報計算はしていません。

何をどこから

気温・体感・降水・降雪・風・気圧・雲量		 Open-Meteo Forecast API
モデルは 気象庁（JMA）の jma_seamless。1時間ごと、実績3日＋予報9日

風速は m/s を明示して取得しています。Open-Meteo の既定は km/h で、 かつて取り違えたまま判定に流し、表示が約3.6倍・判定が約3.6倍厳しくなる事故を出しました。 そのとき「判定が厳しすぎる」と誤診して閾値を緩める対症療法まで踏んでおり、 いまは単位の指定が抜けていないかをテストで見張っています。

2. A / B / C はどう決まるか

5つの項目をそれぞれ A・B・C で採点し、いちばん悪かった項目がその時刻の判定になります。 平均は取りません。ひとつでも C があれば C です。

項目ABC
風速 m/s
山頂の高さの風		 5 未満5 〜 1010 以上
体感温度 ℃ -3 より上-15 〜 -3-15 以下
降雪 cm/h 0.5 未満0.5 〜 22 以上
降水 mm/h 1 未満1 〜 33 以上
気圧の変化 hPa
6時間での増減		 6 未満6 〜 1010 以上

降雪と降水は、降っているときだけ採点に入ります（0 のときは判定に影響しません）。 気圧は上がる側も下がる側も、変化の大きさだけを見ます。

雨・雪・突風は「その時刻から1時間のあいだ」の値です。 20時に合わせたときの雨量は、20時から21時のあいだに降る見込みの量です。 気温・気圧・風・雲量は、その時刻ちょうどの値です。

グラフの雨は予報です。外れることがあります。 そこで、気象庁の高解像度降水ナウキャスト（レーダーの実況）を 読んで突き合わせ、予報と実況が食い違っているときだけ 画面の上に帯を出します。グラフの雨のところに出る細い帯が実況で、 直近の1点（数分前）だけです （気象庁の時刻表が実況しか返さないためです。先の時刻が入っていればそのぶんも描きます）。 帯が描かれていない時間は 「降っていない」ではなく「実況が無い」という意味です。

グラフの上で判定の理由が読めます

  • 風 — バーの色が閾値で変わります
  • 降水・降雪 — バーの縁が 橙（B） 赤（C）になります
  • 体感温度 — 気温グラフの下端の細い帯。 寒いほど濃い青になり、B・C の時間は枠で囲みます

体感温度の帯は、寒い側だけ濃くしてあります。

暑い側にも同じだけ色を振ったところ、ふつうの夏日（体感26〜31℃）で帯が終日オレンジになり、 判定は A のまま——という状態になりました。判定に暑い側の基準が無いのが理由です。 いまは熱中症警戒アラート（暑さ指数 WBGT 33）のあたりまで無彩色にしてあります。 暑さの警告そのものは、まだ作っていません。

3. 風だけ、少し特別なことをしている

ふつうの天気予報が出す風速は地上10mの風です。これを山の判定に使うと、実際とかなりずれます。

きっかけは利用者からの報告でした。ある日の皇海山（2,144m）を、他のサービスは C、 こちらは終日 A と判定していたのです。実際に数値を引き直すと、原因ははっきりしていました。

どの高さの風かその時刻の値
地上10m（当時、判定に使っていた値）2.73 m/s
850hPa（約1,460m）4.47 m/s
800hPa（約1,950m・山頂に近い）21.02 m/s
700hPa（約3,010m）28.86 m/s

そこで山頂の標高にいちばん近い気圧面の風を判定に使うようにしました。 山頂の標高は国土地理院の標高データから読みます。窓の下に @1950m のように、どの高さの風で判定したかが出ます。

この仕組みには続きがあります。当初は「山頂がモデルの地形より十分高いときだけ気圧面を使う」という 安全弁を付けていたのですが、データ提供側の仕様が変わり、 110峰のうち109峰がその弁に引っかかって、黙って地上10mの風に落ちていました。 ランキングでは C なのに詳細画面では A、という食い違いも起きていました。いまは安全弁を外し、 見るのは山頂の標高だけにしてあります。

もう1つ、およそ3日半より先の予報では、800hPa などの一部の気圧面のデータがありません （粗い全球モデルに切り替わり、その高さの値が配信されないため）。以前はここでも黙って地上10mの風に 落ちていました。いまは上下にある気圧面の風から、その時刻の実際の高さを使って山頂の高さへ按分し、 窓に「按分」と出します。それもできない時刻は判定を出さず「—」にします （データが無いことを「安全」とは扱いません）。

いまの予報がどのモデルかは、チャートのいちばん上の帯に出しています （MSM＝青・移行＝橙・GSM（粗い）＝灰紫）。 「移行」は MSM が尽きる直前の約5時間で、MSM と GSM の混じった値です。押した時刻の窓にも「モデル：…」と出ます。 ⚠ この判別は風のデータが尽きる時刻で見ています。気温・降水・雲が同じ時刻で切り替わるかは確かめていません。 判別できないときは「不明」と出し、MSM とは言いません。

予報モデルは切り替えられます。画面右上のチップ（JMA ▾）から、気象庁（既定）・GFS（米国）・ ICON（ドイツ）・ECMWF（欧州）を選べます。選んだモデルの値で、チャートも判定（A/B/C）も出します。 JMA 以外を選んでいる間は、チップとヘッダーの下線が橙になります。 地点を変えても選んだモデルのままで、アプリを開き直すと JMA に戻ります。 取得に失敗したときは、表示は直前のデータのままで、理由を帯で出します。 ⚠ 山岳の風はモデルによる差が大きく（12日分を調べた範囲では、同じ山の平均が2倍近く違う日もありました）、 JMA 以外の精度は、まだ実測と比べていません。地図の風とランキングは、いつも JMA です。

4. どこで妥協しているか

ここがいちばん大事です。判定は単純な仕組みなので、 分かったうえで使わないと読み違えます。

判定のしかた

  • 5項目の最悪値がその時刻の判定。平均も加重もしません。 「B が3つ」より「C が1つ」が悪い、という考え方です
  • ⚠ 継続時間を見ていません。1時間だけの C も、6時間続く C も同じ C です
  • 降水・降雪は降っているときだけ採点に入ります。0 のときは判定に影響しません
  • 気圧は変化の大きさだけを見ます。上昇も下降も同じ扱いです
  • 閾値は日帰りの基準です（幕営向けの切替は撤去しました）

風

  • 使うのは山頂の高さに近い気圧面の風ですが、層は6つしかありません （925 / 900 / 850 / 800 / 700 / 600 hPa ≒ 760 / 990 / 1,460 / 1,950 / 3,010 / 4,200 m）。 ⚠ いちばん近い層に丸めます。たとえば 1,700m の山は 1,460m か 1,950m の値になります
  • ⚠⚠ モデル格子の値なので、稜線やコルでの増速は入っていません。 実際の稜線はこれより強いことがあります
  • 気象庁モデルの格子は細かいほうでも約5km。 孤立峰や細い尾根は平滑化されて潰れます
  • 突風は表示だけで、判定には使っていません
  • ⚠ 突風は目安です。Open-Meteo の突風は地上10mだけで、山頂の突風はありません。 山では地上10mの突風が山頂の風より小さく出ることが多く、そのまま使えません。 そこで山頂の風に、世界気象機関（WMO）の突風率 1.75 を掛けて出しています （幅は ±0.1。出典は WMO/TD-1555 の Table 1.1「ほぼ開けた地形」・1時間平均に対する3秒突風）。 ⚠ これは平地・強風の値で、山岳は資料の範囲外です。山頂ではもっと大きくなる可能性があります。 山頂の風が 3m/s 未満のときは出しません
  • 地図の風の矢印は、既定（AUTO）では場所ごとに高さを自動で選びます。 升目の稜線の高さ（高い方から1割の標高）に対して、その時刻の気圧面の実際の高さから 上下の層を按分します。判定（A/B/C）の層の選び方とは別の仕組みです
  • ⚠ 地表に近いところ（谷や、稜線が低い所）は、地上10mの風と上の層を高さで按分した推定値です。 物理的に正確なつなぎ方ではありません。矢印が点線で、押すと「不確かさあり」と出ます
  • 地図の風は約3日半より先で粗いモデル（約50km）に変わり、800・900hPa の層が無くなります。 層を手動で選んでいるときは、無い時間帯を「データなし」と出します（別の層で埋めません）。 AUTO でその層を飛ばして上下から按分したときは推定値（点線）と出します
  • 地図の風の矢印を押すと、山頂付近（升目の最高点）の高さの風も添えます。 矢印が表すのは稜線の帯の代表の高さなので、山頂の風はそれより強いことがあります
  • 「風の流れ」は矢印と同じ風を粒子で流したものです。粒の速さは見やすさのための速さで、 風の強さに比例しますが実寸ではありません（無風に近い日は粒がほとんど動きません）。 風の強さは背景の色で読めます（設定で「色:粒」にすると粒の色で）。元のデータは約11km（先の予報は約50km）の格子なので、 谷筋ひとつひとつの風までは表せません
  • ⚠ 「風の流れ」の設定で補正を入れると、尾根の風下の陰で粒を遅く、風が稜線を越えるコル（鞍部）の周りで速く描き、 コルへ集まるように向きも少し曲げます。これは地形から見た目を作る表示用の推定で、観測や計算で確かめた風ではありません。 補正を入れているときの色は、この見た目の速さに合わせて変わります（モデルの風速ではありません）。 矢印・押したときの説明・判定（A/B/C）はいつもモデルの風のままです

降雪の目安（地図）

  • ⚠⚠ 予報モデルの値で、観測ではありません。実際に降っているかは、降雨レーダー（観測）で確認してください。 判定（A/B/C）にも使っていません
  • 気温は、モデルの標高から稜線の高さ（基準の標高）へ 1,000m あたり 6.5℃ で補正して、 雪 0.5℃以下・みぞれ 2.0℃以下・それより上は雨に分けています。 ⚠ この境の気温は仮置きです。補正の誤差も 1〜2℃あるので、境の近くは当てにならず、湿度や風でも変わります
  • 降水は先の1時間の量で、0.1mm 未満の所には記号を置きません。 記号を置く格子は約11km四方で、その中の一部だけ降っていることも、降っていないこともあります
  • 3日半より先は粗いモデル（約50km）に変わります。記号を押すと、どちらのモデルの値か出ます

雷雨の目安（地図）

  • ⚠⚠ 予報モデルの値で、観測ではありません。実際の雷は雷ナウキャスト（観測）で確認してください。 判定（A/B/C）にも使っていません
  • ショワルター安定指数（SSI）は、850hPa（約1,500m）の空気塊を持ち上げたときの 500hPa（約5,500m）での温度を、実際の 500hPa の気温から引いた値です。 小さい（負の）ほど大気が不安定で、雷雨が起きやすい目安になります
  • 分け方：SSI 0 以下で不安定、-3 以下で雷雨の可能性、-6 以下で激しい雷雨の可能性、-9 以下で激しい雷雨の可能性大。 0 を超える（安定）所には記号を置きません
  • ⚠ 記号が無い＝雷が無い、ではありません。安定の所・計算できない所・まだ取得できていない所が含まれます。 高い山では 850hPa 面が地面より下になるため計算できず、その旨を画面に出します
  • SSI は雷雨の起きやすさで、雷が起きる場所や時刻そのものではありません。格子は約11km四方です

体感温度

  • ⚠⚠ 判定は寒い側だけ。暑い側の閾値が無く、 熱中症の警告は出していません
  • 帯の暑い側の色は暫定です。apparent_temperature は 熱中症の基準である暑さ指数（WBGT）とは別物で、公式の換算がありません

気圧

  • ⚠⚠ 画面の色と判定の閾値が食い違っています。 6時間で 3 hPa 動くと警告色が付きはじめますが、判定が B になるのは 6、C は 10 です。 色が付いていても判定は A ということが起きます（分かっていて直していません）

標高

  • 山頂の標高は座標から国土地理院の標高データを引きます。 ⚠ 座標が山頂からずれていると斜面の標高を読み、 判定に使う風の層もそのぶんずれます

予報そのもの

  • 2日より先には「◯日先・確度中／低」と出しますが、 ⚠ これは実測した的中率ではありません。 「何日先か」から引いた一般的な目安です（5日より先が「低」）
  • 実績3日＋予報9日を要求していますが、 実際に何日先まで返るかはモデル次第です

圏外のとき

  • 電波が届く所で開いたときの予報を端末に控えておき、 圏外ではそれを表示します。⚠ そのときは画面の上に橙色の帯が出て、 いつ・どこで取ったものかを示します。数字が新しいかどうかは帯で判断してください
  • ⚠ 取ってから24時間を超えたものは表示しません。 「古すぎる」とだけ出て、数字は更新されません
  • ぴったり同じ地点の控えが無いときは、20km以内でいちばん近いものを使います。 ⚠ そのぶん離れた場所の予報です。帯に「◯km先」と出ます
  • ⚠ アプリを閉じている間に自動で取りに行くことはできません。 スマートフォンのブラウザには、閉じたアプリを定期的に動かす仕組みがないためです。 山へ入る前に、電波のある所で一度開いてください

大きな判断は記録として残してあります。かいつまむと次のとおりです。

6. まだ足りていないこと

  • 暑い側の判定（熱中症の警告）が無い。いまの判定は寒い側しか見ていません
  • 気圧の色と判定の食い違い（上記）を直していません
  • 山頂高度の風による判定が、実際の予報と合うかを実機で確かめきれていません
  • 地図の気圧配置と等圧線は、一度作って外しました（方式から練り直しが要ります）
  • 再利用・再配布の条件（ライセンス）は決まっていません
