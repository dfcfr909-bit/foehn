# 尾根・沢の比較：LANDMARK vs 現行 terrainFlow（2026-09-30）

`findings5.md` の続き。既存の計算結果・スクリプト・本番コードは変更していない（experiments/landmark/ に新規ファイルのみ）。窓は追加していない。計算は10mまで。

## 前提

- **鞍部は現行の `terrainFindCols` を継続する。** 根拠は findings5.md：偶然を大きく上回る Recall は両手法とも出たが、OSM 基準で LANDMARK 15/20・現行 14/20 と差がなく、LANDMARK は候補数が現行の 2.5〜15倍多い（10m で 15,811 件対 1,082 件）。saddle の追加検証は行わない。
- 対象：findings4/5 と同じ10窓（男体山・常念乗越・w01〜w08）、10m と 30m。窓の端・DEM 欠測帯から100m以内は評価から除く。

## 方法

### 現行方式（本番の JS を原文のまま node で実行。Python の再実装ではない）
- `runProdFlow.mjs` が `sotoki_v4.html` から `COL`・`terrainFindCols`・`FLOW`・`bearingOf`・`terrainFlow`・`VEC` と線にする一式（`terrainVectorize`・細線化・ヒゲ刈り・ならし）を**文字列で抜き出して**実行する。本番コードは書き換えていない。
- 差し替えたのは `G.toLL`（地図が要るので座標は Python 側で復元）と `G.inner`（全域を採る）だけ。抜き出せない依存は無かった（`bearingOf` を足しただけ）。
- **稜線のつなぎ（`BRIDGE_*`）は2通り**：つなぎ有（本番と同じ。`cols` を渡す）／つなぎ無（`cols` を空で渡す）。
- 入力の格子は、本番の「地理院 z12 タイルを平均した約30m」ではなく、**両手法に同じ DEM**（窓の 30m・10m の GeoTIFF）を与えた。本番の格子と完全には同じではない。
- **⚠ 本番は約30mの格子で作られている。** 10m の格子に同じコードを当てた結果（稜線が1,000本超に細切れになる等）は、設計外の使い方の結果。like-for-like は 30m の行。10m の行は解像度への反応を見るもの。

### 長さ合わせ（沢の階層）
- 現行方式の**既定の定数**の網（`PR_*`）は、LANDMARK の hso≧5 より疎で、全長が合わない（30m で139km 対 419km）。
- そこで、**同じコードのまま閾値の定数だけ**（`FLOW.VALLEY_SCA_M`＝600、`VALLEY_POWER`＝0、`RIDGE_HAND_M`＝5、`VEC.VALLEY_MIN_SCA`＝600、`VEC.RIDGE_MIN_RELIEF`＝5）を下げた「密な網」を別に出し、線を**比集水面積 `sca`（沢）／沢筋からの高さ `relief`（稜線）の大きい順**に足して、**領域内の全長が LANDMARK の対応する階層にもっとも近くなる所で切った**（`PR_v_m5`＝hso≧5 相当、`PR_v_m7`＝hso≧7 相当、`PR_r_m`＝LANDMARK 既定の尾根と同じ長さ）。
- 全長の合わせ具合（10窓・領域内）：沢は 30m で 419→418km・90→91km、10m で 670→669km・317→317km とほぼ一致。**稜線は 764km に対し 666km（30m）・675km（10m）までしか届かなかった**（男体山・w02・w03 は密な網でも足りない）。

### LANDMARK
- 既定閾値（尾根 A_spread≧1e5・沢 A_out≧1e5）の出力。沢は hso≧4 を hso≧5・≧7 に絞った。既存2窓の出力は流用、新規8窓は10m・30mで実行（`run_landmark_lines.py`。10m は1窓約2分、30m は約8秒）。

### 基準（OSM）
- 取得元：OpenStreetMap（Overpass API `overpass-api.de`）。取得日時 2026-09-30 UTC（06:29〜06:51）。窓＋500m の矩形ごと。
- 件数（要素数。10窓合計）：沢 `waterway=river/stream` 662本、`natural=ridge/arete` 71本、水面（`natural=water`・`waterway=riverbank`・`landuse=reservoir`）68件。
- 評価領域内の長さ：**沢 264km**、尾根線 27.5km（男体山 2.1km・w01 25.4km。ほかの8窓は0）。
- ⚠ 重い窓で Overpass が 504 を返したので、線状の地物と水面の2回に分けて取り直した（内容は同じ）。

### 物差し
- `scripts/probeDemRes.mjs`（現在のツリーに無く、過去のコミット `9f79c37` にだけある）の定義を踏襲した：OSM の線を5mおきにサンプル／**精度相当**＝検出した線のうち基準線から d 以内の長さの割合／**再現相当**＝基準線のうち検出した線から d 以内の長さの割合／欠測帯の近くは評価から外す。d＝30m・50m。
- **使えなかった部分**：`probeDemRes.mjs` そのものは、Chromium で本番アプリ全体を動かして地理院タイルを取る Actions 前提の実験で、LANDMARK の線を入れられず、窓の DEM も使えない。定義だけ Python で測り直した。
- **⚠ OSM の沢は、小さな沢ほど載っていない。** OSM 沢は領域内で 0.86km/km²、LANDMARK hso≧5 は 1.4〜2.2km/km²。そのため**精度相当は実際より低めに出る**。両手法を同じ基準で測っているので、相対比較には使えるが、絶対値は控えめ。

### 偶然の値（作業3）
- 基準（OSM の線）を窓の中心まわりに**ランダムに回転（0〜360°）・平行移動（±1,500m）**させ、同じ指標を100回。シード固定（20260930）。精度相当の分母は、動かした基準の取得範囲がカバーする所だけ。10窓を合算し、表は平均と95%範囲（2.5〜97.5パーセンタイル）。

| 10m | 現行 沢 既定の定数 | 0.3（0.1%） | 0 |
| 10m | LANDMARK 尾根 | 0.87（0.1%） | 0 |

**確認済みの事実**：LANDMARK は湖・ため池の水面を横切る沢線を引く（hso≧7 で全長の8〜17%）。水面のある窓に偏り、hso≧7・30m では w02 が 17km 中 7.9km（約半分）、w05 が 11km 中 3.3km、w08 が 8km 中 3.2km、男体山が 8km 中 0.6km。現行方式は自前の平坦地の判定（`FLAT_*`）で湖面を避けるため、ほとんど乗らない（既定で0.1〜0.3%）。尾根線は両手法とも平坦面にほぼ乗らない。

### 平坦面・水面をマスクしたときの指標（沢・OSM基準・10窓合計。精度相当／再現相当）

**確認済みの事実**：マスクで LANDMARK の精度相当は 2〜4pt 下がる（湖面の沢線は OSM の沢ではない）。順位は変わらない。w07 だけ見ても差は小さい（LANDMARK hso≧5・30m・30mバッファで 50.5%→50.2%）。平坦面・水面は、この比較の順位を左右しない。

## 判定

**A（品質面では LANDMARK に置き換える価値がある）。ただし採用の条件がある。**

### 根拠（判定に使った項目）
1. **沢**：同じ全長にそろえて比べると、LANDMARK が全8組で現行を上回る。精度相当 +13〜22pt・再現相当 +5〜26pt（30mバッファ）。偶然（5〜13%）を大きく超え、50mバッファでも変わらない。
2. **尾根の連続性**：落差30m以上の鞍部の前後に1,000m以上続く割合が、LANDMARK 70〜71% 対 現行 7〜20%（長さ合わせでも 7〜29%）。連結成分は 93本（12本/100km）対 591本（133本/100km）（30m）。常念乗越の本線は LANDMARK で一本につながり（約60km）、現行はつなぎの有無によらず途切れる。
3. **解像度への頑健さ（尾根）**：30m と 10m の位置一致が 94%（現行 57〜75%）、密度は 2.5→2.5km/km²（現行 1.5→1.8）。

### 判定から外した項目
- OSM の尾根線に対する精度・再現（2窓・27.5km。30m では差が判断できない。10m の再現相当の差は参考値）。
- 平坦面・水面のマスク（指標は動くが順位は変わらない）。判定の材料ではなく、順位が変わらないことの確認。
- 沢の hso の階層そのもの（解像度で 3.5倍変わるため、「hso の階層だけを採用する」という B は支持されない）。

### 採用の条件・未測定のこと
- **処理時間**：LANDMARK は約6km四方で 30m が約8秒、10m が約2分（純 Python 実装。findings.md）。端末内のリアルタイム計算はできず、**事前計算して保存する前提**。今回の比較は処理時間・配信方法を含まない。
- **後処理**：LANDMARK の線は格子の階段状。湖面を横切る沢線（hso≧5 で全長の5〜6%）は除く必要がある（現行は自前で避けている）。
- **階層の決め方**：沢の階層は hso ではなく A_out（集水面積）の閾値で決める方が解像度に頑健。
- **入力**：投影座標系（メートル）の DEM が必須（findings.md）。
