# 地名・山名検索の調査 07：座標入力（UTM・MGRS）

## 結論

- 日本の範囲は **UTM 51〜56帯、緯度帯 Q・R・S・T**。U 以北・帯の例外（ノルウェー・スバールバル）は掛からない
- 本体は既に **緯度経度 → UTM・MGRS の変換（順方向）を自前で持っている**（`toUTM`・`fmtUTM`・`fmtMGRS`、
  `sotoki_v4.html` 12884行付近、v4.110.0。答え合わせは pyproj と mgrs ライブラリの値で `tests/smoke_coord.mjs`）。
  入力で要るのは**逆方向（UTM・MGRS → 緯度経度）と、文字列の読み取り**
- ライブラリを足すなら、**MGRS は `mgrs`（proj4js、MIT、min 6KB／gzip 2.7KB、2026-07 に更新）が小さい。**
  UTM の逆変換は `mgrs` が公開していない（内部にはある）ので、自前（既存の順方向と同じ級数）か `geodesy` になる
- ⚠ 最大の落とし穴は **「54S」の S が緯度帯か南半球か**の取り違え（下記）

## 入力の書式で注意する点（一次情報）

| 点 | 根拠 |
|---|---|
| **UTM の「52S」の S は緯度帯で、南半球ではない** | スーパー地形のマニュアル「ゾーンの最後の文字は緯度バンドとしてください。北半球、南半球を示すNまたはSではありません。」https://www.kashmir3d.com/online/superdemapp/manual/ |
| ライブラリによっては**半球（N/S）で書く** | `geodesy` の `Utm.parse('31 N 448251 5411932')`（ゾーンと半球を空白で区切る）、配布物 `utm.js` の JSDoc |
| MGRS は空白なし・ありの両方がある | スーパー地形は「スペースは入れずに一続きに」（例 `52SGB5078008854`）。`geodesy` の `Mgrs.parse` は `'31U DQ 48251 11932'` も `'31UDQ4825111932'` も受ける。`mgrs`（proj4js）は空白を取り除いてから読む（`mgrsString.replace(/ /g, '')`） |
| MGRS の桁数（精度） | スーパー地形は 1m 単位・10m 単位を受ける。`mgrs` の `inverse()` は桁数に応じた**範囲（bbox）**を返し、`toPoint()` はその中心を返す |
| 地理院地図の「UTMポイント」は MGRS と同じ形 | 例 `54SVE17689580`（10m 単位、4桁＋4桁）。https://maps.gsi.go.jp/help/pdf/grid.pdf （2022-03-09 作成） |
| 本体の表示は帯つき・空白区切り | UTM＝`54S 417680 3995800`、MGRS＝`54S VE 17680 95800`（`fmtUTM`・`fmtMGRS`）。**入力でもこの形を受けるのが筋**（本体の表示をそのままコピーして貼れる） |

### 「S」「N」の取り違えの扱い（所見）

- 日本はすべて北半球。**ゾーン＋1文字＋東距＋北距**の UTM で、文字が Q/R/S/T なら緯度帯と読めば済む
- ただし **N は緯度帯（0–8°N）にもある**。「54N 417680 3995800」は、半球 N なら東京付近、緯度帯 N なら赤道付近で矛盾する。
  **北距の値から緯度を出し、文字はその確認にだけ使う**、とすれば両方の書き方を受けられる（**未検証**。実装時に確かめる）
- 「54S」を半球 S と読むと、南半球の値になり日本から外れる。**日本の範囲外になったら「範囲外」と言う**（本体の既存の方針と同じ）
