# 地名・山名検索の調査 09：データモデルを決める前に人間が判断すべき点

改訂: 2026-10-07（findings-01〜08 の後半で前提が変わったため全面的に書き直した。旧版は git の履歴にある）

## 0. 調査で固まった前提（判断ではなく、ここから出発する）

| 項目 | 現時点の結論 | 根拠 |
|---|---|---|
| 読み付き山名の**主な情報源** | 地理院「日本の主な山岳標高（1003山）」の **GeoJSON**（UTF-8・JGD2011・1059山頂・**全行に読み**・標高・都道府県・座標） | `findings-02.md` |
| CSV を使わない理由 | CP932 で4件の山名が「?」に化ける（薬萊山・蔵王山＜屛風岳＞・朳差岳・屛風山）。GeoJSON はこの4件も正しい | `findings-02.md` |

| OSM | **混ぜない**（成果物に OSM の値を入れると ODbL の派生データベース。OSMF のガイドラインで確認）。Wikidata も読みは 6% で使わない | `findings-04.md` 1、`findings-03.md` |
| 山群の代表ピーク | **1003山の山頂**（那須岳→茶臼岳、高原山→釈迦ヶ岳、八甲田山→大岳）。**気象庁「日本活火山総覧」の代表点と3山とも一致** | `findings-06.md` |
| 地図表示の扱い（本体の既存機能） | 地理院タイルのリアルタイム表示は申請不要（承認申請Q&A Q1-12）。標高タイルは基本測量成果でなく、加工して重ねても申請不要（地理院の回答） | `findings-04.md` 3 |

### 0-1. 1003山だけでは足りない部分（データモデルに効く）

- 1003山は「**主な**山頂」だけ。**三本槍岳（那須連山の最高点とされる）は 1003山に無い**（那須岳は `那須岳＜茶臼岳＞` の1行だけ）。
  八甲田山も大岳・高田大岳の2山頂だけで、井戸岳・赤倉岳・小岳などは無い
- それを埋めるのが注記（312）だが、注記には**標高が無く**、座標は**文字を置いた位置**で山頂ではない（`findings-03.md`・`findings-08.md` 必要な項目の表）
- → 1003山に載っている峰と、注記だけにある峰とで、**持てる項目（標高・山頂座標の確かさ）が違う**。データモデルはこの差を表せる必要がある
- 1003山の中にも同名の山が多い（例: 茶臼岳は 那須岳＜茶臼岳＞・八幡平＜茶臼岳＞・南アルプスの茶臼岳。釈迦ヶ岳も複数）→ 候補で見分ける情報（都道府県・山群・標高）が要る

### 0-2. 地理院に問い合わせ中（回答待ち。届いたら利用者が貼る）

| 問い合わせの件 | 回答で変わること | 否定的な回答だった場合の代わり |
|---|---|---|
| ① **端末キャッシュ**（オフライン用に地図タイルを端末へ保存する） | 本体の既存のタイルキャッシュ。検索のデータモデルには直接は効かない | 地図のオフライン範囲を見直す（検索とは別件） |
| ② **1003山**を JSON にして同梱・配信すること | 主な情報源をそのまま使えるか | 承認申請を出す／実行時に地理院から取る（同梱しない）／注記だけにする（標高を失う） |
| ③ **注記**（ベクトルタイル）を抜き出して同梱すること | 補助の情報源。地理院は「基本測量成果ではない」と明記しており、PDL1.0（出典＋加工の表示）で足りる見込みが高い | 補助を持たない（1003山だけ） |
| ④ **住所検索 API** の利用・保存・再配信 | オンライン時の地名・住所の検索 | 既存どおり実行時に呼ぶだけ（保存しない） |

- ②について: 配布ページは 1003山を「**国土地理院技術資料**」と書き、利用手続ページは「技術資料」を「**測量成果に該当しないコンテンツ**」に挙げている → **承認不要（PDL1.0）と読める**が、1003山の名指しではないので**解釈**（`findings-02.md`・`findings-04.md` 3）
- ③について: 全国の注記を集めるには**タイルを全国分なめる**ことになる。地理院地図の利用規約は過大な負荷への遮断を書いている（`findings-04.md` 2）。取り方（頻度・範囲）は回答と合わせて決める
- **②の回答が出るまで、1003山を同梱する設計を確定しない**のが安全

## A. 候補に出す種別の範囲 【必須】

選択肢（組み合わせ可）:
山群（総称）／山（ピーク）／峠・尾根などの地形名／地名（集落など）／住所／山小屋・登山口／施設

- 根拠
  - 1003山は「山（総称）＜山頂＞」の2層をそのまま持つ（34山が複数山頂、計90山頂） → `findings-02.md`
  - 注記は 311（山の総称）・312（山、岳、峰等）を分けるが、**旧形式の 312 には尾根・峠も混ざる**（熊見曽根・中の大倉尾根・牛ヶ首・雲谷峠） → `raw/gsi_vt_labels_311_312.tsv`
  - 山小屋・登山口は、どの情報源にも**まとまった形では無い**（住所検索 API に散発的にあるだけ） → `findings-05.md`、`findings-08.md` 表1
  - スーパー地形は施設（コンビニ）まで出す → `findings-08.md` 表1
- 決めること
  1. 初版で出す種別
  2. 注記 312 に混ざる「尾根・峠・ノ頭」を、山と同じに出す／別の種別（地形名）にする／出さない
  3. 注記だけにある峰（標高なし・文字の位置）を候補に出すか。出すなら、1003山の峰と見た目で区別するか
- 推奨
  - 初版は **山群・山（1003山）・山（注記で補う峰）**＋**地名・住所はオンライン時のみ**（既存の住所検索 API・Nominatim）。山小屋・登山口は情報源が無いので後回し
  - 尾根・峠は「地形名」として別種別（山として出すと、天気の取得地点が山頂でない点になる）
  - 注記だけの峰は出す。ただし**標高を表示しない／「位置は地図の文字の位置」と分かる形**にする（標高を DEM で補うなら「DEM の読み」と明記。本体は既にこの区別をしている）

## B. 座標入力の対応書式 【必須】

選択肢: 十進度／度・十進分（DDM）／度分秒（記号・漢字）／UTM／MGRS

- 根拠
  - 本体は既に**6形式を表示**している（DD・DDM・DMS・度分秒・UTM・MGRS）が、**座標を入力して飛ぶ処理は無い** → `findings-08.md`「参考」
  - スーパー地形は 十進度・度分秒・UTM・MGRS（区切りに独自の方言：`35.123/135.951`・`35.12.34/135.59.59`）。地理院地図は 十進度・度分秒（漢字）・UTMポイント（MGRS 形式） → `findings-08.md` 表5
  - 日本は UTM 51〜56帯・緯度帯 Q〜T。**「54S」の S は緯度帯で南半球ではない**。N は緯度帯にもあるので文字だけでは決まらない → `findings-07.md`
  - 逆変換（UTM・MGRS → 緯度経度）は新たに要る。`mgrs`（MIT、gzip 2.7KB）か、既存の順方向と同じ級数で自前 → `findings-07.md`
- 決めること
  1. どの書式まで受けるか
  2. 区切りの方言（スーパー地形のスラッシュ・ドット区切り）まで受けるか
  3. 経度・緯度の順で打たれた入力（`139.96, 37.12`）を、値の範囲から入れ替えるか
  4. 逆変換をライブラリにするか自前にするか（ADR-0001 の単一HTML・依存を増やさない方針との兼ね合い）
- 推奨: **本体が表示する6形式は全部受ける**（表示をコピーして貼り戻せることを保証）。UTM の文字は**北距から緯度を出し、文字は確認にだけ使う**。日本の範囲外になったら「範囲外」と言う。経度・緯度の入れ替えは、日本の範囲で一意に決まるときだけ行う
- 補足: 座標入力は**データモデル（山名データ）とは独立**に決められる。A・C・D と切り離して先に進めてもよい

## C. オフラインで引ける範囲 【必須】

- 根拠
  - 山で使うのでオフライン重視（依頼の前提）。スーパー地形は地名データを内蔵（「山名25000件以上」） → `findings-08.md` 表7
  - **1003山の GeoJSON は 398KB（ZIP で 54KB）**。必要な項目に絞った JSON なら更に小さくできる見込み（**未計測**）
  - 注記を全国分持つ場合の件数・大きさは**未計測**（全国のタイルをなめないと数えられない）
  - いまの本体は、入力中は検索の**履歴だけ**を絞り込んで出し、検索そのものは Enter で Nominatim と住所検索 API を呼ぶ（圏外では履歴しか引けない） → `findings-08.md`「参考」
- 決めること（どれか、または段階的に）
  1. **1003山だけ**を同梱（小さい。標高・山頂座標・読みが揃う。三本槍岳のような峰は引けない）
  2. 1003山＋**全国の注記**を同梱（網羅的。大きさ未計測。取得の負荷と②③の回答待ち）
  3. 1003山＋**山域ごとの注記**を、利用者が選んだ山域だけ取る（既存の山域の単位。中間）
  4. 同梱せず、履歴＋既存の `areas.json`（110峰）だけ
- 入力中に候補を出すかもここで決まる: 候補を出すなら**端末内のデータで出す**しかない（入力ごとに外部を叩くのは、Nominatim の頻度の制約と山の電波に合わない）
- 推奨: **1（1003山を同梱）から始め、3（山域ごとの注記）を後で足す**。入力中の候補は同梱データ＋履歴で出す。ただし **1 は 0-2 の②の回答待ち**

## D. 山群の見せ方 【必須】

### D-1. 山群を選んだとき、何の天気を出すか

- 根拠: 代表ピークは 1003山の山頂（＝気象庁の代表点）を既定にできる（0. の表）。総称の点は情報源によって峰から 0.5〜1km 離れ、**標高の低い点で風を取る**おそれがある → `findings-06.md`「天気の取得地点への影響」
- 選択肢
  1. 代表ピーク1点の天気を出す（山群＝代表ピークへの近道）
  2. 代表ピークを出しつつ、構成ピークを並べて選ばせる
  3. 構成ピークを並べるだけ（代表を決めない）
- 推奨: **2**。既定は代表ピーク（根拠を説明できる）。並べる構成ピークは 1003山の山頂＋注記 312 で拾える
- ⚠ 構成ピークを注記で拾う場合、「その山群に属するか」は注記からは決まらない（範囲内の注記を数えただけ） → `findings-06.md`。所属を誰が・どう決めるか（自動＝範囲で切る／手で決める）も決める必要がある

### D-2. 代表ピークが最高峰と違う山の扱い

- 根拠: 那須岳は 1003山・気象庁とも代表＝茶臼岳（1,915m）。最高点は三本槍岳（1,917m）とされるが、**三本槍岳が最高点であることは一次情報で未確認**（OSM・Wikidata・注記の範囲の話） → `findings-06.md`
- 決めること: 代表ピークを **1003山に従う**で確定してよいか（推奨: 従う。地理院と気象庁の両方で根拠が言える）。例外を手で持つ仕組みを用意するか

### D-3. 「那須岳」と打ったときに何を出すか

- 根拠: 「那須岳」は総称（注記 311・OSM の volcano・Wikidata）としても、茶臼岳の山頂（1003山 `那須岳＜茶臼岳＞`・住所検索で茶臼岳から 12m・気象庁「別名、茶臼岳」）としても使われる → `findings-06.md`
- 選択肢: 「那須岳（山群）」と「茶臼岳（那須岳）」の両方を出す／山群だけ出す（選ぶと D-1 へ）
- 推奨: **両方出す**。打った語が山群名でも山頂名でもあることを、候補の表記（「茶臼岳（那須岳）」）で示す

### D-4. 同名の山の見せ方

- 根拠: 1003山の中だけでも 茶臼岳が3件（那須・八幡平・南アルプス）、釈迦ヶ岳も複数（高原山・黒岳・奈良） → `raw/gsi_1003_targets.tsv`。スーパー地形は名前・読み・種類・県名・標高で並べ替えられる → `findings-08.md` 表4
- 決めること: 候補に併記する情報（推奨: **山群名・都道府県・標高**）と、並び順（既存の「近い順／高い順」を流用するか）
