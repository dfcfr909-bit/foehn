# スモークテスト

`sotoki_v4.html` をヘッドレスChromiumで実際に読み込み、Open-Meteo等の通信をスタブして
主要機能が壊れていないかを検証する。**改修のたびに全件を回すこと。**

## セットアップ（初回のみ）

```bash
cd tests
npm install          # playwright-core・uplot・leaflet を取得
```

Chromium本体は環境に同梱のものを使う（`/opt/pw-browsers/chromium`）。
`playwright install` は不要。**別の場所にある Chromium を使うときは `PW_CHROMIUM`
環境変数でパスを渡す**（CIはこれで解決している → `.github/workflows/test.yml`）。

## 実行

```bash
cd tests
npm test                  # 全件まとめて実行
node smoke_align.js       # 個別実行（詳細なJSONが出る）
```

各テストは `PASSED` / `FAILED` を出力し、終了コードで結果を返す。
失敗時は直前に出力される JSON に実測値が入っているので、期待値との差分を見る。

## 注意

- テストは**現在時刻に依存**する。`smoke_align` の初期選択indexは「現在時刻」を基準にするため、
  時刻をまたぐ実行では±1のズレを許容している。
- **閾値を「実測値すれすれの絶対値」で置かないこと。** `smoke_cloud` の
  「時刻の境目に段差が無い」検査は `maxJump <= 14` だったが、この14は
  **なめらかな坂のいちばん急な所の実測値ぎりぎり**で、アプリを何も変えていないのに
  実行時刻が変わると15になって落ちた（v4.72.0で確認。**過去のコミットでも同じ時刻に
  落ちる**ことを確かめて、変更のせいでないと切り分けた）。
  いまは**時刻の境目とそれ以外の最大値を比べる**（見たいのは「境目だけ余分に飛ぶか」）。
  なお、1時間ごとの段差そのものは `rasterW === hours*8` ・ `distinct > 30` ・
  `span > 40` が押さえている。**落ちたときは、まず過去のコミットを同じ時刻で回して
  「変更のせいか」を切り分けること。**
- **`smoke_mapui` の「古いレイヤーは残さない」は稀に落ちる**（v4.72.1で1回観測、直後に3回連続PASS）。
  古いレイヤーを外す逃げ道が `WX_DROP_MS`(8秒) のタイマー頼みで、待ち時間との競争になるため。
  落ちたら回し直す。**ヘッドレスでしか出ないので、実機の不具合ではない。**
- スクリーンショット（`*.png`）が生成されるが、gitignore済み。目視確認に使う。
- canvasの画素を読んで滑らかさを見るテスト（`smoke_cloud`）は、**走査線に他の描画を
  巻き込まないよう気をつける**。0時の日付区切り線（縦）と高度グリッドの破線（3px周期）は
  雲と無関係な段差として出てくるので、走査する位置をそれらから外している。
  **昼夜の明るさを比べる2点は、fixtureの雲の偶奇をそろえること。** `smoke_cloud` の
  補助データは「indexの偶奇」で雲を出し分けているので、1時と12時のように偶奇の違う
  2点で比べると、雲の量の差を夜の暗さと取り違えて日によって落ちる（実際に落ちた）。
  **`ALT_TICKS` の高度そのものをサンプルしないこと。** 6000mはグリッド線の高度なので、
  そこを読むと破線の位相で明るさが数十も揺れ、時刻によって落ちる（これも実際に落ちた）。
  `safeY()` が線から離れたyを選ぶので、画素を読むときは必ずこれを通す。
- **逆に、画素で見ても捕まらない不具合もある。** SVGフィルタは iOS Safari が
  一度評価したものを使い回すので、**属性だけ書き換えても絵が変わらない**。
  Chromiumは正しく作り直すため、**画素検査では絶対に再現しない**。
  こういう「特定ブラウザの再評価」ものは、構造（`url(#…)` のidが変わるか）で見張るしかない。
  ⚠その際、**比較する「前」の値は対象が載りきってから取ること**。
  非同期の途中で取ると `none` になり、何を比べても違って見えて壊れた版が通る（実際に通った）。
- **「効いているか」をスタイルの検査で済ませない。** `mask-image` が入っていることを
  確かめるだけのテストは、**マスクがレイヤーを丸ごと消していても通る**（0×0のLeaflet paneに
  マスクを掛けて雨雲が全部消えた件を取り逃がした）。見た目が変わる機能は
  **スクリーンショットを2枚撮って比べる**——変わってはいけない場所と、変わらねばならない
  場所の両方を見ること。比較する場所に他の要素が乗っていないかも `elementFromPoint` で先に確かめる。
- **`env()` は headless では常に 0 なので、そのままでは safe-area を検査できない。**
  だから逃げ幅は `:root` の `--sa-top` / `--sa-bottom` に集約してあり、テストが
  変数を差し替えて全画面ぶんまとめて見る。**`env()` を直接書くと検査をすり抜ける**ので、
  直書きが混ざっていないかも見ている（v4.60.0でランキングとお気に入りに入れ忘れ、
  「ランキング」の文字が時計に重なり ✕ が押せなくなった）。画面を足したら検査の配列にも足すこと。
- **fixtureを「都合よく」しすぎると検査が意味を失う。** 雷マークの検査は最初、
  タイルの1/4を塗った素材で「マークの近くに塗りがあるか」を見ていたが、**画像を読まず
  格子状に置くだけの実装でも通ってしまった**（塗りが広いのでどこに置いても近くにある）。
  塗りを面積の3.5%に絞って、壊した版が落ちることを確かめてある。
- **「応答しない」ルートは止める範囲を絞ること。** レイヤーの漏れを見る検査で
  `jmatile` 全体を止めたら `targetTimes` まで止まり、**レイヤーが1枚も作られず空振り**した
  （壊した版でも通った）。タイル画像のパス（`surf/hrpns`）だけ止める。
  またこの検査はレイヤーを貼り直すので、**画素を見る検査より後ろに置くこと**。
- **画素を読むindexはデータから取ること。** fixtureの時刻indexと表示ウィンドウ
  （実績72h＋予報）のindexは**現在時刻ぶんズレる**。決め打ちすると見当違いの場所を
  読んで落ちる（`smoke_press` で実際に落ちた）。バーの内側を読むときも、
  高さは `|dp|/PRESS_BAR_MAX` の割合なので**ゼロ線のすぐ近く**を読む。
- **HTMLの入れ子を壊すと「見えない」だけの症状になる。** `#map-bottom` の閉じ忘れで
  ランキング画面が地図の中に入り込み、`smoke_rank` が「element is not visible」の
  30秒タイムアウトで落ちた——地図のテストは全部通ったまま。
  `#rank-overlay` などが `#map-overlay` の外にあることを直接見るようにしてある。
- **`elementFromPoint` は `#map` の中かどうかで判定する。** 地図上のマーカー
  （アメダスのピン等）に当たることがあるので `=== 'map'` で見ると誤検出する。
- **画面に出ているはずのものが「押せるか」まで見る。** 高さや存在だけの検査は、
  上に別の要素が被っていても通ってしまう（レイヤーパネルが下部バーを覆った件を
  取り逃がした）。`document.elementFromPoint` で当たり判定を確かめる。
- **スクリプトの評価に失敗すると「読み込み中」のまま固まり、clickが30秒待ちになって
  原因が見えない。** `smoke_mapui` は起動直後に `mapPrefs` の有無と読み込み中表示を見て
  早く落とすようにしてある（後方で `const` 宣言した値を前方で参照するTDZで実際に踏んだ）。
- 仕様変更でテストが落ちた場合、**テストを緩めるのではなく**、変更が意図どおりか先に確認すること。
  過去に「スクロールで時刻選択」→「スライダー/タップで選択」へモデル変更した際は、
  テスト側の操作方法を新モデルに合わせて書き換えている。

## 公開URLの検証（スモークとは別物）

`tests/verify-live.mjs` は**公開URLに実際に配信されているもの**を検証する。
`run-all.js` の一覧には**入れていない**（外部を叩くので通常のスモークとは分ける）。

```bash
node tests/verify-live.mjs [URL] [--only=deploy|browser]
```

見るのは2つで、**性質が違うので分けて走らせられる**。
GitHub Actions「公開URLの検証」もこれに合わせて2ジョブに分かれている。

| | 見るもの | 外部 | いつ走る |
|---|---|---|---|
| `--only=deploy` | 配信物がそのコミットの `sotoki_v4.html` と一致するか（sha256） | **叩かない** | Pages デプロイ成功後に**自動** |
| `--only=browser` | 実ブラウザで起動するか・Nominatim・地理院・標高タイルが叩けるか | **叩く** | **手動のみ**（`workflow_dispatch`） |

⚠ **①がいちばん効く。**「直したのに変わらない」の大半は不具合ではなく
**まだ配信されていない**。#27 で同じ往復を2回した。外部を1つも叩かないので、
赤の意味はひとつしかない——**配信されていない**。

⚠ 地理院のCORSは**ブラウザでしか確かめられない**。②で初めて機械で言える。
**検索まわり・外部URLを変更したらマージ後に手で回すこと**（自動では走らない）。

### なぜ②を自動にしないか（2026-08-20）

Nominatim の制限は**IP単位**で、Actions のランナーは他人のCIと共有のIPを使う。
こちらの行儀と無関係に絞られうるので、自動で回すと赤の意味が
「壊した／相手が落ちた／IPが絞られた」に割れる。
**対応不要な失敗通知が定期的に届く検査は、そのうち誰も見なくなる。**
手で回しても得られる情報は同じなので、偽の赤を引き受ける理由が無い。

⚠ **②を `workflow_run` に広げない・`schedule` を足さないこと。**
外部を実際に叩くので、検索は1回だけに保つ。

⚠ **`--only` の綴りを間違えたら exit 2 で止まる**（既定に落とさない）。
`--only=browsers` のような打ち間違いを黙って両方扱いにすると、
**検証していないものが検証済みに見える**。この手の道具のいちばん悪い嘘。

⚠ **`playwright-core` は動的 import にしてある。** 先頭で読むと、
Chromium も `npm install` も要らないはずの `deploy` ジョブが依存が無いだけで落ちる。

⚠ **実機確認の代わりにはならない。** iOS Safari とホーム画面のPWAは Chromium とは
別物で、このリポジトリはiOS特有のフィルタ不具合を2回踏んでいる。

⚠ 作るときに踏んだ穴を2つ残す。手元で走らせて初めて分かった。
- **取得に失敗したら本文を配信物として扱わない。** 403のエラーページ（109バイト）を
  HTMLと突き合わせて「一致しない」と報告し、**到達できないのか中身が違うのかが
  区別できなくなっていた**
- **到達できないときに例外で落とさない。** 以降の検査が走らず、サマリーに
  スタックトレースしか残らない。「届かなかった」も結果の一つとして出す
