# スモークテスト

`sotoki_v4.html` をヘッドレスChromiumで実際に読み込み、Open-Meteo等の通信をスタブして
主要機能が壊れていないかを検証する。**改修のたびに全件を回すこと。**

## セットアップ（初回のみ）

```bash
cd tests
npm install          # playwright-core・uplot・leaflet を取得
```

Chromium本体は環境に同梱のものを使う（`/opt/pw-browsers/chromium`）。
`playwright install` は不要。別環境で動かす場合は各テストの `executablePath` を調整する。

## 実行

```bash
cd tests
npm test                  # 全件まとめて実行
node smoke_align.js       # 個別実行（詳細なJSONが出る）
```

各テストは `PASSED` / `FAILED` を出力し、終了コードで結果を返す。
失敗時は直前に出力される JSON に実測値が入っているので、期待値との差分を見る。

## 注意

- テストは**現在時刻に依存**する。`smoke_align` の初期選択indexは「現在時刻」を基準にするため、
  時刻をまたぐ実行では±1のズレを許容している。
- スクリーンショット（`*.png`）が生成されるが、gitignore済み。目視確認に使う。
- canvasの画素を読んで滑らかさを見るテスト（`smoke_cloud`）は、**走査線に他の描画を
  巻き込まないよう気をつける**。0時の日付区切り線（縦）と高度グリッドの破線（3px周期）は
  雲と無関係な段差として出てくるので、走査する位置をそれらから外している。
  **昼夜の明るさを比べる2点は、fixtureの雲の偶奇をそろえること。** `smoke_cloud` の
  補助データは「indexの偶奇」で雲を出し分けているので、1時と12時のように偶奇の違う
  2点で比べると、雲の量の差を夜の暗さと取り違えて日によって落ちる（実際に落ちた）。
  **`ALT_TICKS` の高度そのものをサンプルしないこと。** 6000mはグリッド線の高度なので、
  そこを読むと破線の位相で明るさが数十も揺れ、時刻によって落ちる（これも実際に落ちた）。
  `safeY()` が線から離れたyを選ぶので、画素を読むときは必ずこれを通す。
- **「効いているか」をスタイルの検査で済ませない。** `mask-image` が入っていることを
  確かめるだけのテストは、**マスクがレイヤーを丸ごと消していても通る**（0×0のLeaflet paneに
  マスクを掛けて雨雲が全部消えた件を取り逃がした）。見た目が変わる機能は
  **スクリーンショットを2枚撮って比べる**——変わってはいけない場所と、変わらねばならない
  場所の両方を見ること。比較する場所に他の要素が乗っていないかも `elementFromPoint` で先に確かめる。
- **`env()` は headless では常に 0 なので、そのままでは safe-area を検査できない。**
  だから逃げ幅は `:root` の `--sa-top` / `--sa-bottom` に集約してあり、テストが
  変数を差し替えて全画面ぶんまとめて見る。**`env()` を直接書くと検査をすり抜ける**ので、
  直書きが混ざっていないかも見ている（v4.60.0でランキングとお気に入りに入れ忘れ、
  「ランキング」の文字が時計に重なり ✕ が押せなくなった）。画面を足したら検査の配列にも足すこと。
- **fixtureを「都合よく」しすぎると検査が意味を失う。** 雷マークの検査は最初、
  タイルの1/4を塗った素材で「マークの近くに塗りがあるか」を見ていたが、**画像を読まず
  格子状に置くだけの実装でも通ってしまった**（塗りが広いのでどこに置いても近くにある）。
  塗りを面積の3.5%に絞って、壊した版が落ちることを確かめてある。
- **HTMLの入れ子を壊すと「見えない」だけの症状になる。** `#map-bottom` の閉じ忘れで
  ランキング画面が地図の中に入り込み、`smoke_rank` が「element is not visible」の
  30秒タイムアウトで落ちた——地図のテストは全部通ったまま。
  `#rank-overlay` などが `#map-overlay` の外にあることを直接見るようにしてある。
- **`elementFromPoint` は `#map` の中かどうかで判定する。** 地図上のマーカー
  （アメダスのピン等）に当たることがあるので `=== 'map'` で見ると誤検出する。
- **画面に出ているはずのものが「押せるか」まで見る。** 高さや存在だけの検査は、
  上に別の要素が被っていても通ってしまう（レイヤーパネルが下部バーを覆った件を
  取り逃がした）。`document.elementFromPoint` で当たり判定を確かめる。
- **スクリプトの評価に失敗すると「読み込み中」のまま固まり、clickが30秒待ちになって
  原因が見えない。** `smoke_mapui` は起動直後に `mapPrefs` の有無と読み込み中表示を見て
  早く落とすようにしてある（後方で `const` 宣言した値を前方で参照するTDZで実際に踏んだ）。
- 仕様変更でテストが落ちた場合、**テストを緩めるのではなく**、変更が意図どおりか先に確認すること。
  過去に「スクロールで時刻選択」→「スライダー/タップで選択」へモデル変更した際は、
  テスト側の操作方法を新モデルに合わせて書き換えている。
