## 画面構成（現行）

上から: ヘッダー（左＝**大きな日付＋選択時刻＋★** / 中＝お気に入り円柱 / 右＝「現在」ボタン） →
チャート4枚 → 時間スクラバー帯 → **凡例（左寄せ）＋バージョン（右端）** → フッター

お気に入り専用の行は廃止しヘッダーに同居（v4.32.0）。凡例は下段へ移動（v4.33.0）。
チャートの上に載るのはヘッダー1行（48px）だけ。

チャート4枚:
1. **気温**（左軸℃）
2. **雲/雨**（左軸=降水mm/h、右軸=高度km）… **青空に白い雲**を無段階表示＋降水バー＋標高ライン
3. **風**（左軸=風速m/s、右軸=突風m/s）
4. **気圧**（左軸hPa）… **上下2段**（v4.65.0）。上段=絶対気圧の線（6時間変化量で色分け）、
   下段=**ΔP6hのバー**。急変時に警告帯とラベル、急降下には**爆弾マーク**

時刻ラベルと天気アイコンは**2時間ごと**（v4.37.0。それ以前は6時間ごと）。
天気アイコンは**白い丸の座布団の上に、自前で描いたベクター記号**を載せる（v4.40.0）。
絵文字をやめた理由は2つ。色が淡くて小さいと判別しづらいことと、字形ごとに重心が違って
丸の中心に合わないこと。`drawWeatherGlyph()` が `weatherEmoji()` と同じ天気区分で
太陽・月・雲・雨・雪・雷・霧を原色寄りのべた塗りで描く。座布団の半径 `icoR` は
`pxPerHourVal - 0.6`（＝2時間間隔で隣と接しないギリギリ）。
**月は実際の満ち欠けを描く**（v4.41.0）。`moonPhase()` が平均朔望月からの近似で位相を出し、
`wxMoon()` が輪郭の半円＋ターミネーター（楕円）を1つのパスにして明るい側を塗る。
誤差は概ね±0.5日（既知の朔望と比べて0.05〜0.51日）なので、形を見て満月に近いと
分かれば十分という用途向け。**潮汐や暦には使わないこと。**
**`destination-out` で抜く方式は使わない**（下の白い座布団ごと消える）。
日付ラベルとアイコンが重ならないよう、気温パネルの上部余白は `SKY_TOP_PAD`(46px)。
なお選択情報のポップアップだけは絵文字のまま（大きく表示されるので判別に困らない）。

**昼夜のシェーディング**: `paintNightOverlay()` が**夜の帯だけ**を塗る（v4.41.0）。
「全面を夜色→昼を白に戻す」方式をやめたので、白地でも空色グラデ地でも同じ関数が使え、
**雲/雨パネルにも同じ夜が掛かる**。境界は `softGradient()` で左右に約1.6時間ぶん
ぼかす（くっきり引くと「現在／過去の境目」の線と紛らわしいため）。
**濃さは月齢で変わる**（v4.45.0）。`nightAlphaAt()` が輝面比 `moonIllum()` から
`NIGHT_ALPHA_NEW`(0.38, 新月＝暗い) 〜 `NIGHT_ALPHA_FULL`(0.20, 満月＝明るい) を返す。
夜の帯ごとに真ん中の時刻で引くので、日をまたぐと少しずつ濃さが変わる。
**月の出入りは見ていない**（その夜の月がどれだけ満ちているかだけ）。雰囲気づけの割り切り。
第4引数 `scale` でパネルごとに倍率をかけられる（雲パネルは1.4）。

**左軸ガター**: 単位は「気温／℃」のように2段組みで、そのぶん `PADDING_L` を44→36pxに
詰めてチャートを左へ寄せ、目盛りの数字を10→11.5pxに大きくしてある（v4.39.0）。
名前・単位・数値はすべて**右寄せ**（v4.42.0。左寄せだと数値と横でぶつかる）。
気圧だけは「値から位置を決める」と単位と重なる高さに来ることがあるため、
**先に安全な位置（プロット高の45%と82%）を決めて、そこに対応する値を書く**。

**気圧パネル**（v4.65.0で2段化）:
- ⚠**上段（`PRESS_LINE_FRAC`=0.70）＝絶対気圧の線／下段＝ΔP6hのバー。**
  分けた理由は「hPaの刻みが大きすぎて上下降が見にくい」という指摘。
  **バーは常に±`PRESS_BAR_MAX`(8)hPa/6h の固定スケール**なので、
  絶対値がどうであれ同じ変化量は同じ高さに見える
- ⚠⚠**上段は「縦窓」で、選択時刻に追従して上下に動く**（v4.66.0。利用者の提案）。
  全期間を1画面に収めると1日ぶんの数hPaが線に出ないため、`pressWindowFor()` が
  **画面に入る範囲の実変動＋余裕**（最低 `PRESS_WIN_MIN_HPA`=10hPa）だけを映す。
  左のガターの数字も一緒に動かすので、**絶対値は読めたまま**
- ⚠**毎フレーム描き直さないこと。** 気圧のcanvasは全期間ぶん（幅3,600px超）あり、
  スクラブのたびに `setScale` すると、チャート移動をtransformにした意味が無くなる
  （v4.42.0の「ゆっくりなぞるとカクつく」原因がまさにこれ）。
  なぞっている間は `PRESS_WIN_COARSE`(2.5hPa)、指を離してから
  `PRESS_WIN_FINE`(0.4hPa) で合わせ直す二段構えにしてある
- ⚠**線は必ずクリップする。** 縦窓は選択時刻のまわりに合わせてあるので、
  画面外の時刻は窓を大きく外れる。切らないと下段のバーや隣のパネルへ突き抜ける
- 線は `u.valToPos(v,'p')` ではなく**上段に収まるよう自前でyを出している**。
  スケールのレンジ自体は `p` のまま（ガターの数字と揃えるため）
- ⚠**ガターのhPa目盛りも上段の範囲で割ること**（`pressGutterLayout()`）。
  パネル全体で割ると、下段のバーの高さにhPaの数字が並んで嘘になる
- **急降下には爆弾マーク**（頭痛ーる風。`PRESS_BOMB_DP`=-3.5hPa/6h）。
  `pressBombIndices()` が**連続して閾値を割っている区間ごとに、いちばん急な1点だけ**を返す。
  毎時置くと爆弾だらけになる
- 色は **下降＝暖色（橙→赤）／上昇＝寒色（水色→青）**。急なほど濃く太い。
  **高気圧＝好天のイメージではなく、「気圧の急降下は体調に効くから警告色」という意図**
- 気圧パネルは風から2%ぶん高さを回してある（風19%→17%、気圧21%→23%）

**役割分担**: 画面上部のチャート＝**参照**、下部の帯＝**移動**。

**表示範囲**: **実績72h（`PAST_HOURS`）＋現在＋予報168h（`FORECAST_HOURS`）＝241点**の固定。
「予報 / 実績+予報」の切替UIは撤去済み（v4.32.0）。取得は `past_days=3&forecast_days=9`。
モデルの予報期間を超えた末尾は `processData` がnullを見て切り落とすので、
`forecast_days` に何を指定しても「実際に値がある所まで」が表示される。

**選択の仕組み**: `state.sliderIndex` が主。赤の選択線はその時刻の位置を指す。
- チャートのタップ／ドラッグ → その位置の時刻を選択（スクロールしない）
- 下部スクラバー帯をなぞる → 選択時刻を移動（チャートが連動してスクロール）
- チャートの指スワイプによる横スクロールは**無効**（`overflow-x: hidden`）
- 選択情報は指追従のポップアップに集約（上部の日付バー/HUD/ABCカードは撤去済み）
- ポップアップでは**判定の根拠になった数値を色分け**する（B相当=黄 `.lv1` / C相当=赤 `.lv2`）。
  内訳は `judgeBreakdown()` が出す。**`judgePoint` は規約により変更禁止なので触っていない。**
  両者は同じ `THRESH`・同じ `abcScore`/`abcScoreInv` を使うので、閾値を変えるときは
  `THRESH` だけを触れば両方に効く
- 日帰り/幕営のモード切替は撤去済み。`state.mode` は `'day'` 固定
- レンジ切替（予報 / 実績+予報）も撤去済み。常に実績＋予報を表示する

**日付バッジ**（`#date-badge`。ヘッダー左上。画面で一番目立つ位置）:
- 選択中の「N月N日(曜)」を22px、その隣に選択時刻「HH:00」を18pxで表示し、
  スクラバーの操作に追従する。祝日名だけ2行目に落とす（`#date-holiday:empty` で消える）
- ブランド表記（SotoKiロゴ）は撤去。バージョンは下段（凡例行）の右端（v4.39.0）
- **★（お気に入り登録）は時刻の右**、日付バッジの中に入れてある（v4.40.0）。
  空いたヘッダー右端に**「現在」ボタン**を移した（以前はチャート上の絶対配置）。
  「現在」は選択が現在から離れたときだけ出るので、出ている間は円柱の枠が狭くなる
  （ResizeObserverが寸法を取り直すので破綻しない）
- **日曜・祝日は赤、土曜は青。祝日は「（山の日）」のように名称も出す**
- 祝日は `jpHoliday()` が算出する。日付固定・ハッピーマンデー・春分/秋分（近似式、
  1980〜2099年で有効）に加え、**振替休日・国民の休日**も判定する。
  五輪年のような一度きりの特例日程には非対応（表示は前後10日ぶんなので実害なし）
- スクラバー帯の日付ラベルも同じ規則で色分けし、祝日名を添える

**お気に入り円柱ピッカー**（`#fav-rotary`）:
- 縦軸まわりに回る円柱の側面に地点名が書いてあるイメージ
- **スクロールは入力（慣性・スナップ）専用**。透明トラック `#fav-track` が
  スクロール量を作り、`position: sticky` の `#fav-stage` に駒を絶対配置する。
  舞台はスクロールしないので、駒の位置をJSが円柱の座標として自由に決められる
- 正面からの距離d（駒数）に対し 角度 = d × `FAV_ANGLE`、
  x = `FAV_R` × sin(角度)、z = `FAV_R` × cos(角度) − `FAV_R`、rotateY(角度)。
  88degを超えた駒は円柱の裏側なので非表示
- **`FAV_R` と `FAV_ANGLE` は固定値ではなく `layoutFavRotary` が枠の広さと駒の幅から決める**
  （v4.37.0）。隣の駒が正面と重ならない条件 R·sinθ − (cw/2)cosθ ≧ cw/2 を満たす最小の角度を採る。
  枠が狭いほど半径は小さく角度は大きくなる
- 枠幅は日付の文字数で変わるので **ResizeObserver で監視して寸法を取り直す**。
  取り直さないと広い枠のときの半径のまま狭い枠に描いてはみ出す
- 枠自体は `flex: 1 1 0` ＋ `margin-left:auto` で、日付と★を置いた残りを右寄せで使う
- 正面の駒＝選択地点（`.centered`）。回している最中も正面の駒が即座に強調される
- **地点リストの顔ぶれが変わらない限りDOMを作り直さない**（`favRotaryKey` で判定）。
  作り直すとスクロール位置がリセットされて引っかかるため

**チャートの移動は CSS transform**（v4.42.0）:
- `#charts-inner` を `translate3d(-chartOffset,0,0)` で動かす。`scrollLeft` は使わない
- 幅3,000pxを超えるcanvasを4枚抱えているため、`scrollLeft` で動かすと毎フレーム
  再描画が走って重い（**ゆっくりなぞるとカクつく原因はこれだった**）。transformなら
  コンポジタが動かすだけで再描画が要らない
- スクロール量の実体は `chartOffset`、上限は `chartMaxOffset()`。
  `chartsWrapper` の scroll イベントはもう発火しないので使わないこと
- 入力は下部スクラバー帯（小さいcanvas1枚）のネイティブスクロールが担う

**時間スクラバー帯**（`#scrubber`）:
- **チャートとまったく同じ座標系を使う。** 左右の余白（`chartPadL`/`chartPadR`）、
  内容幅（`chartTotalW()`）、1時間の幅（`pxPerHourVal`）、x座標（`idxToX()`）、
  スクロール量のすべてが `#charts-inner` と共通。だから帯の目盛りは
  真上のチャートの同じ時刻の真下に来る
- **なぞり中の同期は `scrubFrame()` の requestAnimationFrame ループが行う。**
  最初のscrollイベントでループを起こし、以降は毎フレーム帯の `scrollLeft` を実測して
  チャートと上下の選択線を更新する。scrollイベントはiOSなどで間引かれるため、
  イベント駆動にすると帯だけ先行して上の選択線が遅れる（v4.34.0で修正）
- なぞり中は上下の選択線を**どちらも帯の実測値**で置く（`positionScrubLine(at)`）
- チャート側からの同期は `mirrorScrollToScrubber()`。ループ動作中は主導権を譲る
- 選択インジケータ `#scrubber-center` は固定位置ではなく、`positionScrubLine()` が
  赤い選択線とまったく同じxに置く（チャートのタップ選択時も線が帯まで続く）
- 帯のcanvasに昼夜の地色・ABC判定バー・降水バー・日付区切り・現在時刻の印を描画

**選択線の位置**（`cursorX`）:
- **両端に余白は置かない**（`chartPadL` / `chartPadR` は0）。以前は先頭・末尾の時刻を
  選択線に届かせるため右に画面幅の86%ぶんの余白があり、それが末尾の空白に見えていた
- 選択線はふだん画面の `SCRUB_POS`(**50%＝ど真ん中**)に固定だが、**両端の ramp px ぶんだけ
  かけてその端へ寄っていく**。これで余白ゼロのままスクロールだけで先頭・末尾の時刻に届く。
  中央固定なので先頭側にもランプが要る（先頭の時刻は左端にしか来られないため）
- ポップアップの初期位置は `POPUP_HOME`(13%)。`SCRUB_POS` に追従させると中央の選択線と
  重なるので別定数にしてある。**指を離してもその場に留まる**（毎回定位置へ戻すと
  読めないため。`resetPopupPosition()` を呼ぶのは初期表示とリサイズ時だけ）
- `cursorX` がスクロール量に依存するため、`scrollToIndex` は不動点反復で解く

**地図の操作と現在地の見せ方**（v4.53.0）:
- **ダブルタップ＋上下ドラッグで拡大縮小**（Googleマップと同じ片手操作）。Leafletに無いので
  `bindDoubleTapZoom()` で自前実装。2回目のタップを押したまま上下に動かすと連続ズームし、
  ほとんど動かさずに離せば1段拡大する（着地は整数ズーム）。
  なめらかにするため地図は **`zoomSnap: 0`**（小数ズーム可）にしてある。
  Leaflet標準の `doubleClickZoom` は取り合いになるので **切ってある**
- ⚠**なめらかに動かすための肝が2つある。どちらか欠けるとガクガクになる**（v4.54.0で修正）:
  1. **毎フレーム `setZoom` を呼ばない。** ピンチズームと同じ `map._move(..., {pinch:true,
     round:false})` で変形だけ動かし、指を離したときに `_animateZoom` で一度だけ確定させる。
     `setZoom` はそのつどタイルを組み直すので指に追いつかない
  2. **操作中はLeafletのパンにイベントを渡さない。** 渡すと同じ指の動きでパンとズームが
     同時に走り、引っぱり合って震える。イベントは**地図の親要素でキャプチャ**して
     `stopPropagation()` する（同じ要素に後から足すとLeafletのハンドラが先に動くため）
- **追跡中は自分の位置を中心に拡大縮小する**（`zoomAnchor()`）。追跡していなければ
  タップした地点を基準にする
- マスクの貼り直しは rAF で間引く（`mask` はpane全体を描き直させるので毎フレームだと重い）
- **現在地のまわりだけ雨雲を抜く**（`updateMeSpotlight()`）。雨のエリアに入ると自位置が
  雨雲に埋もれて分からなくなるため、radial-gradient のマスクを掛ける。
  中心 `SPOT_CLEAR_PX` は完全に抜け、`SPOT_FADE_PX` で元の濃さに戻る。
  ⚠**大きさは現在地マーカー基準で決める**（`ME_DOT_R`=10px＝白フチ込みの外半径）。
  v4.59.0で 46/130px → 11/26px へ**大幅に縮小**した。広く抜くと
  「自分の位置の切り抜きが大きすぎて雲の配置が確認できない」（実際の指摘）
- ⚠⚠**マスクは「実寸のある箱」にしか効かない。Leafletのpaneは0×0。**
  paneに直接掛けると塗り領域が無く**レイヤーが丸ごと消える**。
  「追跡をonにすると雨雲が全部消える」不具合を出した（v4.53.0〜v4.56.0。v4.57.0で修正）。
  そのため**マスク用の入れ物 `mapNowcastMask` を1枚挟み**、そちらに画面ぶんの
  寸法を持たせている。タイルは中の `mapNowcast` に入る。**paneに直接掛けないこと**
- 入れ物は「map paneのずれ（`_getMapPanePos()`）を引いて画面の左上に合わせ、
  中身を同じ量だけ逆に動かす」。**同じ o を使う限り差し引きは必ず0なのでタイルはずれない**
  （1フレーム遅れても穴の位置が遅れるだけ）。だから rAF で間引いてよい
- **そのためにナウキャストは `mapNowcast`、マーカーは `mapWeather` と pane を分けている。**
  同じpaneに入れるとマスクで**現在地マーカーごと消える**。ここを混ぜないこと
- マスクは `move`/`zoom` と現在地更新のたびに貼り直す。追跡を止めたら外す（ずらしも戻す）
- テストは**画素で見る**。追跡のon/offで「遠くの雨雲が変わらないこと」と
  「現在地のまわりは変わること」を実際のスクリーンショットで比べている
  （スタイルの検査だけでは、レイヤーが消えていることに気づけない）

**地図の操作ボタン**（v4.58.0。右上に3つ縦に並ぶ）:
- **レイヤー**（角丸のピル）・**方位**（丸）・**現在地**（丸）。
- ⚠**レイヤーパネルを開いている間は浮きボタンを引っ込める**（`#map-stage.panel-open`）。

  加えてヘディングアップ中は環が**赤**になる
- Nの文字だけは `paintCompass()` が逆回転させて立てる（一緒に回すと読めない）。

  | 状態 | 押すと | 見た目 |
  |---|---|---|
  | `off` | 現在地へ寄り、**その地点を選ぶ** | 灰色 |
  | `once` | 追跡モードへ | 青 |
  | `follow` | 解除 | 青＋**隅に印**（`#locate-badge`） |
- **地点を選ぶのはこのボタンの役目。** 地図のタップでピンを立てないようにした（§19）ので、
  「現在地の天気を見る」入口はここだけ。**ボタンを押すのは意思のある操作なので長押しの決まりと矛盾しない**

**現在地の追跡と地図の向き**（v4.52.0）:
- 追跡中の現在地は**選択地点のピンとは別のマーカー**。追跡していても、選ぶ地点は
  利用者が長押ししたところのまま
- `watchPosition` で追い、`mapFollow` が立っている間は画面中央へ寄せ続ける。
  **`once` は watch するが追従しない**（見に行くだけ）。`follow` で追い続ける
- **地図を閉じたら追跡も止める**（電池のため）
- **ヘディングアップは `#map` をCSSで回して実現している。Leafletに回転機能は無い。**
  回すとLeafletの座標変換（画面座標→緯度経度）が狂うので、`patchRotatedInput()` が
  `mouseEventToContainerPoint` を中心まわりの逆回転で補正する。
  **これを外すと、回転中のタップが見当違いの地点を選ぶ**
- **回転中は手動パンを止める**（`dragging.disable()`）。ドラッグ量まで補正しはじめると
  破綻するので「追いかけている間は自分で動かさない」という割り切り
- 角が欠けないよう、回転中は `#map` の実体を `inset:-40%` で広げる
- 自前のラベル（アメダス・風）は `--map-rot` で逆回転させて立てる。
  ベースマップのタイル内の文字は画像なので回ったまま（仕様）
- 方位は iOS が `webkitCompassHeading`、他は `alpha`（反時計回りなので 360−alpha）。
  **iOSは利用者の操作の中で `DeviceOrientationEvent.requestPermission()` が要る**。
  センサーが使えないときは GPS の `heading` で代用する

**メモリの落とし穴**（v4.64.0。**iOSは容赦なく落ちる**）:
- 実機で「問題が繰り返し起きました」＝**Webプロセスのクラッシュ**を踏んだ。
  「いろいろ動かしていると」起きる、つまりじわじわ食い潰す類の問題
- ⚠**貼り替えた古いレイヤーには必ず外れる道を用意する**（`staleWxLayers` / `WX_DROP_MS`=8秒）。
  「新しいタイルが1枚出たら外す」だけだと、新しい方が**読み込まれも失敗もしない**
  （表示範囲外・応答が返らない等）とき古い方が残り、5分ごとの自動更新で積み上がる
- ⚠**いま載っているレイヤーは `await` の"あと"に取る。** 前に取ると、更新が重なった
  ときに2つの呼び出しが同じ古いレイヤーを掴み、**途中で作られたレイヤーが
  誰からも参照されないまま地図に残る**（これも実際に漏れていた）
- ⚠**雷マークの走査canvasは使い回し、画面の半分の解像度で持つ**（`THUNDER_SCAN_SCALE`）。
  毎回 `createElement('canvas')` ＋ `getImageData` すると1回数MBの捨てゴミが出る
- ⚠**`tileload` からの再走査は rAF ではなく時間で間引く**（`THUNDER_DEBOUNCE_MS`=250ms）。
  tileload はタイルの枚数だけ飛んでくるので、rAFだと実質毎フレーム走る
- 地図を閉じたら `dropAllStaleWxLayers()` と `releaseThunderScan()` で明示的に手放す
- `document.hidden` のときは自動更新しない

**リアルタイム表示**（v4.55.0。詳細は `docs/map-selector-requirements.md` §18）:
- **レーダーは降っている所しか映らない。** 「曇っているが降っていない」を見るため
  ひまわりの雲画像（`satellite`）を足した。バンドはカラー/赤外/雲頂の3つ、
  パネルのチップで切り替えて `sotoki.map.satBand` に保存する
- 衛星の時刻表は `targetTimes_jp.json`（ナウキャストとは別）。ズームは3〜6と低い。
  **実機で表示確認済み（v4.68.0）**
- ⚠⚠**ひまわりのタイルはJPEGで透明部分が無い。** そのまま濃度を上げると雲の無い所まで
  真っ黒に塗り潰れて地図が消える（実機で踏んだ）。`blend: 'screen'` を付けて
  **暗い所ほど下の地図が透ける**合成にしてある（v4.68.0）。
- ⚠⚠**衛星画像は「合成」ではなく「輝度→透明度」で抜くこと**（v4.72.0）。
  ひまわりのJPEGには透明部分が無いので、
  **そのまま重ねると黒で塗り潰れ、`screen` で抜くと明るい地図の上で潰れる。両方とも実機で踏んだ。**
  インラインSVGの `#satAlpha`（`feColorMatrix` でA=輝度 → `feFuncA` で直線変換）を
  `mapSatMask` に掛け、`alpha =(輝度 − cut)/(1 − cut)` にしている。
  暗い所（晴れ）は地図が素通し、明るい所（雲）は**色をそのまま残して**乗るので、
  雲頂の色分け（雲頂高度）が読める。`cut` は暗部の切り捨ても兼ねるので格子も出ない。
  - ⚠⚠**フィルタの形を変えないこと。実機で効くのは
    「`feComponentTransfer` 1段 ＋ `feFuncA type="linear"`」だけ**（v4.74.0）。
    実機での経過はこう:
    | 版 | 形 | 実機 |
    |---|---|---|
    | v4.72.1 | 1段・linear | **透けた** |
    | v4.73.0 | 2段（linear＋gamma） | 効かない |
    | v4.73.1 | 1段・table | 効かない |
    | v4.74.0 | 1段・linear | ← これに戻した |
    テストが**ノード数と `type`** を見ている。**触るなら実機で確認してからにすること。**
  - ⚠⚠**ひまわりの「晴れ」は真っ黒ではなく中間の灰色**（赤外なら地表の温度、輝度0.4前後）。
    **cutをそこより上に置く**（いま 赤外0.45／雲頂0.40）。低いと晴れが薄いベールとして
    残り、**地図全体が暗く沈む**（実機で踏んだ）。中間を累乗で落とせれば理想だが、
    上記のとおりiOS Safariがその形を受け付けないので **cutで代替**している。
    **上げすぎると薄い雲が消える**ので、両端（晴れは消える／雲は残る）をテストが画素で見張る
  - ⚠⚠**中身を書き換えたら参照する id ごと変えること**（`bumpSatFilterId`。v4.75.1）。
    iOS Safari は**一度評価したフィルタを使い回し、あとから属性を書き換えても絵が変わらない**。
    実機で「ピンクにしてもシアンにしても色が変わらない」を踏んだ。バンド切替時の
    `cut` も同じく効いていなかったはず。
    **Chromiumは正しく作り直すので、この不具合はヘッドレスでは再現しない。**
    テストは絵ではなく「値を変えたら `url(#…)` も変わる」という構造で見張っている
  - **雲の着色**（`SAT_TINTS`。v4.75.0）。白黒の赤外を目立つ色（ピンク／シアン）で塗れる。
    行列の**値だけ**を差し替える（形は上のとおり触らない）。
    ⚠**明るさを色に掛けないこと。** RGBは定数にして、明るさは**アルファだけ**に載せる。
    色にも掛けると薄い雲が「暗いピンク」になって地図に沈む（テストが画素で見張っている）。
    ⚠**雲頂には出さない**（`tintable` が無い）。あちらは色そのものが雲頂高度の情報。
    着色を入れたまま雲頂へ切り替えるテストがあるので、掛けてしまうと落ちる
  - ⚠**フィルタのSVGを 0×0 や `display:none` で隠さないこと**（v4.72.1）。
    WebKitには寸法の無いSVGだと `filter: url(#id)` が解決されず**丸ごと効かない**不具合がある。
    実寸（1px）を持たせたまま画面外へ逃がす。**効いているかの見分け方は、
    白いベースマップ（淡色地図）にして濃度100%にすること**——晴れの所が
    ほぼ白いままなら効いている、暗い灰色に塗り潰れるなら効いていない
  - ⚠**`color-interpolation-filters="sRGB"` は必須。** 既定のlinearRGBだと
    中間調の透明度が1/8まで落ちて雲がほぼ消える（テストが画素の濃さで見張っている）
  - ⚠**バンドを変えたら曲線も書き換えること**（前のバンドの `cut` が残る）
  - 重い・出ない端末に当たったら、バンド定義を `blend`/`floor` に戻せば従来動作に落とせる
- ~~合成方法はバンドごとに持たせる（`blend`/`floor`。v4.71.0）~~ → v4.72.0で輝度→透明度に統一。
  以下は**逃げ道として残している旧方式**の説明。
  レイヤー一括で `screen` にすると、**中間調が主体の絵（カラー・雲頂）は明るい地図の上で潰れる**。
  `screen` が足せるのは `1−(1−下)(1−上)` の幅だけで、淡色地図（0.92）では**20階調しかない**。
  背景が暗い赤外はその幅を端から端まで使えるが、海も陸も中間調から上にいるカラーは
  上半分に押し込まれて海と雲の差が消える（実機で「カラーだけ雲が写らない」を踏んだ）。
  いまは 赤外＝`screen`＋`floor`、雲頂＝通常合成。
  ⚠**掛けないバンドでは必ず外すこと**（前のバンドの合成が残る）
- ⚠⚠**合成の前に黒レベルを切り捨てること**（`floor: 1.5` → `filter: contrast(1.5)`。v4.68.1）。
  ひまわりの画像は**タイルごとに暗部の水準がわずかに違う**（特に夜のカラーバンドは
  可視光がほぼ無く、その差が支配的）。screen合成は暗い所ほど下を透かすので、
  **その差がそのままタイルの継ぎ目＝縦横の線や格子として見える**（実機で踏んだ）。
  `contrast(C)` は `0.5 − 0.5/C` 以下を黒に落とすので、C=1.5 で約17%以下の暗部が
  まとめて0になり、床の差ごと消える。
  **強くしすぎると薄い雲まで消える**ので、テストは「線が出ない」と
  「薄い雲は出る」の**両方**を見ている（片方だけだと C を上げ放題になる）
  **合成はマスク用の外側のpane（`mapSatMask`）に掛けること。** `mix-blend-mode` は
  いちばん近い祖先のスタッキングコンテキストの中でしか下と混ざらないので、
  内側の `mapSat` に掛けても**黒いまま**になる（`smoke_mapui` が画素で見張っている）。
  合成するぶん雨雲・雷とはpaneを分けてあり（375 < 380）、現在地まわりのマスクは
  `SPOT_PANES` で両方の組に掛ける
- **`WX_REFRESH_MS`(5分) ごとに自動更新**する。`refreshWeatherLayers()` が
  時刻表のキャッシュを捨て（`clearWxTimes()`）、新しい basetime で貼り直す。
  ⚠**キャッシュを捨てないと貼り直しても同じ時刻のまま**で意味が無い
- ⚠**新しいタイルが1枚出るまで古いレイヤーを消さない**（`addTimedTileLayer(def, op, true)`）。
  先に消すと更新のたびに一瞬まっさらになる。取れなかったときは古い方も落とす
- タイマーは**地図を開いている間だけ**（`openMap` で開始 / `closeMap` で停止）。
  再度開いたときは即座に一度貼り直す
- 衛星のバンド切替も同じ貼り替え経路を通すので、切り替えても画面が空にならない

**標高の2本立て**（v4.46.0。**混ぜないこと**）:

**地図タイルのキャッシュ**（`sw.js`。v4.46.0）:

**新雪ランキング**（v4.44.0。詳細は `docs/snow_ranking.md`）:

- 指標＝直近24hの新雪＋今夜〜明朝12hの予想降雪。気温からSLRを引き直して

- 地点座標は**ビルド時に確定**させる（`scripts/buildSpots.mjs`）。ランタイムでは

- **`wind_speed_unit=ms` を必ず付ける**（既定km/h。ここでも同じ罠がある）

- 信頼度は実運用でほとんどlowになる見込み（積雪観測アメダスが谷底にあり標高差が
  1,200mを超えるため）。しきい値を緩めるかは実データを見てから決めること

**雲パネルは「青空に白い雲」**（v4.45.0。**これを灰色に戻さないこと**）:
- 以前は淡い地に**灰色**の雲だった。夜のシェーディングも灰色寄りなので
  「背景・夜・雲」が同じトーンで混ざり、ぱっと見で雲の状況が読めなかった
- 空を青（`SKY_TOP` #6f9fca → `SKY_BOTTOM` #93c0e2）、雲を白（`CLOUD_RGB` 252,253,255）に
  反転した。夜は**空だけ**が暗くなり雲は明るいままなので、昼でも夜でも雲だけが浮く
- グラデーションの上下差は小さくしてある。下を淡くしすぎると**低層の雲**
  （バックカントリーで効く高度）が白地に白で埋もれるため
- 高度で色を変えることは**していない**。濃さ＝雲量という意味づけと衝突するため、
  高度の手がかりはグラデーションと右軸の目盛りに任せている
- 青地になったので、高度グリッド線は白の破線、降水バーは明るい縁つき、
  時刻軸の帯だけは白のまま（目盛りの数字を読ませるため）
- 凡例 `#cloud-legend` は「青空→白い雲」。`SKY_BOTTOM` に `cloudAlpha()` で白を
  重ねた色を並べてあるので、**カーブか空の色を変えたら凡例も直すこと**

**雲の無段階描画**（`buildCloudRaster` / `cloudAlpha` / `cloudSlopes`。v4.43.0）:
- 旧実装は「1時間ぶんの箱を6段階の濃さで塗る」だったので、**毎正時に縦の切れ目**が出て、
  濃さも階段状に見えていた。ブルーメテオのような無段階表示にするため3か所を直した:
  1. **高度方向** … 気圧面のあいだを `cloudSlopes()` の単調3次補間（Fritsch–Carlson）で
     つなぐ。単調性の制限が入っているので**雲量が0〜100%の外へ行き過ぎない**
  2. **濃さ** … しきい値をやめて `cloudAlpha()` の連続カーブ `0.82·((cov−3)/97)^0.85`。
     v4.45.0で白描画にあわせ `0.95·((cov−3)/97)^0.75` に強めた
  3. **時刻方向** … 1時間を `CLOUD_SUB`(8)分割・高さ `CLOUD_ROWS`(192)段のラスタを
     `createImageData` で組み、隣の時刻とは **smoothstep** で混ぜる。それを1枚の
     `drawImage` で引き伸ばして貼る（さらに `ctx.filter` のblur 1.2pxを重ねる。
     `ctx.filter` 非対応のブラウザでは掛からないが、引き伸ばし補間だけで十分なめらか）
- **ラスタは自前で細かく刻む。** 横1画素=1時間の粗いラスタを大きく引き伸ばすと、
  Chromeの `imageSmoothingQuality:'high'` がミップマップ由来の縞を出す。倍率を
  2倍程度に抑えれば起きない
- ラスタは `cloudRasterFor()` が `state.allData` と `state.cloudProfiles` の参照で
  キャッシュする。組み立て時に一度作るだけなので、なぞっている間の負荷はゼロ
- 気圧面は**14層**（1000/975/950/925/900/850/800/700/600/500/400/300/250/200 hPa）。
  975と925を足したのは、地上〜1,000mの分解能が110/540/990mでは粗すぎたため
  （バックカントリーで効くのはまさにこの高度帯）
- 凡例 `#cloud-legend` のグラデーションは `cloudAlpha()` と同じ濃さを並べてある。
  カーブを変えたら**両方**直すこと

**雨・雪のエフェクト**（`updateParticles`）:
- 選択時刻の**風速と風向に合わせて横に流す**（v4.39.0）。風向は「吹いてくる方角」なので
  進む向きは `-sin(風向)`（西風270°なら右へ）。強風時は横殴りになる
- 横殴りのときは風上側の画面外からも湧かせ、左右にはみ出したら出し直す（隙間対策）

## タイル取得の失敗報告（`watchTileStatus`）

⚠⚠**「全部ダメ」だけでなく「ほとんどダメ」も言うこと**（v4.71.0）。

以前は `if (loaded > 0) return;` で、**1枚でも読めたら以降の失敗を全部無視**していた。
そのせいでひまわりのカラーが大半404・帯状にしか出ていないのに画面には何も出ず、
利用者からは「雲が写らない」としか見えなかった。**この作りのせいで原因の切り分けに
何往復もかかった。**

- 端の欠けで騒がないよう、**枚数が溜まってから割合で**判定する
  （`WX_FAIL_MIN_TILES`=6 / `WX_FAIL_RATIO`=0.4 / `WX_FAIL_SETTLE_MS`=1500）
- タイルは非同期に届くので、**落ち着いてから数える**（毎回判定すると出たり消えたりする）
- 全部届いているときは何も出さない（狼少年にしない）。テストは両方を見ている

## 雨の予告（v4.67.0）

地図画面の下、地点チップの上に1行だけ出す（`#map-rain`）。ウェザーニュースの
レーダー画面にある「明日夕方15時から雨」「あと〇〇分で雨が止みます」に相当する。

**2段構え。上の段が出せなければ下の段のまま**という作りにしてある。

1. **毎時データの見込み**（`rainOutlookHourly(data, fromIdx)`）
   - `state.allData` の `precip` だけを見る純関数。追加の通信ゼロなので**必ず出せる**
   - `RAIN_MM = 0.1`（mm/h）以上を「降っている」とみなし、そこから
     `RAIN_LOOK_H = 48` 時間先までの**最初の変わり目**を探す
   - 言い回しは気象庁の時間帯（未明/明け方/朝/昼前/昼過ぎ/夕方/夜のはじめ頃/夜遅く）＋
     今日/明日/明後日。それより先は `M/D`
   - **雨と雪を言い分ける**（`snow > 0`）。バックカントリーでは意味がまるで違うため
2. **ナウキャストの1画素読み**（`rainOutlookNowcast(lat, lon)`）
   - 気象庁ナウキャストの `targetTimes_N1.json` は**実況だけでなく予報も入っている**
     （basetime が同じで validtime が5分ずつ進む）。`jmaTimesList()` が絞らずに全部返し、
     `nowcastSeries()` が「実況→予報」の並びに直す。地図に貼る `jmaTimes()` は
     そこから実況だけを取り出す薄い包み
   - 地点の緯度経度を `tilePixelAt()` でタイル番号＋タイル内画素に直し、
     実況＋60分先（`NOWC_MAX_STEPS = 13`）ぶんのタイルを1枚ずつ読んで
     **`NOWC_ALPHA_MIN = 30` 以上の不透明度なら降っている**とみなす
   - **色→mm/h の対応は推測しない。** 「塗ってあるか否か」だけで判断している
   - 最初の変わり目を5分刻みに丸めて「あと35分で雨が止みます」を出す。
     出せたら1段目を上書きし、`.nowcast` クラスで色を変えて出所の違いを見せる

⚠**気をつけること**

- **1画素しか読まないこと。** 1×1のcanvasに負のオフセットで描いて目当ての画素を(0,0)に
  落としている。画面ぶんのcanvasを毎回作ると数MBの捨てゴミが積み上がり、
  iOSがWebプロセスごと落とす（雷マークで実際に踏んだ。v4.64.0の経緯を参照）
- **CORSが通らない環境では黙って1段目に戻すこと。** `crossOrigin='anonymous'` を
  付けずに読むと canvas が汚れて `getImageData` が例外になる。付けても
  サーバがヘッダを返さなければ画像の読み込み自体が失敗する。どちらの道でも
  `rainOutlookNowcast` は null を返し、毎時の見込みがそのまま残る
- **地図を閉じている間は取りに行かない。** `updateRainOutlook()` の先頭で
  `isMapOpen()` を見ている。外すと地点を変えるたびに気象庁へ余計な通信が出る
  （`smoke_snowui` の「通信回数は地点数に依存しない」が実際に落ちた）

## ランキングから地点へ飛ぶ（v4.70.0）

一覧の名前を押すと、その地点の96hメテオグラムへ移る（`gotoPeak`）。3種類ある。

| 押す所 | 飛び先 |
|---|---|
| 峰名（`.peak-link`） | その峰。以前から |
| **山域名（`.area-link`）** | **代表峰＝その山域でいちばん良い判定を出した峰**（`bestPeakOf`） |
| **新雪の地点名（`.spot-link`）** | その地点 |

- 山域名を足したのは「ランキングの山の状況をすぐ確認したい」という要望から。
  以前は 山域を開く → 峰を押す の2手だった
- 飛び先が代表峰なのは、カードの見出し（山域＝代表峰の最良値）と同じ峰にするため。
  地点名は**峰の名前**にする（山域名のまま飛ぶと、どこの値を見ているのか嘘になる）
- ⚠**リンクは文字の幅ぶんだけにすること**（`display: inline-block`）。行いっぱいに
  広げると、峰の一覧を開こうとして余白を押しただけで飛んでしまう。
  カードの見出し全体は今までどおり開閉に使う
- 新雪の一覧に飛び先を持たせるため、`snowRanking.js` の行に `lat`/`lon` を足した。
  **推定には使わない素通しの値**（ABC評価とは無関係のまま）

## 地図に浮かぶ札の配色

⚠⚠**下地を白で直書きしないこと**（v4.73.0）。

文字色は `var(--text)` 系でテーマに追従するので、下地だけ白のままにすると
**ダークモードで白地に白文字**になる。実機で検索ボタンと「気象データ取得中…」が
読めなくなった。

- 半透明の下地は **`rgba(var(--surface-rgb), α)`** を使う（ライト=白 / ダーク=暗色）
- `#map-search-btn` のように**下地が `var(--text)`** のものは、文字を `#fff` ではなく
  **`var(--surface)`** にする（下地の反転を保ったままテーマに追従する）
- `#map-attribution` のように**下地も文字も直書き**で対になっているものはそのままでよい
- `#map-rain` も下地・文字とも直書きの対
- `smoke_mapui` が `colorScheme: 'dark'` でコントラスト比を測っている
  （壊すと 1.01〜1.1 になって落ちる）

## 現在地の追跡（`locateMode`）

3段階。`off` → `once`（現在地へ寄って地点も選ぶ）→ `follow`（画面中央に追い続ける）。

- ⚠⚠**「自分の意思で地点を選んだ」ら追従はやめること**（`releaseFollow()`。v4.69.0）。
  追従したまま別の地点へ飛ばすと、**次のGPS更新（数秒後）で現在地へ引き戻される**。
  円柱で地域を選ぶと一度その地点へ飛んでから戻る不具合を出した（利用者の報告）。
  呼ぶ場所は3つ——円柱（`selectFav`）・検索結果（`pickMapPoint(lat,lon,name)`）・
  長押しのピン（`pickMapPoint(lat,lng)`）
- 追跡ごと切らず **`follow` → `once` に落とす**。現在地の点とまわりのマスクは残したいため
- ⚠**ヘディングアップは追従が前提でドラッグを止めている**ので、追従をやめるときは
  一緒に戻す。残すと「回ったまま・追わない・動かせない」地図になる
- ⚠**「追跡しているか」と「追従しているか」を混同しない。** 拡大縮小の基準点
  （`zoomAnchor`）は `geoWatchId != null` ではなく **`mapFollow`** で判定する。
  前者だと、地点を選んだあとに拡大しただけで現在地へ引き戻される

## PWA（v4.35.0〜）

デスクトップ／ホーム画面にインストールできる。手順とアイコンの再生成は `docs/install.md`。

- `manifest.webmanifest` … `display: standalone`、`start_url`/`scope` は `./`（GitHub Pagesの
  サブパス配信でもNetlifyプレビューでも動くよう相対にしてある）
- `sw.js` … **HTMLはネットワーク優先**（更新が古いまま残らないため）、同梱の静的ファイルは
  キャッシュ優先＋裏で更新、気象API・地図タイル・`outlook.json` は一切キャッシュしない。
  本体を大きく変えたら `CACHE_VERSION` を上げる
- `icons/icon.svg` が原図。PNGは `node scripts/gen-icons.mjs` で書き出してコミットする
  （ImageMagick等が無い環境なので同梱のChromiumで描画している）

**プログラム的スクロール**（「現在」ボタンなど）:
- `animateScrollTo()` が自前のrAFアニメーションでチャートと帯を**毎フレーム同じ値へ同時に**動かす。
  実行中は `programmaticScroll` を立てて両方のスクロールハンドラを止める
- **ブラウザ標準の `scrollTo({behavior:'smooth'})` は使わない。** 片方しか動かせないため、
  ミラーで動いた帯のscrollイベントが「なぞり」と誤検出され、`scrubFrame` が
  アニメーションを打ち切って元の位置へ引き戻していた（v4.36.0で修正）
- 帯に指が触れたら `cancelScrollAnim()` で即座に操作を優先する

## 重要な経緯（同じ失敗を繰り返さないため）

1. **風速の単位**: Open-Meteo の風速の既定単位は **km/h**。m/s が欲しい場合は必ず
   `wind_speed_unit=ms` を付ける。これを忘れて km/h を m/s として扱い、表示が約3.6倍・
   ABC判定が約3.6倍厳しくなる不具合を出した（v4.28.0で修正）。
   **Open-Meteoに変数を足すときは単位を必ず確認すること。**
2. **判定閾値**: 上記バグの対症療法として一度閾値を緩めたが（v4.27.0）、単位修正後に
   当初の m/s 基準へ戻した（v4.28.0）。現行は日帰り B:5 / C:10 m/s、幕営 B:3 / C:8 m/s。
3. **ABC評価ロジック**: `abcScore` / `abcScoreInv` / `judgePoint` は変更禁止（CLAUDE.md）。
   調整が必要なときは `THRESH` の閾値のみを変える。
4. **モデル依存の変数**: `models=jma_seamless` では突風・気圧面雲量が取れない。
   これらは models 未指定（best_match）の**別リクエスト**で取得し、失敗しても
   本体に影響させない作りにしてある（`fetchSupplemental`）。
5. **デプロイ**: Netlify は無料枠のクレジット切れで停止したため **GitHub Pages に移行済み**。
   PRに出る Netlify のプレビューURLは確認用で、本番ではない。
6. **時間移動UIの変遷**: 「チャートを横スワイプして時刻選択」→「スライダー＋タップ」→
   （v4.30.0）「下部スクラバー帯＋タップ」。スライダーが使いにくかった原因は**密度**で、
   73時間を幅約336pxに載せて1時間≒4.6px、指1本が約9時間に相当していた。
   帯は1時間=14pxなので指1本が約3時間。
   **チャート直接スワイプは一度採用して撤回した方式なので、戻すときは慎重に。**
7. **お気に入りの引っかかり**: 地点を選ぶたびに `renderFavRotary()` が `innerHTML` を
   全消しして駒を作り直し、スクロール位置がリセット→再センタリング、という
   二段構えになっていたのが原因（v4.30.0で修正）。**ここに手を入れるときは
   DOM再構築を増やさないこと。**
8. **末尾の空白**: 選択線を画面の14%位置に固定していたため、最後の時刻を選択線へ
   持ってくるには右に画面幅の86%ぶんの余白が構造的に必要で、それが空白に見えていた
   （v4.31.0で修正）。**選択線の位置を固定値に戻すと空白も戻る。**
9. **狭い枠での円柱**: ヘッダーに移した際、半径そのままだと隣の駒が正面の駒に
   重なった。**半径ではなく1駒の角度（`FAV_ANGLE`）を広げる**と、隣の駒がより外側
   （x = R sinθ）かつ強く圧縮される（幅 ∝ cosθ）ので重なりが解ける。
   駒は絶対配置なので、枠外へ出たものは `display:none` にしないとスクロール範囲が狂う。
10. **予報期間**: Open-Meteoの `forecast_days` の上限は16だが、実際に値が返る長さは
   モデル依存。`jma_seamless` はGSMの予報期間（約11日とされる）まで。
   **未検証なので鵜呑みにしないこと。** 確認は下記URLを開いて末尾を見る:
   `https://api.open-meteo.com/v1/forecast?latitude=36.57&longitude=137.65&hourly=temperature_2m&forecast_days=16&models=jma_seamless&timezone=Asia%2FTokyo`
11. **上下の赤線のズレ**: 「下が先行し上が追いかける」症状。原因は段階的に3つ潰した。
    ①選択線の更新を `requestAnimationFrame` に逃がしていて1フレーム遅れた、
    ②なぞり終わりの吸い付きが smooth で帯の慣性と競合した（以上v4.33.0）、
    ③**本命**：追従を scroll イベントに載せていたこと。帯はコンポジタ側で滑らかに
    動くのに対し scroll イベントは間引かれるため、JSで動かす側だけが遅れる（v4.34.0）。
    **スクロール追従をイベント頻度に依存させないこと。** なぞり中は rAF ループで
    毎フレーム実測し、上下の線は同じ一つの値で置く。吸い付きは即時にする。
12. **「現在」で飛ばない**: チャートだけを `scrollTo({behavior:'smooth'})` で動かしていたため、
    ミラーで動いた帯のscrollイベントが「なぞり」と誤検出され、`scrubFrame` が
    `chartsWrapper.scrollLeft` を書いてアニメーションを打ち切り、元の位置の index へ
    吸い付いていた（「下のバーは一瞬飛ぶが上が追従せず、下も元に戻る」症状）。
    **チャートと帯は必ず同時に動かすこと。** 標準のsmoothスクロールは片方しか
    動かせないので使わず、自前のrAFアニメーション（`animateScrollTo`）を使う。
13. **上下の時刻のズレ**: 帯の指標を「中央(50%)固定」、チャートの選択線を
   「画面のSCRUB_POS(14%)」に置いていたため、両者が別の場所を指していた。
   目盛りの間隔も帯14px/hに対しチャート約13.08px/hと違っていた。
   **帯とチャートは必ず同じ座標系（余白・px/h・スクロール量・idxToX）を共有させること。**
   どちらか一方だけの寸法をいじるとまたズレる。
