## 画面構成（現行）

上から: ヘッダー（左＝小さいブランド＋**大きな日付** / 右＝お気に入り円柱＋★） →
チャート4枚 → 時間スクラバー帯 → **凡例** → フッター

お気に入り専用の行は廃止しヘッダーに同居（v4.32.0）。凡例は下段へ移動（v4.33.0）。
チャートの上に載るのはヘッダー1行（48px）だけ。

チャート4枚:
1. **気温**（左軸℃）
2. **雲/雨**（左軸=降水mm/h、右軸=高度km）… 雲を高度方向に濃淡表示＋降水バー＋標高ライン
3. **風**（左軸=風速m/s、右軸=突風m/s）
4. **気圧**（左軸hPa）… 6時間変化量で線を色分け、急変時に警告帯とラベル

**役割分担**: 画面上部のチャート＝**参照**、下部の帯＝**移動**。

**表示範囲**: **実績72h（`PAST_HOURS`）＋現在＋予報168h（`FORECAST_HOURS`）＝241点**の固定。
「予報 / 実績+予報」の切替UIは撤去済み（v4.32.0）。取得は `past_days=3&forecast_days=9`。
モデルの予報期間を超えた末尾は `processData` がnullを見て切り落とすので、
`forecast_days` に何を指定しても「実際に値がある所まで」が表示される。

**選択の仕組み**: `state.sliderIndex` が主。赤の選択線はその時刻の位置を指す。
- チャートのタップ／ドラッグ → その位置の時刻を選択（スクロールしない）
- 下部スクラバー帯をなぞる → 選択時刻を移動（チャートが連動してスクロール）
- チャートの指スワイプによる横スクロールは**無効**（`overflow-x: hidden`）
- 選択情報は指追従のポップアップに集約（上部の日付バー/HUD/ABCカードは撤去済み）
- 日帰り/幕営のモード切替は撤去済み。`state.mode` は `'day'` 固定
- レンジ切替（予報 / 実績+予報）も撤去済み。常に実績＋予報を表示する

**日付バッジ**（`#date-badge`。ヘッダー左上。画面で一番目立つ位置に19pxで置く）:
- 選択中の時刻の「N月N日(曜)」を表示し、スクラバーの操作に追従する
- **日曜・祝日は赤、土曜は青。祝日は「（山の日）」のように名称も出す**
- 祝日は `jpHoliday()` が算出する。日付固定・ハッピーマンデー・春分/秋分（近似式、
  1980〜2099年で有効）に加え、**振替休日・国民の休日**も判定する。
  五輪年のような一度きりの特例日程には非対応（表示は前後10日ぶんなので実害なし）
- スクラバー帯の日付ラベルも同じ規則で色分けし、祝日名を添える

**お気に入り円柱ピッカー**（`#fav-rotary`）:
- 縦軸まわりに回る円柱の側面に地点名が書いてあるイメージ
- **スクロールは入力（慣性・スナップ）専用**。透明トラック `#fav-track` が
  スクロール量を作り、`position: sticky` の `#fav-stage` に駒を絶対配置する。
  舞台はスクロールしないので、駒の位置をJSが円柱の座標として自由に決められる
- 正面からの距離d（駒数）に対し 角度 = d × `FAV_ANGLE`(36deg)、
  x = `FAV_R` × sin(角度)、z = `FAV_R` × cos(角度) − `FAV_R`、rotateY(角度)。
  88degを超えた駒は円柱の裏側なので非表示
- **横幅は円柱の直径（`FAV_R`×2）を超えない**。地点が増えても場所を取らない。
  枠自体は画面幅の50%を `margin-left:auto` で右端（★の手前）に寄せてある
- 正面の駒＝選択地点（`.centered`）。回している最中も正面の駒が即座に強調される
- **地点リストの顔ぶれが変わらない限りDOMを作り直さない**（`favRotaryKey` で判定）。
  作り直すとスクロール位置がリセットされて引っかかるため

**時間スクラバー帯**（`#scrubber`）:
- **チャートとまったく同じ座標系を使う。** 左右の余白（`chartPadL`/`chartPadR`）、
  内容幅（`chartTotalW()`）、1時間の幅（`pxPerHourVal`）、x座標（`idxToX()`）、
  スクロール量のすべてが `#charts-inner` と共通。だから帯の目盛りは
  真上のチャートの同じ時刻の真下に来る
- **なぞり中の同期は `scrubFrame()` の requestAnimationFrame ループが行う。**
  最初のscrollイベントでループを起こし、以降は毎フレーム帯の `scrollLeft` を実測して
  チャートと上下の選択線を更新する。scrollイベントはiOSなどで間引かれるため、
  イベント駆動にすると帯だけ先行して上の選択線が遅れる（v4.34.0で修正）
- なぞり中は上下の選択線を**どちらも帯の実測値**で置く（`positionScrubLine(at)`）
- チャート側からの同期は `mirrorScrollToScrubber()`。ループ動作中は主導権を譲る
- 選択インジケータ `#scrubber-center` は固定位置ではなく、`positionScrubLine()` が
  赤い選択線とまったく同じxに置く（チャートのタップ選択時も線が帯まで続く）
- 帯のcanvasに昼夜の地色・ABC判定バー・降水バー・日付区切り・現在時刻の印を描画

**選択線の位置**（`cursorX`）:
- **両端に余白は置かない**（`chartPadL` / `chartPadR` は0）。以前は先頭・末尾の時刻を
  選択線に届かせるため右に画面幅の86%ぶんの余白があり、それが末尾の空白に見えていた
- 選択線はふだん画面の `SCRUB_POS`(**50%＝ど真ん中**)に固定だが、**両端の ramp px ぶんだけ
  かけてその端へ寄っていく**。これで余白ゼロのままスクロールだけで先頭・末尾の時刻に届く。
  中央固定なので先頭側にもランプが要る（先頭の時刻は左端にしか来られないため）
- 指を離したときのポップアップ定位置は `POPUP_HOME`(13%)。`SCRUB_POS` に追従させると
  中央の選択線と重なるので別定数に分けてある
- `cursorX` がスクロール量に依存するため、`scrollToIndex` は不動点反復で解く

## PWA（v4.35.0〜）

デスクトップ／ホーム画面にインストールできる。手順とアイコンの再生成は `docs/install.md`。

- `manifest.webmanifest` … `display: standalone`、`start_url`/`scope` は `./`（GitHub Pagesの
  サブパス配信でもNetlifyプレビューでも動くよう相対にしてある）
- `sw.js` … **HTMLはネットワーク優先**（更新が古いまま残らないため）、同梱の静的ファイルは
  キャッシュ優先＋裏で更新、気象API・地図タイル・`outlook.json` は一切キャッシュしない。
  本体を大きく変えたら `CACHE_VERSION` を上げる
- `icons/icon.svg` が原図。PNGは `node scripts/gen-icons.mjs` で書き出してコミットする
  （ImageMagick等が無い環境なので同梱のChromiumで描画している）

## 重要な経緯（同じ失敗を繰り返さないため）

1. **風速の単位**: Open-Meteo の風速の既定単位は **km/h**。m/s が欲しい場合は必ず
   `wind_speed_unit=ms` を付ける。これを忘れて km/h を m/s として扱い、表示が約3.6倍・
   ABC判定が約3.6倍厳しくなる不具合を出した（v4.28.0で修正）。
   **Open-Meteoに変数を足すときは単位を必ず確認すること。**
2. **判定閾値**: 上記バグの対症療法として一度閾値を緩めたが（v4.27.0）、単位修正後に
   当初の m/s 基準へ戻した（v4.28.0）。現行は日帰り B:5 / C:10 m/s、幕営 B:3 / C:8 m/s。
3. **ABC評価ロジック**: `abcScore` / `abcScoreInv` / `judgePoint` は変更禁止（CLAUDE.md）。
   調整が必要なときは `THRESH` の閾値のみを変える。
4. **モデル依存の変数**: `models=jma_seamless` では突風・気圧面雲量が取れない。
   これらは models 未指定（best_match）の**別リクエスト**で取得し、失敗しても
   本体に影響させない作りにしてある（`fetchSupplemental`）。
5. **デプロイ**: Netlify は無料枠のクレジット切れで停止したため **GitHub Pages に移行済み**。
   PRに出る Netlify のプレビューURLは確認用で、本番ではない。
6. **時間移動UIの変遷**: 「チャートを横スワイプして時刻選択」→「スライダー＋タップ」→
   （v4.30.0）「下部スクラバー帯＋タップ」。スライダーが使いにくかった原因は**密度**で、
   73時間を幅約336pxに載せて1時間≒4.6px、指1本が約9時間に相当していた。
   帯は1時間=14pxなので指1本が約3時間。
   **チャート直接スワイプは一度採用して撤回した方式なので、戻すときは慎重に。**
7. **お気に入りの引っかかり**: 地点を選ぶたびに `renderFavRotary()` が `innerHTML` を
   全消しして駒を作り直し、スクロール位置がリセット→再センタリング、という
   二段構えになっていたのが原因（v4.30.0で修正）。**ここに手を入れるときは
   DOM再構築を増やさないこと。**
8. **末尾の空白**: 選択線を画面の14%位置に固定していたため、最後の時刻を選択線へ
   持ってくるには右に画面幅の86%ぶんの余白が構造的に必要で、それが空白に見えていた
   （v4.31.0で修正）。**選択線の位置を固定値に戻すと空白も戻る。**
9. **狭い枠での円柱**: ヘッダーに移した際、半径そのままだと隣の駒が正面の駒に
   重なった。**半径ではなく1駒の角度（`FAV_ANGLE`）を広げる**と、隣の駒がより外側
   （x = R sinθ）かつ強く圧縮される（幅 ∝ cosθ）ので重なりが解ける。
   駒は絶対配置なので、枠外へ出たものは `display:none` にしないとスクロール範囲が狂う。
10. **予報期間**: Open-Meteoの `forecast_days` の上限は16だが、実際に値が返る長さは
   モデル依存。`jma_seamless` はGSMの予報期間（約11日とされる）まで。
   **未検証なので鵜呑みにしないこと。** 確認は下記URLを開いて末尾を見る:
   `https://api.open-meteo.com/v1/forecast?latitude=36.57&longitude=137.65&hourly=temperature_2m&forecast_days=16&models=jma_seamless&timezone=Asia%2FTokyo`
11. **上下の赤線のズレ**: 「下が先行し上が追いかける」症状。原因は段階的に3つ潰した。
    ①選択線の更新を `requestAnimationFrame` に逃がしていて1フレーム遅れた、
    ②なぞり終わりの吸い付きが smooth で帯の慣性と競合した（以上v4.33.0）、
    ③**本命**：追従を scroll イベントに載せていたこと。帯はコンポジタ側で滑らかに
    動くのに対し scroll イベントは間引かれるため、JSで動かす側だけが遅れる（v4.34.0）。
    **スクロール追従をイベント頻度に依存させないこと。** なぞり中は rAF ループで
    毎フレーム実測し、上下の線は同じ一つの値で置く。吸い付きは即時にする。
12. **上下の時刻のズレ**: 帯の指標を「中央(50%)固定」、チャートの選択線を
   「画面のSCRUB_POS(14%)」に置いていたため、両者が別の場所を指していた。
   目盛りの間隔も帯14px/hに対しチャート約13.08px/hと違っていた。
   **帯とチャートは必ず同じ座標系（余白・px/h・スクロール量・idxToX）を共有させること。**
   どちらか一方だけの寸法をいじるとまたズレる。
