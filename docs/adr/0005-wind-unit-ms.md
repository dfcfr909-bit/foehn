# ADR-0005: Open-Meteo の風速は必ず `wind_speed_unit=ms` を指定する（事故の記録）

- ステータス: 採用
- 日付: 2026-08-07（記録日。事故は v4.27.0、修正は v4.28.0）

## 背景

**Open-Meteo Forecast API の風速の既定単位は km/h。** m/s ではない。

これを見落とし、返ってきた km/h の値を m/s としてそのまま扱っていた。結果:

- 画面の風速表示が**約3.6倍**になった
- ABC評価の風速閾値は m/s 基準なので、**判定が約3.6倍厳しく**なった
  （風速3m/sの日が「10.8m/s」として C 判定に落ちる）

さらに悪いことに、**原因を単位ではなく閾値の問題だと誤診し、
v4.27.0 で「判定が厳しすぎる」対症療法として閾値を緩めてしまった。**
その後に単位が原因だと判明し、v4.28.0 で `wind_speed_unit=ms` を追加すると同時に、
**緩めた閾値を当初の m/s 基準へ戻した**（現行: 日帰り B:5 / C:10 m/s、幕営 B:3 / C:8 m/s）。

## 決定

**Open-Meteo を叩くリクエストには、風速を含む限り必ず `wind_speed_unit=ms` を付ける。**
本体（`sotoki_v4.html`）・補助リクエスト（`fetchSupplemental`）・
新雪ランキング（`snowRanking.js` / `scripts/buildSpots.mjs`）の**すべて**が対象。

## 理由 / 検討した代案

- **なぜ ms 指定か**
  - ABC評価（`abcScore` / `abcScoreInv` / `judgePoint`）と `THRESH` の閾値はすべて m/s 基準で、
    これは変更禁止領域。データ側を合わせるのが唯一の正しい向き
  - 日本の山岳の風速は m/s で語られる。表示単位としても m/s が正

- **却下: 取得したあとコードの中で km/h → m/s に割る**
  - 割り忘れる箇所が必ず出る。実際、風速を使う経路は本体・補助・新雪ランキングと複数あり、
    どこか1つで割り忘れれば同じ事故が再発する。**APIに正しい単位で返させる方が漏れない**

- **却下（実際にやって撤回した）: 判定閾値を緩めて「厳しすぎる」を解消する**
  - v4.27.0 でこれをやった。**症状は薄まるが原因は残る**うえ、
    数字が3.6倍のまま表示され続けるので利用者に嘘をつく。
    さらに、あとで単位を直したときに閾値が二重にズレる。
    **「判定が厳しい／緩い」と感じたら、閾値を触る前にまず単位と数値の桁を疑うこと**

- **却下: 単位の既定値を記憶に頼る**
  - 記憶違いで起きた事故そのもの。**Open-Meteo に変数を足すときは、
    その変数の単位を毎回ドキュメントで確認する**（風速以外にも既定単位はある）

## 影響

- Open-Meteo のURLを組み立てる箇所を新設したら、`wind_speed_unit=ms` を入れること。
  既存は `sotoki_v4.html` / `snowRanking.js` / `scripts/buildSpots.mjs`
- **ABC評価ロジック（`abcScore` / `abcScoreInv` / `judgePoint`）は変更禁止。**
  調整が必要なら `THRESH` の閾値だけを触る。
  `judgePoint` と `judgeBreakdown()` は同じ `THRESH` / 同じ `abcScore` を使うので、
  `THRESH` を直せば両方に効く
- 「表示がおかしい」系の不具合では、まず**桁（3.6倍・1/3.6倍）を疑う**。
  この倍率が見えたら単位の取り違えを最初に確認する
