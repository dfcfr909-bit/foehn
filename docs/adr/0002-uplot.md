# ADR-0002: チャート描画に uPlot を採用し、`vendor/` に同梱する

- ステータス: 採用
- 日付: 2026-08-07（記録日。移行そのものは全面改修＝`docs/requirements_renewal.md` の項目1）

## 背景

メテオグラムは気温・雲/雨・風・気圧の4枚を、実績72h＋現在＋予報168h＝241点ぶん
横に並べて描く。内容幅は3,000pxを超え、指でなぞって横に動かす。
つまり **「幅の広いcanvasを4枚、指の動きに追従させて動かす」** のが要件で、
描画性能とスクロールの手触りが全面改修の主目的だった（要件定義 実装順序 1番）。

## 決定

チャートライブラリは **uPlot 1.6.32** を採用し、CDNではなく **`vendor/` にファイルを同梱**する。
昼夜シェーディング・雲ラスタ・天気記号など独自の描画は uPlot の draw hook から
自前のcanvas描画として差し込む。

## 理由 / 検討した代案

- **なぜ uPlot か**
  - canvas直描きで軽い。241点×4枚を持っても指の動きに追いつく
  - draw hook で**素のcanvasコンテキストに自由に描ける**。本アプリは
    夜帯シェーディング（`paintNightOverlay`）、雲の無段階ラスタ（`buildCloudRaster`）、
    自前ベクターの天気記号（ADR-0004）といった独自描画が本体で、
    「ライブラリの表現力」より「邪魔をしないこと」が要る
  - 軸・スケール・座標変換だけを借りて、見た目はこちらで作る使い方に合う

- **却下: Chart.js / ECharts などの高機能ライブラリ**
  - 表現の大半を自前描画でやるので、高機能ぶんはそのまま死に荷重になる
  - 巨大なcanvasを毎フレーム再描画する前提の作りが多く、
    横スクロールの手触りという最重要要件で不利

- **却下: SVGベースのライブラリ（D3など）**
  - 241点×4枚を要素として持つとDOMが重い。iOSは特に苦しい
  - iOS Safari の SVG まわりでは既に何度も踏んでいる（フィルタの使い回しで3回）

- **却下: CDN から uPlot を読む**
  - **CDNが403等で失敗した実績がある。** ライブラリが落ちるとチャートが丸ごと出ない。
    山中で電波が細い状況を想定するアプリなので、本体と同じ経路で確実に配れる方を採る
  - `vendor/` 同梱ならバージョンがリポジトリに固定され、
    CDN側の更新でいきなり挙動が変わることもない

- **Leaflet は CDN のまま**にしてある。こちらは地図画面を開いたときだけ必要で、
  読めなければ地図が出ないだけで済む（メテオグラムは動く）。同列に扱わない

## 影響

- **uPlot を CDN 参照に戻さないこと。** 更新するときは `vendor/` のファイルを差し替え、
  バージョン番号を CLAUDE.md の技術スタック欄に反映する
- チャートの見た目を変えたいときは、ライブラリの機能を探すのではなく
  draw hook 内の自前描画を触る（それが本アプリの実体）
- 気圧パネルのように**毎フレーム `setScale` しない**等、
  「再描画を起こさない」ための工夫が各所に入っている。ここを崩すとカクつきが再発する
  （チャートの移動は `scrollLeft` ではなく CSS transform）
