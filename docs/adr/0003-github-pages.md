# ADR-0003: ホスティングを Netlify から GitHub Pages へ移行する

- ステータス: 採用
- 日付: 2026-08-07（記録日。移行は v4.35.0 前後）

## 背景

公開は当初 Netlify で行っていたが、**無料枠のクレジットが切れて配信が停止した**。
アプリ本体は単一HTML（ADR-0001）＋静的ファイル数点で、
サーバ側の処理を必要としない（KYTの下書き生成だけは Cloudflare Worker に分けてある）。

## 決定

公開先を **GitHub Pages**（静的ファイル直接配信）に移した。
公開URLは https://dfcfr909-bit.github.io/SotoKi/ で、
`index.html` が `sotoki_v4.html` へリダイレクトする中継になっている。

## 理由 / 検討した代案

- **なぜ GitHub Pages か**
  - このリポジトリに静的ファイルしか無いので、そのまま置くだけで配信できる
  - 費用がかからず、クレジット切れで止まる構造がない（停止した理由がそもそもこれ）
  - リポジトリ＝配信物なので、`main` にマージした内容がそのまま本番になる

- **却下: Netlify の有料プランに上げる**
  - サーバ側の機能を使っていないので、支払う対価に見合う機能がない

- **却下: Netlify Functions を前提に組み直す**
  - 動的処理が必要になったのは KYT の下書き生成だけで、
    そちらは Cloudflare Worker（`worker/`）に分けて解決済み。
    アプリ本体のためにホスティングを動的に戻す理由がない

- **却下: 独自ドメイン＋別ホスティング**
  - 個人利用のPWAで、URLの見栄えに投資する段階ではない

## 影響

- **PRに出てくる Netlify のプレビューURLは確認用であって本番ではない。**
  残置のCIとして今も動いているが、そこで動いたことを「公開できた」と判断しないこと
- `manifest.webmanifest` の `start_url` / `scope` は **`./`（相対）** にしてある。
  GitHub Pages はサブパス配信（`/SotoKi/`）なので、絶対パスにするとPWAが壊れる
- サーバ側の処理は増やせない。必要になったら `worker/`（Cloudflare Worker）側に置く
- 公開URLが404になるという報告が出た場合、疑うのは
  GitHub Pages の公開設定か `index.html`（リダイレクト中継）の配信
