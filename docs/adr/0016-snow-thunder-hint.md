# ADR-0016: 降雪・雷雨の目安は、気象庁と Open-Meteo の予報モデルの値で作る（SCW は使わない）

- ステータス: 採用
- 日付: 2026-10-02

## 背景

利用者の要望は「雲・降雪を地図でグラフィカルに見たい。ここは新雪が降っていそう、ここは曇っていそう、が分かればよい」。
きっかけは SCW（supercweather.com）の雲観測マップだった。調査（2026-10-01〜02）の結果:

- SCW の雲観測マップは、公式のタイル配信・API の記述が無い。運営（weather-gpv）は画像データの配信・販売を行い、
  著作権は運営に帰属すると明記している。無料の閲覧は「9時間前〜3時間前」に制限され、最新は有料会員のみ。
- 雲形・雲頂高度の**算出方法は公開されていない**。SCW 自身が「積雪を雲と誤判定することがある」と書いている。
- このリポジトリは public で、公開PWAの利用者全員のブラウザからアクセスが飛ぶ。

要件は `docs/requirements_snow_thunder_hint.md`。

## 決定

1. **SCW のデータ・画像・URL・配色は取り込まない。** 使うのは気象庁（ひまわり・ナウキャスト）と Open-Meteo（どちらも既に使っている）だけ。新しい送信先は増えない。
2. **降雪の目安**（段階2・#131）は、Open-Meteo の JMA モデルの**気温と降水**から作る。標高補正した気温（`T = T2m + 0.0065 × (モデル標高 − z_ref)`）で雨・みぞれ・雪を分ける。閾値は仮置き（雪 ≦0.5℃／みぞれ ≦2.0℃）。
3. **雷雨の目安**（段階3）は、850hPa と 500hPa の気温・850hPa の露点から**ショワルター安定指数（SSI）を自前で計算**する。
4. **どちらも予報モデルの値であって、観測ではない。** 画面（凡例・札）に「観測ではありません・実際の降水は降雨レーダーで確認」と出す。
5. **ABC評価（`abcScore` / `abcScoreInv` / `judgePoint` / `THRESH`）とは独立。** 閾値は別の定数表（`SNOW_HINT`）に置き、判定には使わない。

## 理由 / 検討した代案

- **SCW を埋め込む**：公式の配信が無く、内部URLを使うことになる。規約・著作権・有料の壁・仕様変更のどれも避けられない。却下。
- **雲観測マップ（雲形7分類・雲頂高度の等値線）を再現する**：算出方法が非公開。しかも雲形は高度の区分で、乱層雲（雪や雨を降らせる雲）と高積雲が同じ色になるので、「降雪」を言えない。却下。
- **レーダーで絞る**：格子が約11km、レーダーが1kmで代表性が合わず、「降っていない」と言い切る方が危ない。初版は絞らない。必要なら実機で使ってから足す。
- **`freezing_level_height` で雨雪の境を出す／`cape`・`lifted_index` で雷雨を出す**：JMA モデルでは全時間 null（段階0・#126の調査）。使えない。
- **`elevation=` を渡して Open-Meteo に標高補正させる**：返る標高の意味が変わりうる（ADR-0011）。補正式は自前で持つ（実効の減率 6.47〜6.62℃/km と整合を確認済み）。
- **閾値を細かく詰める**：標高補正の誤差が ±1〜2℃あるので、境界を細かく追っても意味が薄い。仮置きとして定数表にまとめ、実機で調整する。

## 影響

- 降雪の目安・雷雨の目安は**判定に使わない**。広げるなら新しいADR。
- 風の取得に**相乗りしない**（変数が別）。ただし 429 の待ち（`windBackoffUntil`）は風と共有する。
- `jma_seamless` は近い時刻で MSM、先で GSM に切り替わる（値が大きく違う）。札にモデル名を出す。
- 層別雲量の高さの定義（Open-Meteo：低＜3km／中 3〜8km／高＞8km・未確認）は SCW の定義と別物。混ぜて書かない。
