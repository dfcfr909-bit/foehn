# ADR-0014: 風の流れを WebGL 版に一本化し、設定を「風の流れ」の行へ

- ステータス: 採用
- 日付: 2026-09-28

## 背景

ADR-0013 で WebGL 版の風の流れを「風の流れ（実験）」として Canvas 版と並べ、実機で比べてきた（v4.120.0〜v4.140.0）。
その間に、地形に沿った高さの風（段階1）、風下の遮蔽・コルの加速・収束（段階3a〜3c）、Windy 型の色（背景＝見た目の粒の速さ・粒は白）、
粒の数と背景の濃さのスライダーを足し、利用者が実機で確かめた。操作は開発用の「計測表示」（地図の上の黒いパネル）に集まっていた。

PR #104 を main（公開）へ入れる前に、次を決める必要があった。

- Canvas 版と WebGL 版の2つの層を並べたままにするか
- ふだん使う設定（色・補正・高さ・粒・背景）と、開発用の道具（地形解析・中心を解析・検証・10秒計測など）をどこに置くか

## 決定

1. **WebGL 版を正式な「風の流れ」にする**（層の id は `windFlowGL` のまま、名前だけ変える）。Canvas 版（`windFlow`）は**予備**に下げ、
   レイヤー一覧に出さない（`hidden`）。WebGL が使えない端末では、これまでどおり Canvas 版が代わりに流す。
   前の版で Canvas 版を入れていた人は、読み込み時に WebGL 版へ移す（透過率も引き継ぐ）
2. **設定は「風の流れ」の行に統合する**（利用者の選択）。色（背景／粒）・補正（切／遮蔽・コル）・高さ（地形／升目）・粒（スライダー・¼・½・×2）・
   背景の濃さ・「計測表示（開発用）」を、AUTO／層の切り替えと同じ場所に並べる。**どれも端末に覚える**
3. **計測表示は既定で切**。行の「計測表示」を入れたときだけ地図の上に出す。開発用の道具（補正を調べる・地形解析・中心を解析・検証・10秒計測・コピー）はそこに残す。
   切ると地形解析の重ねも消す
4. PC の粒の既定は 2万 → **1万**（利用者の上限 10,000 に合わせる）
5. 一時的だった「鞍部の検証（実験）」ワークフローは**消さずに手動実行だけ**にする（利用者：また後で使いそう。地点を足して閾値を見直すとき）
6. 説明ページ（`about.html`）の色の説明を直し、補正が**表示用の推定**であること・補正中の色はモデルの風速ではないことを書く

## 理由 / 検討した代案

| 案 | 判断 |
|---|---|
| 2つの層を並べたまま | **却下**。同じ風を2つの描き方で出す層が並ぶと、どちらを入れればよいか迷う。比べる目的は果たした |
| Canvas 版を消す | **却下**。WebGL が使えない端末（古い端末・コンテキスト喪失）で風の流れが出なくなる |
| 計測表示を `?dev=1` のときだけ出す | **却下**（利用者の選択）。粒の数や背景をふだんから触るので、URL を毎回付けるのは不便 |
| 計測表示を残し、既定で畳む | **却下**（利用者の選択）。ふだんの設定と開発用の道具が同じパネルに混ざったままになる |
| 検証ワークフローを消す（ADR-0013 の頃のコメントどおり） | **却下**（利用者：後で使いそう）。push で走らないので CI の時間は増えない |

## 影響

- レイヤー一覧の気象の行から「風の流れ（実験）」が消え、「風の流れ」が WebGL 版になる。`MAP_WEATHER` の顔ぶれ（id）は変えない
  （`windFlow` は `hidden` で残す。`smoke_mapui` の顔ぶれの検査はそのまま）
- 設定の要素の id は計測表示にあったときのまま（`wind-hud-color`・`wind-hud-shelter`・`wind-hud-terrain`・`wind-sl-count`・`wind-sl-bg`）。
  「風の流れ」の行（`#layer-weather`）に出る。見た目の更新は `windFlowSettingsSync`（計測表示が無くても呼ぶ）
- 端末に覚える値：`windGL.count` / `windGL.bgAlpha` / `windGL.color` / `windGL.shelter` / `windGL.terrain` / `windGL.hud`（`windPref`・読めなくても既定で動く）
- 補正（段階3a〜3c）は**表示用の推定**のまま。矢印・ポップアップ・判定（ABC）はモデルの風。これは ADR-0013 と同じ役割分担
