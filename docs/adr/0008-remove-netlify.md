# ADR-0008: Netlify を完全に撤去し、PRのチェックをスモークテストに置き換える

- ステータス: 採用
- 日付: 2026-08-12
- 関連: ADR-0003（Netlify → GitHub Pages）、ADR-0007（院内資料の分離）

## 背景

ADR-0003 で本番を GitHub Pages に移したあとも、Netlify のプロジェクトは
**PRのデプロイプレビューを出す残置のCI**として残していた
（`docs/status.md` に「PRのNetlifyプレビューが唯一のCIチェック」と記録があった）。

ADR-0007 で院内資料を分離した際、**分離前のファイルが Netlify の過去デプロイに
残ったまま公開URLで配信され続けている**ことが分かった。
GitHub リポジトリを private にしても Netlify は止まらない（別サービスなので当然だが、
「GitHub を private にすれば公開は止まる」と誤解しやすい）。

つまり、このリポジトリには**気づきにくい第2の公開面**があった。
`netlify.toml` を置いてあること以外に、リポジトリ内のどこにも
サイト名（`aquamarine-queijadas-21a564`）が書かれておらず、
**どこに何が公開されているかをリポジトリから追えない状態**だった。

## 決定

Netlify プロジェクトを削除し、`netlify.toml` もリポジトリから消す。
PRのチェックは **GitHub Actions でスモークテスト（`tests/run-all.js`）を回す**方式に置き換える。

## 理由 / 検討した代案

- **なぜ撤去するか**
  - 本番ではない（ADR-0003）。得ていたのはプレビューURLだけ
  - **公開面が2つあると、片方を止め忘れる。** 実際に止め忘れた
  - リポジトリを見ても Netlify に何が出ているか分からない。追跡できない配信面は持たない

- **なぜテスト実行に置き換えるか**
  - プレビューは「ビルドが通った」しか保証しない。このリポジトリはビルドしないので、
    **実質なにも検証していなかった**
  - `tests/` には16件のスモークテストがあるのに、PRで自動実行されていなかった。
    プレビューより明確に強い

- **却下: Netlify を残し、パスワード保護だけかける**
  - 公開は止まるが、追跡できない配信面が残るという問題は解決しない。
    パスワードを外した瞬間に元に戻る

- **却下: Netlify を disable のまま放置する**
  - 再有効化が1クリックで、しかも「無効にしたこと」がリポジトリ側に残らない。
    次に触る人（＝未来の自分）が存在に気づけない

- **却下: プレビューを GitHub Pages のプレビュー環境で再現する**
  - GitHub Pages にブランチプレビューの仕組みはない。
    実機確認はマージ後に本番URLで行う（Issueの「実機確認」種別はもともとその運用）

## 影響

- **PRでマージ前に実機で触れなくなった。** 実機確認はマージ後に
  https://dfcfr909-bit.github.io/SotoKi/ で行う。
  代わりに PR で16件のスモークテストが自動で回る
- ADR-0003 の「PRに出てくる Netlify のプレビューURLは確認用であって本番ではない」は、
  **プレビュー自体が無くなったので該当しなくなった**（ADR-0003 は不変。ここで更新する）
- テストをCIで回すため、Chromium のパスを `PW_CHROMIUM` 環境変数で
  上書きできるようにした。既定値は従来どおり `/opt/pw-browsers/chromium`
- ⚠ **配信面を増やすときは、必ずどこかに書き残すこと。**
  リポジトリから追えない配信面は、止めるべきときに止められない

## 未決（この ADR では決めない）

ADR-0007 の対応でリポジトリを private にしたため、**GitHub Pages も停止している**
（無料枠では private リポジトリの Pages は配信されない）。
公開に戻すかどうかは、過去コミットに残る院内資料の扱い
（ADR-0007「履歴の書き換えは行っていない」）と一緒に判断する。
決めたら新しいADRを書く。
