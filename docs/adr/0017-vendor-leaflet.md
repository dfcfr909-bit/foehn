# ADR-0017: Leaflet も `vendor/` に同梱し、起動を止める外部読み込みを無くす

- ステータス: 採用
- 日付: 2026-10-12

## 背景

利用者が登山中に使って、「開くまでに時間がかかる」「電波が無いと開かない？」「地図がひらかない」と
報告した（#227）。原因の一つは、起動時に**外部の配信元から読み込みを止める形で取っていた**もの。

- Leaflet 1.9.4 を cdnjs から同期の `<script>` で読んでいた。`sw.js` は外部オリジンを控えないので、
  弱電波ではここで止まり、取れなければ `L` が無く地図そのものが作れない
- Web フォント（Google Fonts）を `<style>` の中の `@import` で読んでいた。これも描画を止める

ADR-0002 は「Leaflet は地図を開いたときだけ必要で、読めなければ地図が出ないだけで済む」として
CDN のままにしていた。山では圏外・弱電波がふつうで、**現地で地図が出ないことはアプリとして致命的**
（利用者：「欲しい地図が現地で見られないならなんの意味もない」）なので、この判断を覆す。

## 決定

- Leaflet 1.9.4（`leaflet.js` / `leaflet.css` / `images/` / `LICENSE`）を `vendor/leaflet/` に置き、
  `sw.js` の PRECACHE に入れる
- Web フォントは `<link rel="stylesheet" media="print" onload="this.media='all'">` で読み、起動を待たせない
  （取れなければ既定の字のまま）

## 理由 / 検討した代案

- **却下: CDN のまま `sw.js` で外部の Leaflet を控える** … 不透明な応答（opaque）になりうるうえ、
  初回に取れなければ同じこと。外部オリジンを控えない方針（`docs/spec/pwa.md`）も崩れる
- **却下: Leaflet を非同期で読み、地図を開くときに待つ** … 本体の多くの箇所が `L` を前提にしており、
  書き換えが大きい。同梱すれば圏外でも確実に読めるので、待つ理由自体が無くなる
- **却下: Web フォントも同梱** … 日本語フォントは数 MB あり、PRECACHE に入れると初回の取得が重くなる。
  字形が既定に戻るだけで機能は失わない

## 影響

- **Leaflet を CDN 参照に戻さないこと。** 更新するときは `vendor/leaflet/` を差し替え、
  `tests/package.json` の leaflet の版も揃える（`smoke_pwa` が同梱物と `tests/node_modules` の中身の一致を見る）
- 本体（`sotoki_v4.html`）に、外部オリジンの `<script src>`・止める形の外部 stylesheet・`@import` を足さないこと
  （`smoke_pwa` が落とす）
- ADR-0002 の「Leaflet は CDN のまま」の段はこの ADR で置き換えた（uPlot の同梱の判断はそのまま）
- 弱電波で HTML の取得を待つ問題（`sw.js` のネットワーク優先に見切りが無い）は、この ADR では扱っていない（#227 の残り）
