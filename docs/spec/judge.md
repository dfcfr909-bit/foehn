# ABC評価

> ⚠ **このロジックは変更禁止。** `abcScore` / `abcScoreInv` / `judgePoint` の
> **中身を書き換えない**（移植のみ）。調整が要るときは **`THRESH` の値だけ**を触る。
> → `docs/adr/0005-wind-unit-ms.md`

登山の適否を A（良）／B（注意）／C（危険）の3段階で出す。

## 評価していないもの

- **雪崩の危険度は評価していない。** 積雪の安定性・弱層・斜面方位は一切見ていない
- 地形（急斜面・沢地形・雪庇）も見ていない
- 評価の対象は「気象要素が単独で危険域にあるか」だけ

README の免責と同じ立場。**このアプリの判定だけで入山の可否を決めない。**

## 閾値（`THRESH`）

```js
const THRESH = {
  day:  { windA: 5,  windB: 10 },
  camp: { windA: 3,  windB: 8  },
  apparentA: -3, apparentB: -15,
  snowA: 0.5, snowB: 2,
  rainA: 1,   rainB: 3,
  dpressA: 6, dpressB: 10,
};
```

| 項目 | 単位 | A→B | B→C | 備考 |
|---|---|---|---|---|
| 風速（日帰り） | m/s | 5 | 10 | `state.mode` は `'day'` 固定 |
| 風速（幕営） | m/s | 3 | 8 | 切替UIは無い。`judgePoint` の構造を変えないため定義だけ残す |
| 体感気温 | ℃ | -3 | -15 | **低いほど悪い**（`abcScoreInv`） |
| 降雪 | cm/h | 0.5 | 2 | `snow > 0` のときだけ評価に入る |
| 降水 | mm/h | 1 | 3 | `precip > 0` のときだけ。B の理由は出さない |
| 気圧変化 | hPa/6h | 6 | 10 | 絶対値で見る（上昇も下降も） |

**風速は m/s。** Open-Meteo に `wind_speed_unit=ms` を指定して取得している。

## 判定に使う風は「山頂高度の気圧面風」

⚠ **地上10m風（`windspeed_10m`）で判定しない。** → `docs/adr/0006-summit-wind.md`

モデルの格子（MSMで約5km）では孤立峰の地形が平滑化されて潰れるため、山頂の風が出ない。
皇海山（2,144m）ではモデル地形が **1,405m** で、地上10m風 2.73 m/s に対し
山頂高度（800hPa=1,950m）の風は **21.02 m/s** だった（実測）。
**モデル地形より高く突き出た山ほど判定が甘くなる＝危険側にズレる。**

| 定数 / 関数 | 役割 |
|---|---|
| `WIND_LEVELS` | 気圧面と標準大気での高度。925/900/850/800/700/600 hPa |
| `windLevelFor(elevM)` | 山頂高度に**最も近い1層**を選ぶ |
| `pickWindSource(summitM, modelM)` | 気圧面と地上10mのどちらを使うか決める |
| `WIND_LEVEL_MIN_RISE` | 100m。山頂がモデル地形よりこれだけ高いときに気圧面へ |

- 山頂高度の優先順位は **`state.summitElev`（峰と分かっている場合の `areas.json` の値）
  → `state.demElevation`（地理院DEM）**。ランキングは `peak.elev` を直接使う
- ⚠ **DEMだけに頼らない。** 座標が山頂からずれるとDEMが斜面を読み、
  **静かに地上風の判定へ落ちる**（皇海山で実際に踏んだ。座標が**5.2km**ずれていた）。
  `gotoPeak(name, lat, lon, elev)` / `pickMapPoint(lat, lon, name, elev)` の
  **第4引数で標高を渡すこと**。渡さない選択（長押しのピン・お気に入り）はDEMに任せる
- ⚠ **山頂がモデル地形より高くないときは地上10m風のまま**（気圧面が地中になり、
  無意味な外挿値を拾うため）
- ⚠ **地上風に落ちたら画面に出す。** ポップアップに `@2144m` / `@地上10m（山頂の風が取れず）`
  のように添える。**黙って甘い判定に戻るのが、この件でいちばん危ない失敗の仕方**
- `d.wind10` に地上10m風を参照用に残してある（判定には使わない）

**`judgePoint` のコードも `THRESH` の閾値も変えていない。変えたのは入力データの質だけ。**

## スコア関数

```js
function abcScore(val, a, b)     // 高いほど悪い: val<a → 0 / val<b → 1 / それ以上 → 2
function abcScoreInv(val, a, b)  // 低いほど悪い: val>a → 0 / val>b → 1 / それ以下 → 2
```

`val == null` はどちらも 0（評価しない）を返す。

## `judgePoint(d)`

**入力** — 1時刻ぶんのデータ `d`。使うのは次の5つ。

| キー | 意味 |
|---|---|
| `d.wind` | 風速 m/s。**山頂高度の気圧面風**（下記） |
| `d.apparent` | 体感気温 ℃ |
| `d.snow` | 降雪 cm/h |
| `d.precip` | 降水 mm/h |
| `d.dpress` | 6時間の気圧変化量 hPa（符号つき。絶対値で評価する） |

閾値は `THRESH` と `THRESH[state.mode]` から引く。

**出力**

```js
{ grade: 'A' | 'B' | 'C', reasons: string[] }
```

- `grade` は各項目のスコアの**最悪値**（`Math.max`）を `['A','B','C']` に写したもの
- `reasons` はスコアが 1 以上だった項目の文言

| 項目 | スコア1 | スコア2 |
|---|---|---|
| 風速 | 風が強め | 風速が危険値 |
| 体感気温 | 体感寒冷 | 体感気温が危険値 |
| 降雪 | 降雪あり | 降雪が危険値 |
| 降水 | （文言なし） | 降水が危険値 |
| 気圧変化 | 気圧低下中 | 気圧変化が急激 |

## `judgeBreakdown(d)`

ポップアップで**根拠の数値を色分けする**ための内訳。読み取り専用。

```js
{ wind: 0|1|2, apparent: 0|1|2, precip: 0|1|2, dpress: 0|1|2 }
```

- `precip` は降雪と降水の**大きい方**
- **`judgePoint` とまったく同じ `THRESH`・同じ `abcScore`/`abcScoreInv` を使う。**
  だから閾値を変えるときは `THRESH` だけを触れば両方に効く
- `judgePoint` が変更禁止なので、内訳はこちらに分けてある

表示側は `updatePopup()` が `.lv1`（B相当=黄）／`.lv2`（C相当=赤）を付ける → `ui.md`

## 使われている所

| 場所 | 使い方 |
|---|---|
| 選択情報のポップアップ | `judgePoint` の grade ＋ `judgeBreakdown` の色分け |
| スクラバー帯の判定バー | 各時刻の grade を色で並べる（`drawScrubber`。A=`#2a7d4f` / B=`#e8a020` / C=`#d03030`） |
| 全国山域ランキング | `judgePeakDay()` が行動時間帯（`RANK_WINDOW_START`=6時〜18時）の**最悪値**を採る |

## 全国山域ランキングの対象（`areas.json`）

評価する山域と峰は `areas.json` に外出ししてある。**コードではなくこのファイルを直す。**

```json
{ "id": "yatsu", "name": "八ヶ岳", "region": "中部", "peaks": [
  { "name": "赤岳", "lat": 35.9714, "lon": 138.3703, "elev": 2899, "hyakumeizan": true }
]}
```

| キー | 意味 |
|---|---|
| `id` | 山域の識別子 |
| `name` | 表示名。カードの見出し |
| `region` | 地方。カードの副題（`rn-sub`）に出るだけで、グルーピングには使っていない |
| `peaks[].elev` | Open-Meteo に `elevation` として渡し、地形条件を揃える |
| `peaks[].hyakumeizan` | **日本百名山（深田久弥）なら true。** 判定には使わない |

現在 **51山域 / 110峰**。うち**百名山100座すべて**を含む。

⚠ **座標は山頂を指していないことがある**（皇海山は**5.2km**ずれていた → #67）。
ズレると DEM が斜面を読んで判定が甘くなるうえ、**モデルの格子セルまで変わって
予報が別地点のものになる**。見た目の問題ではない。

検査と修正は GitHub Actions「山頂座標の検査」から。
手元から地理院に到達できないため Actions で回す（スマホからでも実行できる）。

| mode | 中身 | 出るもの |
|---|---|---|
| `check` | `scripts/checkPeaks.mjs` | **どの峰がずれているか**（差の大きい順） |
| `snap` | `scripts/snapPeaks.mjs` | **正しい座標の修正案**（提案のみ。自動適用しない） |

`snap` は標高タイルのCSV（`dem/{z}/{x}/{y}.txt`。1枚で256×256点）で一帯を総なめし、
山頂を探す。

⚠ **「探索範囲の最高点」を採ってはいけない。** 笠ヶ岳(2,898m)の近くには
槍ヶ岳(3,180m)や穂高(3,190m)があるので、最高点だと**隣の別の山へ飛ぶ**うえ、
値がそれらしいので気づけない。**`elev` と一致する点のうち元の座標に最も近いもの**を
採る（公称の山頂標高を「山の識別子」として使う）。`tests/smoke_snap.mjs` が固定している。

自動で決められないもの・移動距離が大きいものは、
**アプリの地図で山頂を長押しし、下段に出る緯度経度を写す**（皇海山はこれで直した）。

⚠ **推測で座標を直さない**（2回外している → `docs/decisions.md` 2026-08-10）。
⚠ **`elev` を下げて辻褄を合わせない。** DEM は約10mメッシュの標本なので、
公称の山頂標高より数m低く出るのが正常（皇海山は 2,144m に対し DEM 2,141m）。

### 山域の粒度

**峰どうしがだいたい同じ天気になる範囲**（同じ山塊・稜線）でまとめる。

⚠ **地方単位の受け皿山域（「北海道」「その他」など）を作らないこと。**
カードの見出しに出る判定は `bestPeakOf(row)` ＝**その山域でいちばん良い判定を出した峰**で、
山域名を押すとその代表峰へ飛ぶ（`gotoPeak`）。
地理的に離れた峰を束ねると、**遠くの1座が晴れているだけで山域全体が A に見える**。

本当に孤立した山（大山・開聞岳・宮之浦岳・筑波山など）は**1座だけの山域でよい**。

### 全峰を1リクエストで取る

`fetchRankData()` が全峰の緯度経度をカンマ区切りで1本のURLにまとめる。
**地点数が増えてもリクエストは1本**だが、Open-Meteo のレートは**地点数ぶん消費する**。

## 新雪ランキングとの関係

**新雪ランキング（`snowRanking.js`）は ABC評価とは完全に独立している。**
`judgePoint` / `THRESH` / `abcScore` を参照しない（テストで固定してある）。
