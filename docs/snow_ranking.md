# 新雪ランキング

翌日の滑走先を選ぶための機能。ランキングの指標は

**直近24時間の新雪 ＋ 今夜〜明朝12時間の予想降雪**

で、降順に並べる。既存のABC評価（`judgePoint` / `THRESH` / `abcScore`）とは**完全に独立**していて、
あちらのコードには一切触れていない。

| ファイル | 役割 |
|---|---|
| `data/spots.seed.json` | 地点のシード。bbox / coord は概算値 |
| `scripts/buildSpots.mjs` | シード → `data/spots.json`。OSMと国土地理院で座標・標高を確定させる |
| `data/spots.json` | **生成物**。ランタイムが読むのはこれだけ |
| `snowRanking.js` | 推定エンジン（通信＋計算）。ブラウザでは `window.snowRanking` |
| `sotoki_v4.html` | 表示のみ（ランキングオーバーレイの「❄️ 新雪」タブ） |

## 設計の要点

| 課題 | 対応 |
|---|---|
| アメダスは麓にしかない | Open-Meteo に山頂標高を直接指定して推定する |
| モデルは日々バイアスを持つ | 近傍アメダスの実測降雪でモデル値を補正する（係数 k） |
| `snowfall` は 7:1 固定換算 | 気温から雪水比(SLR)を引き直し `precipitation` から算出する |
| スキー場とBCで体感が違う | 地点単位（索道最上部 / 山頂）で個別評価し、タグで区別する |

## 座標の確定（初回・地点を足したとき）

```bash
node scripts/buildSpots.mjs --dry-run   # シードの静的チェックだけ（通信しない）
node scripts/buildSpots.mjs             # 実際に生成する
```

`resort` は bbox 内の索道（駅ノード＋各リフト線の両端）を Overpass から拾い、
国土地理院の標高APIで**標高最大の点＝索道最上部**を採る。
`bc` は `coord` をそのまま使い、標高だけ取る。

**実行後は必ず出力を目視すること。**

- 湯沢周辺（かぐら / 神立 / 岩原 / 中里）は bbox が近接している。
  同一索道を拾っていないか座標を確認する（スクリプトも近すぎる組を警告する）
- 「OSMに索道データなし」が出た地点は、シードにその地点の `coord` を書き足して再実行する。
  `coord` のある `resort` は Overpass を叩かずその座標を使う
- `bc` の標高乖離警告（`expectedAlt` と 100m 以上ずれた）が出たら座標が間違っている。
  これが座標の自己検証になっている

相手は公共の無料APIなので、GSIは250ms、Overpassは地点間1200msあけている。
**ランタイムではこの2つを叩かない。** 生成物 `data/spots.json` を読むだけ。

## 推定の中身（`snowRanking.js`）

### 雪水比（SLR）

Open-Meteo の `snowfall` は降水量×7 の固定換算なので、重雪とパウダーが同じ値になる。
気温から SLR を引き直して `precipitation` から出す。

| 気温 | SLR | ラベル |
|---|---|---|
| −1℃以上 | 7 | 湿雪 |
| −5〜−1℃ | 11 | 標準 |
| −10〜−5℃ | 15 | パウダー |
| −10℃未満 | 20 | パウダー |

`降水量[mm] × SLR ÷ 10 = 実効新雪深[cm]`（例: 10mm × 11 ÷ 10 = 11cm）

**雪かどうかは「その時刻の `snowfall > 0`」で判定する。** 気温だけで決めない。
雪でない時間の `precipitation` は加算しない（雨を新雪に数えないため）。

### バイアス補正（係数 k）

```
k = アメダス実測 snow24h ÷ 同座標・同標高でのモデル24h snowfall
```

- `[0.5, 2.0]` にクランプする（分母が小さいときの発散を防ぐ）
- モデル値が **2cm未満** なら比が不安定なので k = 1（補正なし）
- `snow24h` が欠測でも k = 1

k は `precipitation` に掛けてから SLR を適用する。

> 理屈: アメダスの実測降雪量とモデルの `snowfall` は厳密には同一量ではないが、
> その日の**降水量そのもののモデル誤差**が支配的なので、比を取れば大半を吸収できる。

補正基準点はハードコードしない。`map` JSON に `snow` が非nullで載っている地点だけを
候補にして（`elems` の解釈に依存しない）、`距離km + |標高差| ÷ 50` が最小の1点を選ぶ。
60km以内に無ければ補正なし。

### 信頼度

| 条件 | 信頼度 |
|---|---|
| 基準点なし | low |
| 距離 > 40km または 標高差 > 1200m | low |
| 距離 > 25km または 標高差 > 800m | mid |
| それ以外 | high |

**この値は実運用でほとんどが low になる。** 積雪を観測しているアメダスは
ほぼ谷底（150〜700m）にあり、対象地点は 1,500〜2,400m なので、標高差が
1,200m を超えやすいため。距離ではなく標高差で落ちている。

高標高アメダスが近い地点だけが high になる（例: 八甲田は酸ケ湯890mが2.6kmで標高差695m）。
UIには基準点名・距離・標高差をそのまま出しているので、なぜ low なのかは行を読めば分かる。
**しきい値を緩めるかどうかは実データを見てから決めること**（現状は仕様どおりの値）。

### 評価窓

`hourly.time` は `Asia/Tokyo` のローカル文字列。現在の「日付＋時」に一致する index を
`nowIdx` として、

- `past24h` … `(nowIdx − 24, nowIdx]` … 24点
- `next12h` … `(nowIdx, nowIdx + 12]` … 12点（現在時刻を二重に数えない）
- `total = past24h + next12h` ← **ソートキー**

### 風

`next12h` の最大風速と、そのときの風向を持つ。**15 m/s 超で警告**（吹き飛び・
ウインドスラブ生成の目安）。

## 通信

| いつ | 回数 |
|---|---|
| 初回 | 4回（アメダス `latest_time` / 地点表 / `map` ＋ Open-Meteo 1回） |
| 2回目以降（同一セッション） | 3回（地点表は `sessionStorage` から読む） |

**地点数がいくつあっても増えない。** 地点と補正用アメダスの座標をまとめて
1リクエストにしているため（40地点でも4回であることをテストで固定している）。

アメダスが取れなくても補正なし（k=1）で予報だけを表示する。落ちない。

## ★単位に注意

過去に風速の km/h と m/s を取り違えて事故を起こしている。

| 変数 | 単位 |
|---|---|
| Open-Meteo `precipitation` | mm |
| Open-Meteo `snowfall` | cm |
| Open-Meteo `wind_speed_10m` | **既定 km/h** → 必ず `wind_speed_unit=ms` を付ける |
| アメダス `snow` / `snow24h` | cm |

`wind_speed_unit=ms` を忘れると風速が3.6倍になり、15m/s の警告が出っぱなしになる。
テスト（`smoke_snowrank`）がURLにこのパラメータがあることを固定している。
