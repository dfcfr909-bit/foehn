# 予報モデルの切り替え（段階B）要件定義書【案・承認前】

作成日: 2026-09-30 / 状態: **案（D1・D2・D4・D6 は決定済み。D3・D5・D7 と全体の承認は未了。実装に着手しない）** / 承認者: Kato
対象: ナギナビ（`sotoki_v4.html`）。段階A（予報モデルの帯・v4.142.0）の続き。

> ⚠ この文書は**要件の案**。§6 の未決（D3・D5・D7）と全体の承認が入るまで実装しない。
> 承認されたら ADR を切る。

## 1. 背景と目的

- 現状の予報は Open-Meteo の `jma_seamless` **固定**（MSM→GSM の自動切り替えは Open-Meteo 側）。
- 段階A（v4.142.0）で「いまどのモデルか」を帯と窓に出した。
- 利用者の要望（2026-09-30）：**基本は今のまま（JMA）でよい。ただし不確実性が高いときは、モデルを切り替えて見たくなることがある。**
- 目的：不確実性が高いと感じたときに、**別のモデルの予報へ切り替えて**確かめられるようにする。
  「自分がそこにいたときに、予報通りだ！と思えること」が最終的な狙い。

### 対象外（この段階ではやらない）
- 複数モデルの**同時の重ね描き・平均・アンサンブル**（切り替えで足りるうちは持たない。§6 D5）
- ランキング（新雪ランキング・山域ランキング）のモデル切り替え（JMA 固定のまま）
- ABC 評価ロジックの変更（`abcScore` / `abcScoreInv` / `judgePoint` は変更禁止。**入力の風が変わるだけ**）

## 2. 実測：各モデルが実際に何を返すか

2026-09-30、谷川岳（36.8371, 138.9301）、`forecast_days=16`、`wind_speed_unit=ms`、必要な変数を全部要求。
⚠ **1地点・1時点の実測。** 他地点・他時刻で変わりうる。

| モデル | 地上の列 | 突風 | 気圧面の風・高さ | 予報の長さ（最終時刻） | 山頂風を作れるか |
|---|---|---|---|---|---|
| `jma_seamless`（現行） | 揃う | **無い** | 全層（MSM の期間のみ 975/950/900/800 も） | 約11日（10/11 02時） | ○（実績あり） |
| `gfs_seamless` | 揃う | ○ | 全層 | 約15.6日（10/15 23時） | ○ |
| `icon_seamless` / `icon_global` | 揃う | ○ | 全層 | 約7.5日（10/07 21時） | ○ |
| `ecmwf_ifs025` | 揃う | **無い** | 1000/925/850/700/600/500 のみ | 約15日（10/15 11時） | △（層が疎。GSM 期間と同じ状況） |
| `ecmwf_ifs`（9km） | 揃う | 無い | **無い** | 約15日（10/15 09時） | **×（地上10m風に落ちる＝ADR-0006/0011 の失敗）** |
| `ecmwf_aifs025` | **地上の列が全部空** | — | 無い | — | × |
| `gem_seamless` | 揃う | ○ | 950 まで（975 無し） | 約10日（10/10 11時） | ○ |
| `meteofrance_seamless` | 揃う | ○ | 950 まで（975 無し） | 約4日（10/04 15時） | ○（ただし予報が短い） |

- 各モデルの**格子の細かさは未確認**（GFS は約13km、ICON global は約13km、IFS025 は約28km のはずだが、実測していない）。
  MSM（約5km）より粗いモデルでは、山岳の風は過小に出やすい（§7 R6）。
- ⚠ 「最終時刻」は全列の最後の非 null。列ごとに違う可能性があり、**未確認**。

### 現行の複数モデル混在（すでにある）
- **突風・気圧面ごとの雲量は `jma_seamless` が返さない**ため、`models` 未指定（`best_match`）の**補助リクエスト**で取っている
  （`fetchSupplemental`）。つまり**いまも、突風と雲の断面は JMA ではない別モデルの値**。
- 帯（段階A）が言っているのは**本体（`jma_seamless`）の風の判別**。突風・雲断面の出どころは帯に出ていない。
- 地図の風（`fetchWindColumns`）も `jma_seamless` 固定（`windModelPhases` を共有）。

## 3. 現行の構造（影響が出る所）

| 場所 | 中身 | モデル切り替えでの扱い |
|---|---|---|
| `fetchWeather`（`sotoki_v4.html:2981` 付近） | `models=jma_seamless` を URL に直書き | モデル ID を引数に |
| `WIND_LEVELS` / `pickWindSource` / `summitWindAt` | 山頂高度の風。固定表で層を選び、無い時刻は gh で按分 | 層の構成がモデルごとに違う（§2）。**gh 按分を軸にする** |
| `windModelPhases` | 900/800hPa の風が null になる時刻で MSM/移行/GSM を判別 | **JMA 専用**。他モデルには当てはまらない |
| `fetchSupplemental` | 突風・気圧面の雲量を `best_match` で取得 | 突風を返すモデル（GFS・ICON・GEM）では不要になりうる |
| `fetchWindColumns`（地図） | `jma_seamless` 固定、`WindVertical.auto` | 段階B では触るか（§6 D6） |
| オフライン控え（`wxSave` 系） | 地点ごとに JSON を控える | **モデルをキーに含める**（別モデルの控えを出さない） |
| 帯・窓（段階A） | `data[i].model` | 選択モデルの名前を出す。移行の概念は JMA だけ |

## 4. 機能要件（案）

| # | 要件 | 優先 |
|---|---|---|
| R1 | 利用者が**予報モデルを切り替えられる**（UI は §6 D3） | 必須 |
| R2 | 切り替えたら、**チャートの全要素**（気温・降水・雲・風・突風・気圧）が選んだモデルで再描画される | 必須 |
| R3 | **選択中のモデル名を常に画面に出す**（帯と窓）。JMA 以外のときは、JMA の既定に戻す手段が一目で分かる | 必須 |
| R4 | 既定は `jma_seamless`。**起動のたびに既定に戻す**か、覚えるかは §6 D4 | 必須 |
| R5 | ABC 判定は、**表示しているモデルと同じモデルの値**で出す（表示と判定がずれない）。§6 D1 | 必須 |
| R6 | 山頂高度の風は、**モデルごとの気圧面の構成に合わせて gh 按分**で作る。気圧面が使えないモデルは候補から外す（地上10m風に黙って落とさない） | 必須 |
| R7 | 予報が短いモデルは、**足りない先は「データなし」**と言う。他のモデルで埋めない | 必須 |
| R8 | 通信失敗・空の応答は**黙って別のモデルに戻さない**。理由を出す | 必須 |
| R9 | オフライン控えは**モデルごと**。別のモデルの控えを出さない | 必須 |
| R10 | 突風は、モデルが返すならそのモデルの値。返さない（JMA・IFS）なら現行どおり補助リクエスト（`best_match`）で、**出どころを画面で分かるように**する | 必須 |
| R11 | `about.html` に、選べるモデル・それぞれの特徴・妥協点（粗い格子で山岳の風が過小に出る等）を書く | 必須 |
| R12 | 地図の風は**連動しない**（JMA 固定）。地図に「JMA」と明記する（§6 D6 決定） | 必須 |
| R13 | モデル間の**ばらつき**を示す表示（不確実性の可視化） | 対象外（将来） |

## 5. 制約・地雷（守ること）

- **風速は `wind_speed_unit=ms` を必ず指定**（ADR-0005）。モデルを足しても変えない。
- **どの層を使うかを、応答の `elevation` で決めない**（ADR-0011）。
- **山頂の風は気圧面の風を使う**（ADR-0006）。地上10m風に黙って落とさない。
- **ABC 評価の関数は変更禁止。** 変えるのは入力の風・気温・降水などだけ。閾値は `THRESH` だけ。
- Open-Meteo の呼び出し回数：1地点あたり本体1回＋補助1回。モデルを増やす**同時取得はしない**（切り替えたときに1回取り直す）。429 に注意。
- 公開リポジトリ。院内・施設名・個人名を書かない。

## 6. 論点（D1・D2・D4・D6 は 2026-09-30 に利用者が決定。残りは案）

| # | 論点 | 私の推奨 | 理由 |
|---|---|---|---|
| D1 | **ABC 判定も切り替えたモデルで出すか** | **【決定】出す**（表示と判定を必ず同じにする） | ずれると「予報通り」にならない。JMA 以外で判定が変わるので、モデル名は常時表示（R3） |
| D2 | **選べるモデルの範囲** | **【決定】JMA（既定）／GFS／ICON／ECMWF（`ecmwf_ifs025`）** | `ecmwf_ifs` は気圧面が無く山頂風を作れない。`aifs025` は地上の列が空。GEM は10日・MF は4日で短く、当面は外す |
| D3 | **切り替えの UI**（未決） | 帯（段階Aの予報モデルの帯）を**タップ**して選ぶ | すでに「いまのモデル」が出ている場所。設定画面に隠さない |
| D4 | **覚えるか、起動で JMA に戻すか** | **【決定】起動で JMA に戻す** | 「時々見たくなる」用途。別モデルの判定を、気づかず使い続けるのを防ぐ |
| D5 | **モデルの同時重ね描き・比較表示**（未決） | **この段階では持たない** | 切り替えで足りるかを先に見る。必要になれば別の要件で |
| D6 | **地図の風もモデルに連動するか** | **【決定】連動しない（JMA 固定）。地図に「JMA」と明記** | 地図は別系統（`fetchWindColumns`・場の解析）で、変更が大きい。チャートだけ先に出す |
| D7 | 分解能・精度の検証（未決） | 出す前に、**アメダス等の実測と比べて**過小・過大を測る | 切り替えて「予報通り」に近づく保証は無い。JMA GSM 相当の検証では、粗いモデルは強風時に過小だった |

## 7. リスク・未確認

- R6 の精度：GFS・ICON・IFS025 の山頂風が、JMA（MSM/GSM）より当たるかは**未検証**。
  先の調査（GSM 相当の層だけで按分）で、粗い層構成は強風時に過小に出た。同じことが起きる可能性がある。
- 山岳ではどのモデルも格子が粗い。**モデルを変えても、山頂の風の過小は消えない**可能性が高い。
- ICON は約7.5日、IFS025 は層が疎で 2 系統ある（`ecmwf_ifs025` と `ecmwf_ifs`）。名前と中身が変わりうる（Open-Meteo 側の仕様変更）。
- 気温・降水・雲が、風と同じ時刻でモデルが切り替わるか（JMA）は未確認（段階A の積み残し）。
- 実測は1地点。他の山域で、各モデルの列の有無・長さが同じかは未確認。

## 8. 受け入れ基準（案）

1. 既定（JMA）の表示と判定が、段階Aと**完全に同じ**（回帰が無い）。`smoke_*` が全件通る。
2. 帯をタップしてモデルを切り替えると、チャート全体が選んだモデルで再描画され、帯と窓の名前が変わる。
3. 気圧面が使えないモデルは選べない（一覧に出さない）。
4. 予報が短いモデルは、足りない先が「データなし」（他モデルで埋めない）。
5. 通信失敗・空の応答で、黙って JMA に戻らない。理由が出る。
6. オフライン控えがモデルごとに分かれる。
7. `about.html` に選べるモデルと妥協点が書いてある。`tests/smoke_about.mjs` が通る。
8. 実機で、JMA と別モデルを切り替え、山頂の風と判定が変わること（または変わらないこと）を確認する。
