# 要件定義書（案）: 風の強さの細分化レイヤー（WindNinja の表を端末で読む）

**状態: 案（2026-10-16）。利用者の承認待ち。**

## 背景

- 「尾根と沢の細かい地形で風の流れを細かく見たい」（利用者・2026-10-15）
- 調査は `experiments/windninja/README.md`（findings-01〜04）。決まったこと：
  - WindNinja の**質量保存の解法**で、山域ごとに 8方位の「倍率と向きの曲がり」の表を Actions で前もって作る（升目 60m・一辺 32km）
  - 予報の風との合わせ方は **案A（山頂基準）**：その地点の風 ＝ 判定の風 × 倍率(地点) ÷ 倍率(選択地点)
  - ⚠ この解法は**風下の陰を出さない**（風を逆向きにしても倍率が同じ）。陰は v4.177.0 の「風の当たり方」で見る（利用者の決定 A）
  - 運動量の解法（OpenFOAM）は急な山で発散して使えなかった（findings-04）

## 何を出すか

- 地図の気象の区分に「風の強さ（地形）」を足す。**選択地点・選択時刻の判定の風**（`state.allData[i]` の `wind`・`wdir`）を、表の倍率で地図の各点へ配る
  - 色＝推定の風速（m/s）。色の段は「風の流れ」の背景（`WIND_FLOW.COLORS`）と同じにする（同じ m/s が同じ色）
  - 向きは表の曲がりを足した向き（矢印の有無は決めること #1）
- 風向は判定の風の向き。8方位の表のうち、挟む2方位を角度で按分（findings-02：45° 離れていても差は中央 0.04）
- 押すと札：その点の推定の風速・倍率（選択地点に対して）・使った風・表の出どころ
- **選択地点が表の範囲の外**なら塗らない（基準が取れない）。凡例に「この地点は表の範囲外」
- **表の無い山域**では出さない（行に「この山域の表はまだ無い」）

### 画面と about に必ず書くこと

- 「**推定**。風下の斜面は強めに出る（風上と同じ倍率になる計算）。陰は『風の当たり方』で見る」
- 「選択地点で判定の風と一致するように合わせた値。谷・樹林の中は強めの見込み」
- 判定（A/B/C）・グラフ・矢印には使わない

## 作り方

- 表：`data/wind/<山域id>.png`（8方位を縦に積む・R＝倍率×64・G＝曲がり×127/180＋128）＋`.json`（範囲・升目・峰の倍率）。
  Actions（`windninja.yml`）で作り、PR で入れる
- 端末：レイヤーを入れたときに選択地点の山域の表を取りに行く（PNG を `createImageBitmap` で読み、Worker で R・G を取り出す）。
  一度取った表は端末に控える（決めること #3）
- 描き方：CS立体図風と同じ GridLayer（タイルごとに、表を双線形で引いて色を塗る）。時刻・地点が変わったら描き直す（表は取り直さない）

## 決めてほしいこと

| # | 項目 | 案（推奨を先に） | 理由 |
|---|---|---|---|
| 1 | 見せ方 | **色だけ**／色＋向きの矢印（約 300m おき）／「風の流れ」の粒子に組み込む | 色だけが最も軽く誤読しにくい。粒子への組み込みは粒子の補正（遮蔽・コル）と二重になるので後で |
| 2 | 表を作る山域 | **谷川だけで試し、実機で良ければお気に入りの山域から足す**／最初から 51山域 | 1山域 約 2 MB。51山域で約 100 MB を Pages と git の履歴に置くことになる |
| 3 | 端末への控え方 | **一度取ったら控える（地図タイルと同じ上限の中）**／お気に入りの山域は前もって取る | 前もって取るのは段2「お気に入りごとの DEM 保存」と一緒に作る方が筋がよい |

## 触れること・触れないこと

- 触れない：ABC評価・`areas.json`・判定の風の作り方・粒子の補正
- ⚠ 端末の控えに `sw.js` のタイルキャッシュを使うなら `sw.js` に触れる（確認が要る区分）。使わずに Cache API を本体から直接使う案もある（決めること #3 と一緒に計画で決める）
- 新しい送信先：無し（表は自分の Pages から取る）
- 出典：「地理院タイル（標高タイル）を加工して作成」「WindNinja（米国農務省林野局）で計算」

## 検査
