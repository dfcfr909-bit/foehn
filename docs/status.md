### 利用者への未回答の問い（2026-09-13）

⚠ 「4.98.0なんだけど、自動で更新とかしてもらえない？」が**タグのことか PWA の自動更新のことか
確認できていない**（利用者は「90.0でしたね。」と版数を訂正しただけ）。タグとして実装した。

**PWA の自動更新はもともと効いている**——`sw.js` は HTML を**ネットワーク優先**で取り、
Service Worker も `skipWaiting` + `clients.claim`。圏内で開き直せば必ず最新になる。
古い版が残りうるのは GitHub Pages のキャッシュ（`max-age=600`）と、開きっぱなしの間だけ。
⚠⚠ **その症状が実際に出た（2026-09-25）。** 「リポジトリから開いてるんだが版が上がらない」。
`公開URLの検証` の `deliver`（配信物の sha256 照合）は緑なので、**server 側は正しい**。
残る疑いは**端末側のキャッシュ**で、`sw.js` の「ネットワーク優先」が
`fetch(req)` のままなこと——これはブラウザのHTTPキャッシュを**通る**ので、
GitHub Pages の `max-age` のあいだ古いものが返りうる。
- 直し方の案: HTML の取得を `fetch(req, { cache: 'reload' })` にする（HTTPキャッシュを跨ぐ）
- ⚠ **未着手。`sw.js` は「必ず確認」の対象**なので、手を付ける前に利用者に確認すること
- ⚠ 確かめずに直さない。まず実機で**再読み込み（キャッシュを捨てる）だと上がるのか**を見る。
  上がるならキャッシュで確定、上がらないなら別の原因

### ⚠⚠ 宿題: 暑い側の判定が無い（熱中症の警告を出していない）

**2026-09-10 に利用者が気づいた**——「夏はむしろ暑いのが問題になるのに
熱中症アラートを作ってませんでしたね」。いまの判定（`abcScoreInv`）は**寒い側だけ**を見る。

調べた基準（環境省・日本生気象学会）:

| 区分 | 暑さ指数 WBGT |
|---|---|
| 熱中症**特別**警戒アラート | 35以上（都道府県内の全地点で予測） |
| 熱中症警戒アラート | **33以上**（府県予報区内のいずれかの地点で予測） |
| 危険 | 31以上 |
| 厳重警戒 | 28〜31（2025年6月から職場の環境管理義務ライン） |
| 警戒 | 25〜28 / 注意 21〜25 / ほぼ安全 21未満 |

⚠⚠ **WBGT は気温ではない。** 湿球温度が7割を占め、湿度・輻射熱を織り込む。
**Open-Meteo の `apparent_temperature` とも別物**で、公式の換算は無い
（日射込みで気温よりかなり高く出る。実機で気温25℃→体感31℃）。
目安は湿度60%で 気温31℃ ≒ WBGT 28、気温35℃ ≒ WBGT 32。
暑さ指数の式で当てると厳重警戒が体感35℃前後、危険が体感45℃前後——
**帯の暑い側の数値はこの線で置いた暫定値**。

やるなら2段階。**どちらも未着手・未承認。**

1. **WBGT を計算して持つ。** Open-Meteo は湿度・日射を返すので近似できる。
   ⚠ 体感温度で代用しない（別物）
2. **判定に暑い側を足す。** ⚠⚠ `THRESH` に暑い側の閾値が無いので、
   **`abcScoreInv` を足すだけでは済まない可能性がある**——ABC評価ロジックは変更禁止
   （`CLAUDE.md`）。着手前に必ず確認すること

⚠ 山の上は平地より涼しいが、**低山の夏や樹林帯では効く**。無視してよい話ではない。

> docs/status.md を読んだうえで、**暑い側の判定（熱中症）をどうするか**から進めて。
> ⚠ WBGT は体感温度とは別物。⚠ ABC評価ロジックに触れるので着手前に確認すること。
> `origin/main` から新しいブランチを切ること。

⚠ **案2（ポップアップをタップ時だけ出す）は保留のまま。** 窓は PR #60 で

⚠ **実機で至仏山も見てもらうこと（#16）。** ADR-0011 で判定に使う風が変わった。
