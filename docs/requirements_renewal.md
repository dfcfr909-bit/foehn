# SotoKi 全面改修 要件定義書

作成日: 2026-07-21 / 承認者: Kato
対象: SotoKi（バックカントリー気象PWA / Netlify / Open-Meteo JMAモデル / Leaflet）

## 背景・不満点

1. スクロールがカクつき滑らかでない
2. 昼夜の時間帯の移行が視覚的にわかりにくい
3. 全体的に表示が見にくい

## 確定事項

| 項目 | 決定 |
|---|---|
| チャートライブラリ | uPlot へ移行 |
| 配色テーマ | OS設定に自動追従（prefers-color-scheme） |
| 改修範囲 | 地図含む全画面 |
| データ源 | Open-Meteo JMAモデル（現行維持） |
| ABC評価ロジック | 現行維持（移植のみ、変更禁止） |
| デプロイ | Netlify（現行維持） |

## 機能要件

### 1. 過去48時間表示の統合

- 既存fetchに `past_days=2` を追加（追加リクエストなし）
- 時間軸: -48h 〜 +96h の連続表示
- `hourly.time` を現在時刻で分割し、過去/予報のインデックス境界を算出
- 現在時刻に縦線（実線）、過去域は背景を薄グレー等で区別
- 初期スクロール位置は現在時刻付近（過去域で画面が始まらないこと）
- ABC評価は予報域のみ対象（過去域は評価対象外）
- 注記に「過去データはJMAモデル解析値であり実測ではない」旨を追記

### 2. スクロール性能改善

- チャートは初回1回のみ描画。スクロールはCSSネイティブ
  （overflow-x + 描画済みcanvas）。JSでのスクロール追従処理は全廃
- scroll/touchリスナーは `passive: true`
- box-shadow / blur 等のGPU負荷装飾を廃止、will-changeは最小限
- 高DPI対応（devicePixelRatioに応じたcanvas解像度、ただし過剰解像度禁止）
- 目標: iPhone実機で60fpsスクロール

### 3. 昼夜の視覚区別

- Open-Meteo `daily=sunrise,sunset` を取得
- チャート背景に夜間帯シェーディング（日没〜日出）を uPlot draw hook で描画
- 日付境界に薄い区切り線
- ライト/ダーク両テーマでシェーディングの視認性を確保

### 4. 視認性の再設計

- 情報階層: ABC評価を最上位 → 概況 → 数値詳細の順
- 数値は等幅タブラー数字、ラベルは小サイズ・低彩度
- コントラストWCAG AA目安（両テーマで検証）
- 屋外・グローブ操作前提: タップ領域44px以上
- ライト/ダークはCSSカスタムプロパティで一元管理

### 5. 地図の気象表示（新規）

- 雨雲レーダータイル重畳: 気象庁ナウキャストタイル
  - 過去1h→予測1hのアニメ再生、レイヤーON/OFF切替
- 格子点マーカー: 選択地点周辺の風向矢印・気温・降水を表示
  - Open-Meteoの複数地点一括取得を使用
  - ズームレベルに応じて格子点を間引き
- 地図タイル・UI配色をテーマに合わせて刷新（Leaflet自体は維持）

## 対象外（本改修でやらない）

- 風パーティクルアニメ（leaflet-velocity）→ 別issueとして将来枠
- 実測値（アメダス）との照合
- 48h超の過去データ
- ABC評価ロジックの変更
- Open-Meteo以外への移行

## 実装順序（推奨）

1. uPlot移行 + スクロール性能改善（コア）
2. 過去48h統合 + 現在時刻線
3. 昼夜シェーディング
4. テーマ自動追従 + 視認性再設計
5. 地図: 雨雲タイル → 格子点マーカー

各段階で実機（iPhone Safari）検証後に次へ進む。

## 検証項目

- [ ] スクロール60fps（実機）
- [ ] 過去/予報境界と現在時刻線の位置が正しい
- [ ] 夜間帯シェーディングが日出没時刻と一致
- [ ] ライト/ダーク切替で全要素のコントラスト確保
- [ ] 雨雲タイルのアニメ再生・切替動作
- [ ] PWAオフライン動作・初回ロードサイズが現行比で悪化しないこと
- [ ] ABC評価の出力が改修前後で一致（回帰確認）
