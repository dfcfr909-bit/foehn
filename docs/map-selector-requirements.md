# SotoKi 地図選択画面 要件定義書

作成日: 2026-07-31
対象: 地図選択画面（レイヤー切替・標高取得・タイルキャッシュ）

> **メモ（実装時に判明）**: 本文冒頭に「§13 の運用ルールを必ず読むこと」とあるが、
> 本文書は §12 で終わっており §13 は存在しない。§2 の制約条件のみを前提に実装した。
> 実装状況と積み残しは末尾の「§14 実装メモ」を参照。

---

## 1. 目的とスコープ

### 1.1 目的
バックカントリーでの地形判読を支援するため、地図選択画面に複数のベースマップと地形オーバーレイを追加する。あわせて選択状態の永続化と、訪問済みタイルの自動キャッシュを実装する。

### 1.2 スコープ内
- ベースマップの切替（5種）
- 地形・情報オーバーレイの重ね合わせ（6種、透過率調整可）
- 赤色立体図風の合成表示
- 選択地点の標高自動取得
- Service Worker によるタイル自動キャッシュ
- 選択状態の localStorage 永続化

### 1.3 スコープ外（別フェーズ）
- MapLibre GL への移行
- 標高タイル演算による赤色立体図・CS立体図の本実装
- 範囲指定によるタイル事前ダウンロード
- ABC判定ロジックの変更

## 2. 制約条件

| 項目 | 内容 |
|---|---|

## 3. ベースマップ仕様

排他選択（常に1つのみ有効）。

| ID | 名称 | タイルURL | ズーム | 出典表記 |
|---|---|---|---|---|
| `std` | 標準地図 | `https://cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png` | 5–18 | 国土地理院 |
| `pale` | 淡色地図 | `https://cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png` | 5–18 | 国土地理院 |
| `photo` | 航空写真 | `https://cyberjapandata.gsi.go.jp/xyz/seamlessphoto/{z}/{x}/{y}.jpg` | 2–18 | 国土地理院 |
| `osm` | OpenStreetMap | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` | 0–19 | © OpenStreetMap contributors |
| `esri` | 衛星画像 | `https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}` | 0–19 | Esri, Maxar, Earthstar Geographics |

**注記**
- 既定値は `pale`。オーバーレイの下地として最も視認性が高い。
- Esri はURLのタイル座標順が `{z}/{y}/{x}` である点に注意。
- OSM はタイル利用ポリシー上、大量の先読み取得が禁止されている。本件は訪問済みキャッシュのみのため適合するが、事前ダウンロード機能を将来追加する場合は OSM を対象外とすること。

## 4. オーバーレイ仕様

複数同時有効可。各レイヤーに透過率スライダー（0–100%）を持つ。

| ID | 名称 | タイルURL | ズーム | 既定透過率 | 用途 |
|---|---|---|---|---|---|
| `slope` | 傾斜量図 | `https://cyberjapandata.gsi.go.jp/xyz/slopemap/{z}/{x}/{y}.png` | 3–15 | 50% | 斜度判断 |
| `hillshade` | 陰影起伏図 | `https://cyberjapandata.gsi.go.jp/xyz/hillshademap/{z}/{x}/{y}.png` | 2–16 | 50% | 立体感・谷筋把握 |
| `rrimLike` | 赤色立体図風 | 合成（§5参照） | 3–15 | 70% | 微地形判読 |
| `relief` | 色別標高図 | `https://cyberjapandata.gsi.go.jp/xyz/relief/{z}/{x}/{y}.png` | 5–15 | 40% | 標高帯の把握 |
| `gazo1`–`gazo4` | 過去空中写真 | `https://cyberjapandata.gsi.go.jp/xyz/gazo1/{z}/{x}/{y}.jpg` 他 | 地域差あり | 100% | 林相・地形変化 |
| `volcano` | 火山土地条件図 | **実装前に要確認** | 火山域限定 | 60% | 那須・燧・火打 |
| `csmap` | CS立体図 | `https://map.ecoris.info/tiles/csmap/{z}/{x}/{y}.png`（**第三者配信・未確認**） | 4–17 | 75% | 谷筋・微地形の判読。**v4.63.1で保留（`pending`）**、§25 |

### 4.1 ズーム範囲外の扱い
- 各レイヤーに `maxNativeZoom` / `minNativeZoom` を設定する。
- ネイティブ範囲を超えた場合はオーバーズーム表示とし、レイヤーが空白にならないこと。
- 特に傾斜量図は z15 が上限のため、`maxNativeZoom: 15, maxZoom: 18` を必須とする。

### 4.2 排他制御
- `rrimLike` を有効化した場合、`slope` と `hillshade` の単独トグルは自動的に無効化する（二重描画防止）。

## 5. 赤色立体図風 合成仕様

### 5.1 方式
陰影起伏図を下地、傾斜量図を上に `mix-blend-mode: multiply` で重ねる。傾斜量図の赤系彩度と陰影の明暗が乗算され、赤色立体図に近い見え方になる。

### 5.2 実装方針
- Leaflet の専用 pane を作成し、そこに2枚の TileLayer を配置する。
- pane に対して CSS で `mix-blend-mode` を適用する（個別タイル画像ではなく pane 単位）。
- 合成レイヤー全体の不透明度は pane の `opacity` で制御する。
- 有効ズームは傾斜量図に合わせ 3–15（超過分はオーバーズーム）。

### 5.3 留意点
- `mix-blend-mode` は iOS Safari で描画が重くなる場合があるため、実機でスクロール性能を確認する。
- 期待どおりの発色にならない場合は、`multiply` の代わりに `overlay` や、傾斜量図側に CSS フィルタ（`saturate` / `hue-rotate`）を併用して調整する。

## 6. 選択地点の標高自動取得

### 6.1 データソース
国土地理院 標高タイル（PNG形式）
`https://cyberjapandata.gsi.go.jp/xyz/dem_png/{z}/{x}/{y}.png`

### 6.2 処理フロー
1. 選択地点の緯度経度からタイル座標とタイル内画素座標を算出
2. 該当タイルPNGを取得（`crossOrigin = 'anonymous'`）
3. Canvas に描画して該当画素の RGB を取得
4. 標高に換算する
   - `x = R * 65536 + G * 256 + B`
   - `x < 2^23` のとき `標高 = x * 0.01`（m）
   - `x = 2^23` のとき 無効値（NA）
   - `x > 2^23` のとき `標高 = (x - 2^24) * 0.01`（m）

### 6.3 要件
- 取得した標高は地点データとともに保存し、同一地点で再取得しない。
- 取得失敗・無効値の場合は標高欄を非表示にし、地図機能全体は停止しない。
- 取得は非同期で行い、地図描画をブロックしない。
- 負荷は1地点あたりPNG1枚（数KB）であり、既存の地点数であれば無視できる。

## 7. キャッシュ要件

### 7.1 方針
Service Worker による訪問済みタイルの自動キャッシュのみ。事前ダウンロードは実装しない。

### 7.2 詳細
| 項目 | 仕様 |
|---|---|
| キャッシュ名 | `sotoki-tiles-v1`（アプリシェルとは分離） |
| 戦略 | cache-first。ヒット時は即返却し、バックグラウンドで更新しない |
| 対象 | 本要件で定義したタイルドメインのみ |
| 容量上限 | 150MB |
| 削除方式 | 上限超過時に LRU（最終アクセス時刻を IndexedDB で管理） |
| 使用量表示 | `navigator.storage.estimate()` で設定画面に表示 |
| 手動削除 | 設定画面に「タイルキャッシュを削除」ボタンを設置 |

### 7.3 留意点
- iOS の PWA はストレージ上限が厳しく、OS側で削除される可能性がある。上限値は実機計測後に調整する。
- キャッシュ削除は破壊的操作のため、実行前に確認ダイアログを表示する。

## 8. UI要件

### 8.1 レイヤーパネル
- ボトムシート形式。地図画面からボタン1つで開閉。
- 上段: ベースマップ（ラジオ選択、サムネイル付き）
- 下段: オーバーレイ（トグル + 透過スライダー）
- タッチターゲットは全て 44px 以上
- スライダーはドラッグ中もリアルタイムに地図へ反映

### 8.2 出典表記
- 地図右下に常時表示。
- 有効なベースマップとオーバーレイに応じて動的に更新する。
- 地理院タイル・OSM・Esri いずれも出典表示が利用条件であるため、非表示・省略は不可。

### 8.3 テーマ・アクセシビリティ
- `prefers-color-scheme` による light / dark 切替
- WCAG AA コントラスト比を満たす
- パネル内のフォーカス順序が論理的であること

## 14. 実装メモ（v4.46.0 時点）

### 14.1 §11 の要確認事項の扱い

開発環境から `cyberjapandata.gsi.go.jp` などの外部ホストに到達できないため
（プロキシが CONNECT に403）、4項目とも**未確認のまま**である。
推測でURLを埋めることはしていない。実機で確認して埋めること。

| # | 項目 | 実装での扱い |
|---|---|---|
| 1 | 火山土地条件図のタイルID | `MAP_OVERLAYS` に `pending: true` で定義してある。**pendingのレイヤーはUIに出ない**ので、URLとズーム範囲を埋めて `pending` を消せば그대로出る |
| 2 | 過去空中写真のカバー範囲 | `gazo1`〜`gazo4` を定義済み。範囲外は空タイルになるだけで壊れない。UIに「地域により配信なし」と注記を出している |
| 3 | Esri の attribution 文言 | §3 の表にある `Esri, Maxar, Earthstar Geographics` をそのまま使用。正式表記が違えば `MAP_BASES` の `attribution` を直すだけ |
| 4 | iOS のストレージ実測値 | 上限は `TILE_CACHE_LIMIT_BYTES`（sw.js）の1定数。実測後に変更する |

### 14.2 仕様と実装が違う点

- **「設定画面」が存在しない。** 本アプリに設定画面が無いため、キャッシュ使用量の表示と
  削除ボタンは**レイヤーパネルの最下段**に置いた。設定画面を作るならそちらへ移すこと。
- **light/dark 切替はレイヤーパネルと地図画面のみ。** アプリ本体は light 固定の配色で、
  全体のダークテーマ化は本要件の範囲を超える。地図画面は全画面オーバーレイなので、
  ここだけダーク対応しても本体と並んで見えることはない。
- **地図の最大ズームは18。** OSM と Esri は z19 まで配信しているが、地理院のオーバーレイに
  合わせて18で止めている（z19 にすると傾斜量図などの引き伸ばしが4倍になり粗くなるため）。

### 14.3 標高の扱い（既存の値と混ぜないこと）

- `state.elevation` … **Open-Meteo が返すモデル格子の標高**。従来どおり
  `fetchSupplemental` に渡して地形条件を揃えるのに使う。**変更していない**
- `state.demElevation` … 標高タイルから読んだ**実際の地点標高**。表示用
- 表示は `displayElevation()` が DEM を優先し、無ければモデル標高に落ちる

ABC判定は本体の気象データだけで決まり、どちらの標高にも依存しない。

## 15. 気象レイヤー（v4.47.0 で追加）

利用者の依頼で「アメダス・降雨レーダー・雷・風を重ねたい」を追加した。
**§2 の「気象データは Open-Meteo のみ」を緩めている**（降雨レーダー等は Open-Meteo に
配信が無いため気象庁を使う）。定義は `MAP_WEATHER`。

| ID | 名称 | 方式 | 出所 | 状態 |
|---|---|---|---|---|
| `radar` | 降雨レーダー | 時刻つきタイル | 気象庁 高解像度降水ナウキャスト | **実機で表示確認済み**（v4.48.0） |
| `thunder` | 雷 | 時刻つきタイル | 気象庁 雷ナウキャスト | **実機で表示確認済み**（v4.61.0）。雷マークとぼかしを重ねている（§24） |
| `amedas` | アメダス | 点（マーカー） | 気象庁アメダス | **実機で表示確認済み**（v4.48.0） |
| `windArrows` | 風向風速 | 点（マーカー） | Open-Meteo | 実装済み |

### 15.1 Windyのようなアニメーション風速は実装していない

§2 の禁止ライブラリ `leaflet-velocity` がまさにその用途のため。代わりに
**画面を5×5に割った代表点の風を Open-Meteo から1リクエストで取り、矢印で置く**方式にした。
アニメーションはしないが、風向と強さは読める。15m/s超は赤（チャート側と同じしきい値）。

矢印の向きは `風向 + 180°`。風向は「吹いてくる方角」なので、進む向きは逆になる。
**`wind_speed_unit=ms` を付けている**（既定km/h。ここでも同じ罠）。

### 15.2 targetTimes は種別ごとに別ファイル

**降水は `targetTimes_N1.json`、雷・竜巻は `targetTimes_N2.json`。**
実機で降水（N1 + `hrpns`）は表示できたが雷（N1 + `thns`）は取得できなかったため、
雷だけ N2 を見に行くようにした（v4.48.0）。**雷はまだ実機未確認。**

レイヤー定義の `timesFile` で切り替える。時刻表は種別ごとにキャッシュする。

### 15.2.1 雷が出ない件（v4.50.0時点）

実機では雷だけタイルが404。**時刻表(N2)の取得は成功している**（失敗していれば
エラー文言に `（HTTP xxx）` が付くが、付いていなかった）ので、残るのはタイルのパスか
ズーム範囲。雷ナウキャストは降水より粗いメッシュと見て `maxNativeZoom` を 10→8 に下げた。

**雷が観測されていない時間帯はタイル自体が無い**可能性もある。区別できないので、
`mayBeEmpty: true` の付いたレイヤーは「取得できません」ではなく
「この範囲に表示なし」と出す。あわせて**失敗したタイルのズーム**を文言に入れてあるので、
まだ出ない場合はその数字で切り分けられる。

### 15.3 ナウキャストのURL

`targetTimes_N1.json` から `basetime` / `validtime` を引いて

```
https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/{element}/{z}/{x}/{y}.png
```

を組み立てている。開発環境から到達できず**URLの形を確認できていない**ため、
`unverified: true` を付けてパネルに「要確認」バッジを出している。
火山土地条件図と違って候補URLがあるので、隠さず出して実機で試せるようにした。

**タイルが1枚も取れなければパネルに「取得できません」と出る**（`tileerror` を数えている）。
黙って空にならないので、URLが違えばすぐ分かる。

### 15.4 気象レイヤーはキャッシュしない

`www.jma.go.jp` を `TILE_HOSTS` に入れていない。レーダーや雷は時間で中身が変わるので、
古いタイルを返すと嘘になる。**ここにホストを足さないこと。**

### 15.5 点で描くレイヤーの間引き

アメダスは全国1,300地点あるので、`z8` 未満では出さず、表示範囲内かつ最大140地点までに絞る。
風は `z7` 未満で出さない。出さないときは理由をパネルに表示する（黙って消えない）。
**UIの文言に「z8」などのズームレベルを出さない。** 利用者に「z7とは？風速？」と
聞かれたので、「もう少し拡大すると表示されます」という言い方に変えた（v4.48.0）。
**選んだ要素を観測していない地点はピンを出さない。**「—」だけのピンが散らかるため。

### 15.6 アメダスは表示する要素を選べる（v4.49.0）

気温／風／降水／積雪／湿度（`AMEDAS_ELEMENTS`）。パネルでアメダスを有効にすると
チップが出る。選択は `sotoki.map.amedasElement` に保存する。
地点ごとに観測項目が違うので、選んだ要素を持たない地点は出ない
（例：雨量計だけの地点は「降水」でしか出ない）。

風のときはピンに向きの矢印も付ける。**アメダスの風向は16方位のindex**で来る
（0=静穏, 1=北北東 … 16=北）。度に直すと `index × 22.5`。
**実機で確認済み（v4.50.0）。** 気象庁の宇都宮「東南東 2.9m/s」に対して矢印が
西北西を向いた（風向は吹いてくる方角なので、矢印は +180° 側へ進める）。
なお速度が気象庁の表と一致しないのは、表が1時間値・マップJSONが10分値のため。
地図を動かすたびに `moveend` / `zoomend` で描き直す。

## 16. 操作まわりの変更（v4.51.0）

利用者からの指摘: 「地図で地点を選ぶと、その地点に飛んでさらに最初の画面に戻ってしまうのが
非常にウザい」「地図画面にも現在地ボタンとお気に入りのロータリーダイヤルが欲しい」
「ダイアルの場所に飛ぶ際は一瞬でジャンプではなくスムーズに移動してほしい」。

### 16.1 地点を選んでも地図は閉じない

タップ／検索／円柱のいずれで選んでも `closeMap()` を呼ばない。
`fetchWeather` は裏で走るので、✕で閉じたときには最新のメテオグラムが出ている。
今どこを選んでいるかは左下のバッジ（地点名＋標高）に出す。

**地図を開いている間は全画面の読込オーバーレイを出さない。**
タップのたびに地図が覆われて操作できなくなるため、`showLoading()` が `isMapOpen()` を
見て抑止し、代わりにバッジへ状態を出す。

### 16.2 現在地ボタンとお気に入り円柱を地図の下へ

`#map-bottom` に「現在地」ボタンと `#map-fav-slot` を置いた。

**円柱のDOMは1つだけ。** 地図を開いている間だけスロットへ引っ越し、閉じたら
ヘッダーへ戻す（`moveFavRotaryTo` / `restoreFavRotary`）。
**2つ作らないこと**——寸法計算（`layoutFavRotary`）と選択確定のロジックが二重になり、
必ず食い違う。幅が変わるぶんの再計算は `#fav-rotary` のResizeObserverが拾う。

「現在地」は `fetchGPS({ keepMap: true })` を呼ぶ。地図を閉じずに現在地へ寄る。

### 16.3 移動はなめらかに

`mapFlyTo()` が `flyTo(..., { duration: 0.8 })` を使う。**`setView` の瞬間移動は使わない。**
どこからどこへ動いたのかが分かるようにするため。

## 17. 地図操作の追加（v4.53.0）

### 17.1 ダブルタップ＋上下ドラッグで拡大縮小

Googleマップと同じ片手操作。Leafletに無い操作なので `bindDoubleTapZoom()` で自前実装した。

- 2回目のタップを**押したまま**上下に動かすと連続的にズーム（`DTAP_PX_PER_ZOOM`=90pxで1段）
- ほとんど動かさずに離したら、ふつうのダブルタップとして1段拡大（着地は整数ズーム）
- **追跡中は自分の位置**、そうでなければ**タップした地点**を基準に拡大縮小する
- なめらかにするため地図は **`zoomSnap: 0`**（小数ズームを許す）
- Leaflet標準の `doubleClickZoom` は**切ってある**（自前の操作と取り合いになるため）

#### なめらかに動かすための肝（v4.54.0）

初版は「毎フレーム `setZoom`」で作ったところ、実機でガクガクだった。原因は2つ。

1. **`setZoom` はそのつどタイルを組み直す**ので指の動きに追いつかない。
   ピンチズームと同じ `map._move(anchor, zoom, {pinch: true, round: false})` で
   **変形だけ**動かし、指を離したときに `_animateZoom()` で一度だけ確定させる。
   更新は `requestAnimFrame` で1フレーム1回に間引く
2. **Leafletのパンと取り合っていた。** 同じ指の動きでパンとズームが同時に走り、
   引っぱり合って震えていた。イベントを**地図の親要素でキャプチャ**して
   `stopPropagation()` し、Leafletのハンドラへ渡さないようにした。
   （同じ要素にあとから足しても、Leafletのハンドラのほうが先に動くので効かない）

Leafletの内部関数（`_move` / `_moveStart` / `_animateZoom` / `_limitZoom`）を使っている。
**Leafletのメジャーバージョンを上げるときはここを確認すること。**

### 17.2 現在地のまわりだけ雨雲を抜く

雨のエリアに入ると自位置が雨雲に埋もれて分からなくなる、という指摘への対応。
`mapNowcast` pane に radial-gradient のマスクを掛け、現在地の周囲だけ雨雲を透明にする。

- `SPOT_CLEAR_PX` までは完全に抜け、`SPOT_FADE_PX` で元の濃さに戻る（§22 で縮小）
- ⚠**マスクを pane に直接掛けてはいけない**（§20 参照。v4.57.0で修正）
- **ナウキャストとマーカーは pane を分けること。** マスクはpane単位なので、同じpaneに
  入れると**現在地マーカーごと消える**。そのために `mapNowcast`(380) と
  `mapWeather`(400) を分けてある
- マスクは `move`/`zoom` と現在地の更新のたびに貼り直すが、**rAFで1フレーム1回に間引く**。
  `mask` はpane全体を描き直させるので、毎フレーム貼るとズームがカクつく
- 追跡を止めたら外す

### 17.3 宿題（§22 で解決）

- ~~**フワッと抜ける範囲の調整**（`SPOT_CLEAR_PX` / `SPOT_FADE_PX`）は、実際に雨が
  降っているときに実機で見て決める~~ → v4.59.0 で縮小した（§22）

## 18. リアルタイム表示（v4.55.0）

「地図画面で雲とか雨の様子とかをリアルタイムでレイヤリングできたりする？」への対応。
足りていなかったのは**雲そのもの**と**自動更新**の2つ。

### 18.1 衛星の雲（ひまわり）

**レーダーは降っている所しか映らない。** 「曇っているが降っていない」を見るには
別の配信が要るので、ひまわりの雲画像を `satellite` レイヤーとして足した。

```
https://www.jma.go.jp/bosai/himawari/data/satimg/{basetime}/jp/{validtime}/{band}/{prod}/{z}/{x}/{y}.jpg
```

- 時刻表は `targetTimes_jp.json`（ナウキャストとは別ファイル）
- バンドは3つ。パネルのチップで切り替え、`sotoki.map.satBand` に保存する
  | id | 表示 | band/prod | 用途 |
  |---|---|---|---|
  | `REP` | カラー | `REP`/`ETC` | 見たままの雲（既定） |
  | `B13` | 赤外 | `B13`/`TBB` | 夜も見える・雲頂高度が分かる |
  | `SND` | 雲頂 | `SND`/`ETC` | 雲頂強調 |
- ズームは `3〜6`。衛星画像は地形図ほど細かくないのでネイティブ上限が低い
- **実機で表示確認済み（v4.68.0）**。取れなければナウキャストと同じくパネルに理由が出る
- ⚠⚠**ひまわりのタイルはJPEGで透明部分が無い。** 濃度を上げると雲の無い所まで
  真っ黒に塗り潰れて地図が消える（実機で踏んだ）。def に `blend: 'screen'` を付け、
  **暗い所ほど下の地図が透ける**合成にしてある（v4.68.0）
- ⚠⚠**合成の前に黒レベルを切り捨てる**（def の `floor: 1.5` → `filter: contrast(1.5)`。v4.68.1）。
  タイルごとに暗部の水準がわずかに違うため、切り捨てないと**その差がタイルの継ぎ目
  ＝縦横の線・格子**として見える。`contrast(C)` は `0.5 − 0.5/C` 以下を黒に落とす。
  **強くしすぎると薄い雲まで消える**ので、上げるときは両方を確かめること
- pane は雨雲とは別の `mapSat`（外側の箱は `mapSatMask`、z-index 375）。
  雨雲・雷（380）より下に敷き、レーダーが雲の上に来るようにする。
  合成のために分けている（同じpaneに入れると雨雲まで一緒に薄まる）。
  **合成は外側の `mapSatMask` に掛ける。** `mix-blend-mode` はいちばん近い祖先の
  スタッキングコンテキストの中でしか下と混ざらないので、内側の `mapSat` に掛けても
  ベースマップと混ざらず**黒いまま**になる
- 現在地まわりのマスク（§17.2）は `SPOT_PANES` に両方の組を並べて掛けている

### 18.2 自動更新

ナウキャストは5分、ひまわりは10分ごとに更新される。地図を開けっぱなしにしていると
古い絵のままになるので、`WX_REFRESH_MS`(5分) ごとに `refreshWeatherLayers()` で貼り直す。

- **時刻表のキャッシュはURLをキーにして捨てられるようにしてある**（`clearWxTimes()`）。
  ここを捨てないと、貼り直しても同じ basetime のままで意味が無い
- **新しいタイルが1枚出るまで古いレイヤーを消さない**（`addTimedTileLayer` の
  `replace` 引数）。先に消すと更新のたびに一瞬まっさらになる。
  逆に、新しい方が取れなかったときも古い方を落とす（`tileerror` 側でも `dropPrev`）
- アメダスは点で描くので、`amedasData` を捨ててから描き直す
- タイマーは**地図を開いている間だけ**。`openMap` で開始し `closeMap` で止める
  （見ていない間は通信しない）。再度開いたときは即座に一度貼り直す

### 18.3 バンド切替も貼り替えと同じ道を通す（続きは §19）

`setSatBand()` は `addTimedTileLayer(def, opacity, true)` を呼ぶ。
自動更新と同じ「新しいのが出てから古いのを消す」経路なので、
切り替えても画面が一瞬空にならない。

## 19. ピンは長押しで立てる（v4.56.0）

「ピンが触れたところにすぐ置かれちゃうのが不快。意思を持ってタップした時だけ
ピンが立つようにして欲しい」への対応。**`map.on('click')` での地点確定をやめた。**

地図はまず「見る」ためのもので、拡大・パン・レイヤー確認のたびに指が触れる。
そのたびに地点が変わって逆ジオコーディングと再取得が走るのは邪魔でしかない。

### 19.1 操作

| 操作 | 結果 |
|---|---|
| タップ（短い） | 何も起きない。下の案内文が光る（迷わせないため） |
| 押している途中で動かす | 取り消し。地図のパンとして扱われる |
| 長押し `PIN_HOLD_MS`(500ms) | ピンが立つ。振動でも知らせる |

- 押している間は `#pin-hold` の輪が締まっていくので、**あとどれくらいで確定するかが見える**。
  閉じる時間はJSから `animationDuration` に入れる（**CSSに秒数を二重に持たない**）
- `PIN_HOLD_SLOP_PX`(12px) を超えて動いたら取り消す
- 手袋でも分かるよう `navigator.vibrate(15)` を鳴らす（対応端末のみ）

### 19.2 注意点

- **緯度経度は押した時点で控える。** 離してから求めると、その間に地図が動いていた場合
  押した場所とずれる。回転中は `patchRotatedInput` の補正も要る（§17参照）
- **ダブルタップ拡大の1回目のタップは「短いタップ」に見える。** そのまま案内を光らせると
  拡大するたびにチカチカするので、`flashPinHint()` は `DTAP_MS` 待ってから
  `dtapLastAt` を見て、直前に拡大操作をしていれば出さない
- **`bindPinLongPress` は地図コンテナのバブリング側で聞く**（`bindDoubleTapZoom` は
  親要素のキャプチャ側）。ダブルタップ拡大の2回目以降は親で `stopPropagation` されるので、
  長押し側には届かない＝拡大操作中に誤ってピンが立つことがない
- `passive: true` で聞く（`preventDefault` しない）。**Leafletのパンを邪魔しないこと**
- 地図を閉じるときに `cancelPinHold()`。押しっぱなしで閉じても後からピンが立たないように

## 20. 追跡をonにするとレイヤーが消える（v4.57.0 で修正）

「追跡をオンにした時と外した時でレイヤーが異なる？のはなぜ？」への回答と修正。
**現在地スポットライト（§17.2）が、雨雲・衛星のレイヤーを丸ごと消していた。**

### 20.1 原因

**CSSのマスクは「実寸のある箱」にしか効かない。Leafletのpaneは 0×0 である。**

paneは `position:absolute; left:0; top:0` だけで幅も高さも持たず、タイルは
はみ出して描かれている（`overflow` は visible）。この 0×0 の箱に `mask-image` を
掛けると、マスクの塗り領域が 0×0 になり、**要素の中身が全部マスクの外＝消える**。

つまり追跡on＝雨雲が全部消える、追跡off＝戻る、という挙動になっていた。
「自分の周りだけ晴れる」どころか「全部晴れて」いた。

`mask-clip: no-clip` も試したが、Chromiumでは計算値は `no-clip` になるものの
描画は変わらず消えたままだった（実験して確認）。使えない。

### 20.2 直し方

**マスク専用の入れ物 pane を1枚挟み、そちらに画面ぶんの実寸を持たせる。**

```
mapNowcastMask (z:380)  ← 実寸あり。ここに mask-image を掛ける
  └ mapNowcast          ← タイルはこちら。入れ物のずらしを打ち消す
```

`map.createPane(name, container)` の第2引数で親を指定して入れ子にできる。

入れ物は毎回こう置き直す（`paintMeSpotlight`）:

| 要素 | left / top | 寸法 |
|---|---|---|
| `mapNowcastMask` | `-o.x` / `-o.y` | `map.getSize()` |
| `mapNowcast` | `+o.x` / `+o.y` | （既定のまま） |

`o = map._getMapPanePos()`。map pane はパンしたぶんだけずれているので、
それを引いて入れ物を画面の左上に合わせ、中身を同じ量だけ逆に動かして元の位置に戻す。

- **同じ `o` を使う限り差し引きは必ず 0 なので、タイルは絶対にずれない。**
  1フレーム遅れて更新されても穴の位置が遅れるだけなので、rAF で間引いてよい
- 入れ物の左上＝画面の左上になるため、**穴の中心は `latLngToContainerPoint`**
  （レイヤ座標ではなく画面座標）でよい
- 追跡を止めたら、マスクだけでなく**ずらしも元に戻す**

`map pane` のずれは**パンを重ねるほど際限なく育つ**（実測：40回パンで 16,000px 超。
ズームやドラッグ終了でも 0 には戻らない）。だから「大きめの固定サイズ」では駄目で、
毎回 `o` を見て置き直す必要がある。

### 20.3 テストは画素で見ること

**スタイルの検査だけでは、レイヤーが消えていることに気づけない。**
実際 v4.53.0 のテストは「`radial-gradient` が入っていること」を見て通っていた。

`smoke_mapui` では、雨雲のスタブタイルだけ色を変えたうえで、追跡の on/off で
スクリーンショットを比べている。

- **穴の外（中心から200px下）… 変わってはいけない**（消えていたら変わる）
- **穴の中（中心の78px左、マーカーには掛からない位置）… 変わらねばならない**

比較する場所に他の要素（矢印・ピン・ズームボタン）が乗っていないことも
`elementFromPoint` で先に確かめている。

## 21. 地図の操作ボタン（v4.58.0）

「ヘディングアップやノースアップをグラフィカルな表示にしてほしい」
「自位置に戻るボタンをもう一度押すと追跡モードに切り替わる仕様が好み」
「このボタン2つを右上に並べれば現在地ボタンを消せますよね？」への対応。

右上に **レイヤー（ピル）／方位（丸）／現在地（丸）** の3つを縦に並べ、
**下部にあった「現在地」ボタンは廃止**した。

### 21.1 方位バッジ

スーパー地形の方位バッジと同じ考え方。**絵そのものが状態を表す。**

- 環と N が**実際の北**を向いて回る（`rotate(mapRotationDeg)`）
- **スマホの絵は回さない。** これが「手に持っている端末」を表すので、
  N との角度差がそのまま「端末に対して北はどっち」になる
- ノースアップ … N は真上／ヘディングアップ … **N が真横**（東を向いていれば左）
- ヘディングアップ中は環と N が**赤**（`--c-col`）。色でも一目で分かるようにしてある

実装の注意:

- **N の文字だけは逆回転させて立てる**（`paintCompass()`）。一緒に回すと読めない。
  回転の中心は文字の位置 (22,7) であって環の中心 (22,22) ではない
- N は環の線の上に載るので、`paint-order: stroke` ＋ `--surface` 色の太いフチを付けて
  線が文字を横切らないようにしている
- `applyMapRotation()` から `paintCompass()` を呼ぶ。方位が変わるたびに環が追従する

### 21.2 現在地ボタン（3段階）

押すたびに `off → once → follow → off` と回る（`cycleLocate()` / `locateMode`）。

| 状態 | 動き | 見た目 |
|---|---|---|
| `off` | — | 灰色の十字 |
| `once` | 現在地へなめらかに寄り、**その地点を選ぶ**（天気も更新） | 青 |
| `follow` | 地図が現在地を追い続ける | 青＋**隅に印** |

- **`once` は `watchPosition` するが追従しない**（現在地マーカーは出るが地図は動かない）。
  `follow` で `mapFollow = true` になる
- **地点を選ぶのはこのボタンの役目。** §19 で地図のタップからピン立てを外したので、
  「現在地の天気を見る」入口はここだけになった。
  **ボタンを押すのは意思のある操作なので、長押しの決まりとは矛盾しない**
- ヘディングアップ（§21.1）は向きだけ変えても使いにくいので `follow` を立てる
- 色は `--gps-col`。現在地マーカーと同じ青にしてある（暗色時は明るい青へ差し替え）

### 21.3 テスト

`smoke_mapui` で、3段階が順に回ること・`follow` のときだけ隅の印が出ること・
`once` で地点名が入ること（下部ボタンの役目を引き継げていること）・
下部の `#btn-map-gps` が消えていることを見ている。
方位は環の `transform` が北へ回ること、**N の文字だけ逆回転すること**、
**スマホの絵に `transform` が付かないこと**、ヘディングアップで環の色が変わることを見る。

## 22. スポットライトの大きさ（v4.59.0）

「自位置の周りの輪っかが大きすぎる。雲の配置を確認しようと思ったら
自分の位置の切り抜きが大きすぎて何もできない。
青い周りの白いラインから1〜2倍の範囲をふわっと抜けさせる感じで」への対応。

**大きさは現在地マーカーを基準に決める。**

```js
const ME_DOT_R = 10;                   // .me-dot（16px＋白フチ2px）の外半径
const SPOT_CLEAR_PX = ME_DOT_R + 1;    // 11px：マーカーのぶんだけ完全に抜く
const SPOT_FADE_PX  = ME_DOT_R * 2.6;  // 26px：白フチの1〜2倍ぶんでふわっと戻す
```

以前は 46px / 130px で、**抜ける範囲が直径260px**あった。画面幅390pxの3分の2である。
これでは自位置のまわりの雲・雨がまったく読めない。**マーカーの白フチのすぐ外側だけ**が
ふわっと抜ける程度に留めること。

数値を直接書かず `ME_DOT_R` から導いているのは、マーカーの寸法を変えたときに
スポットライトだけ取り残されるのを防ぐため。**`.me-dot` の大きさを変えたら
`ME_DOT_R` も合わせること。**

テストで画素を比べる場所も、この大きさに合わせて中心の20px左に寄せてある
（方位の扇は右を向いているので左が安全）。

## 23. 地図の全画面化（v4.60.0）

「地図表示をする上で全画面表示ができないのがかなり痛い。上下の帯は消せないの？」への対応。

### 23.1 帯には2種類ある

| 帯 | 正体 | 対処 |
|---|---|---|
| ブラウザの帯 | Safariのアドレスバー・ツールバー | **ホーム画面に追加**すれば消える（manifestは元から `display: standalone`）。iPhoneのSafariでは Fullscreen API が動画以外に使えないので、これが唯一の道 |
| アプリ自身の帯 | ヘッダー・検索行・円柱・案内文 | 本節で全部浮かせた |

### 23.2 実測（画面高664pxで計算）

| 部分 | 以前 | いま |
|---|---|---|
| ヘッダー（「地点を選択」＋✕） | 60px | 0（✕を丸ボタンにして地図の上へ） |
| 検索行 | 61px | 0（浮かせた） |
| お気に入り円柱 | 49px | 0（浮かせた） |
| 案内文 | 31px | 0（浮かせて自動で消す） |
| **地図に使える高さ** | **463px（70%）** | **664px（100%）** |

### 23.3 実装の要点（ここを外すと壊れる）

- ⚠⚠**浮かせた器は `pointer-events: none`、直接の子だけ `auto`。**
  器がタップを食うと**帯の下の地図が触れなくなり、全画面にした意味が無くなる**。
  `#map-top` と `#map-bottom` の両方に要る
- ⚠**z-index は 1100。** Leaflet標準のコントロールが 1000 なので、
  550 のままだと隠れる（実際に閉じるボタンが +/- の下に隠れて見えなくなった）
- **Leaflet標準の +/- は出さない**（`zoomControl: false`）。左上は「閉じる」の場所。
  拡大縮小はピンチとダブルタップ＋上下ドラッグ（§17.1）で足りる
- **`.map-round` は id で縛らないこと。** `#map-tools button.map-round` と書いていたため、
  `#map-tools` の外に出した閉じるボタンに丸ボタンの見た目が付かなかった
- **案内文は開いた直後だけ**（`MAP_HINT_MS` = 4.5秒）出して消す。
  全画面にした以上、常時出して地図を隠す価値は無い。短いタップ（§19）で呼び戻す
- **出典表記は消さないこと**（§8.2 の利用条件）。浮かせた下段に地点名と並べてある
- `#map-stage` の `overflow: hidden` は**引き続き必要**。閉じたレイヤーパネルを
  `translateY(101%)` で下へ逃がしているので、切り抜かないと浮いた円柱を覆う

### 23.4 safe-area（ホーム画面から起動したとき）

`apple-mobile-web-app-status-bar-style: black-translucent` を指定しているのに
`viewport-fit=cover` と safe-area の逃げ幅が無かった。全画面にするなら必須なので入れた。

- viewport meta に `viewport-fit=cover`
- 逃げ幅は **`:root` の `--sa-top` / `--sa-bottom`** に集約
- 地図の浮きもの … `top: calc(8px + var(--sa-top))` /
  `padding-bottom: calc(6px + var(--sa-bottom))`

⚠⚠**`viewport-fit=cover` はアプリ全体に効く。全画面のかぶせ画面すべてに逃げ幅が要る。**

| 画面 | 上 | 下 |
|---|---|---|
| 本体 | `#header` | `#footer` |
| 地図 | `#map-top` | `#map-bottom` |
| ランキング | `#rank-header` | `#rank-list` / `#snow-list` |
| お気に入り | `#fav-header` | `#fav-save-btn` |

**v4.60.0 でランキングとお気に入りを入れ忘れた。** 「ランキング」の文字が時計に重なり、
✕ がステータスバーに潜って**画面から戻れなくなった**（iOSはステータスバー領域の
タップがページに届かない）。v4.60.1 で修正。

**`env(safe-area-inset-*)` を直接書かないこと。** 変数を通さないと §23.6 の検査を
すり抜ける。直書きが混ざっていないかもテストで見ている。

### 23.6 safe-area のテスト

`env()` は headless Chromium では常に 0 なので、そのままでは検査できない。
だから逃げ幅を CSS 変数にしてある——**テストが `--sa-top` / `--sa-bottom` を
差し替えて、全画面ぶんまとめて検査する**。

各画面の「いちばん上にある押せるもの」（`btn-map` / `btn-map-close` /
`btn-rank-close` / `btn-fav-close`）について、

- `getBoundingClientRect().top >= --sa-top`（ノッチの下から始まっているか）
- `elementFromPoint` で本当に押せるか

の両方を見る。画面を1つ足したら、この配列にも足すこと。

### 23.5 全画面化のテスト

`smoke_mapui` に「地図が画面いっぱいか」「浮かせた帯の外側が地図に触れるか」
「✕と検索が押せるか」「出典が見えているか」「案内文が消えるか」を足した。

**`elementFromPoint` は `#map` の中かどうかで判定する。** 地図上のマーカー
（アメダスのピン等）に当たることがあるので、`=== 'map'` で見ると誤検出する。

**HTMLの入れ子が壊れると、他の画面が地図の中に紛れ込んで「見えない」だけになる。**
実際に `#map-bottom` の閉じ忘れでランキング画面が地図の中に入り、
`smoke_rank` が原因の見えないタイムアウトで落ちた。
`#rank-overlay` などが `#map-overlay` の外にあることを直接見るようにしてある。

## 24. 雷を「雷らしく」見せる（v4.61.0）

「雷ゾーンがちょっとパッと見分かりにくい。Windyみたいに縦Zの雷マークを入れて
周辺ボカシを入れて、見た目で『雷なってるんだなー』ってわかるようにして欲しい」への対応。

気象庁の雷ナウキャストはべた塗りの多角形で、黄色や橙が何を意味するのか色だけでは分からない。

### 24.1 やったこと

| | |
|---|---|
| **ぼかし** | レイヤーの入れ物に `filter: blur(5px) saturate(1.35)`（`.wx-glow`） |
| **雷マーク** | 縦Zの稲妻SVGを塗りの上に散らす。黄色＋橙の drop-shadow で光らせる |

⚠**ぼかしは pane ではなくレイヤーの入れ物（`.leaflet-layer`）に掛けること。**
雷は雨雲・衛星と同じ `mapNowcast` pane に載っているので、paneに掛けると全部滲む。
レイヤー定義の `glow: true` で付ける。

### 24.2 マークの置き場所はタイル画像から読む

雷の範囲はタイル画像しか情報が無いので、**画像そのものを読んで決める**。

1. 画面と同じ大きさのcanvasに、いま出ている雷タイルを並べ直す
2. `THUNDER_CELL_PX`(92px) の格子に区切る
3. 各マスを `THUNDER_STEP_PX`(4px) おきに読み、不透明な画素が
   `THUNDER_MIN_HITS`(7) 以上あればそのマスに雷があるとみなす
4. 塗られた画素の**重心**にマークを置く。濃い順に `THUNDER_MAX_ICONS`(26) まで

タイルの位置は「タイル座標 → そのズームの世界座標 → 緯度経度 → 画面座標」で出す。
`getBoundingClientRect` を使わないのは、**ヘディングアップで地図を回すと外接矩形が
狂う**ため（§17参照）。

⚠**タイルは別ドメインなので、canvasが汚染されると `getImageData` が例外を投げる。**
握りつぶして「ぼかしだけ効いた状態」に落ちる。マークが出なくても地図は壊れない。

### 24.3 テストの落とし穴

**塗りを広くすると検査が意味を失う。** 最初はタイルの1/4を塗った素材で
「マークの近くに塗りがあるか」を見ていたが、**画像を読まず格子状に置くだけの実装でも
通ってしまった**（塗りが広いのでどこに置いても近くに塗りがある）。

素材をタイルの面積の3.5%だけ塗るように変え、格子状に置く実装が落ちることを
確かめてある。**この手の検査は「壊した版で落ちるか」を必ず確認すること。**

## 25. CS立体図（v4.62.0）

「CS立体図もレイヤーに入れたい」への対応。
曲率（Curvature）＋傾斜（Slope）＋陰影の合成で、谷筋や微地形が読みやすい。
長野県林業総合センターの戸田堅一郎氏の考案。

⚠**これだけ地理院ではなく第三者の配信を見に行く。**

- `https://map.ecoris.info/tiles/csmap/{z}/{x}/{y}.png`
- **URLも利用条件も開発環境から確認できていない**ので `unverified: true`。
  UIには「要確認」バッジが付き、タイルが1枚も取れなければパネルに理由が出る
- 出典は `エコリス地図タイル（CS立体図）`。**地理院と混同しないこと**
- 配信元を変えるときは `MAP_OVERLAYS` の `url` と `attribution` を差し替えるだけでよい
- 地形なので中身が変わらない。SWの `TILE_HOSTS` に `map.ecoris.info` を足してキャッシュ対象にしてある

**赤色立体図風（§5）との排他はしていない。** どちらも全面を覆う立体表現なので
重ねると濁るが、透過スライダーで調整できるようにしてあるので利用者に任せる。

### 25.1 実機の結果（v4.62.0時点）

**表示されなかった。** ただし当時は**失敗の理由がどこにも出ていなかった**——
`watchTileStatus()` を時刻つきタイルにしか付けておらず、ふつうのオーバーレイは
失敗しても黙って空になるだけだった（§26）。

v4.63.0 で次の2つを直した。

- 報告を全タイルレイヤーに付けた。次は「取得できません（z**N**のタイルが無い）」が出る
- **ズーム範囲の決め打ちをやめた**（8〜16 → 4〜17）。
  当てずっぽうの範囲が狭いと、その外では必ず404になり原因が二重になる

### 25.2 実機の結果（v4.63.0）と保留（v4.63.1）

報告が出るようになって、はっきりした答えが得られた。

> **石川県・白山市 z10 →「この範囲に表示なし（z10のタイルが無い）」**

つまり**この配信は石川県をカバーしていない**。URLそのものが間違っているのではなく
（それなら全ズーム・全域で同じ失敗になる）、**配信範囲が限られている**とみてよい。

利用者の判断で**一旦保留**とし、`pending: true` にしてUIから隠した。
火山土地条件図と同じ扱いで、**定義は残してある**。

### 25.3 戻すときにやること

1. **配信範囲の分かるURL**を用意して `url` を差し替える
2. `pending` を消す
3. あわせて**ズーム範囲**と**利用条件**を確認する（どちらも未確認のまま）

`pending` のレイヤーは `loadMapPrefs()` が保存済みの設定からも落とすので、
隠している間に設定が壊れることはない。

## 26. タイルの失敗は必ず報告する（v4.63.0）

⚠⚠**新しいタイルレイヤーを足したら `watchTileStatus(layer, def)` を必ず通すこと。**

v4.62.0 まで、失敗の報告は `addTimedTileLayer()`（雷・衛星）の中にだけ書いてあった。
ふつうのオーバーレイ（`def.url` の分岐）には無かったので、**CS立体図が404を返しても
パネルには何も出ず、利用者からは「表示されない」としか見えなかった**。

いまは共通関数になっている。

- タイルが**1枚も**取れず、失敗が3枚を超えたときだけ出す
  （配信範囲の端で一部が欠けるのは正常なので黙る）
- **失敗したタイルのズームを文言に添える。** 配信範囲の問題かズーム範囲の問題かは
  これが無いと切り分けられない
- `mayBeEmpty: true` のレイヤーは「取得できません」ではなく「この範囲に表示なし」

テストは `map.ecoris.info` を404に差し替えて、パネルに理由とズームが出ることを見ている。
報告を外すと落ちることを確認済み。

## 27. メモリ（v4.64.0）

実機で **「問題が繰り返し起きました」** ＝ iOS Safari の Webプロセスのクラッシュを踏んだ。
「いろいろ動かしていると」起きるので、じわじわ食い潰す類の問題。
原因を2種類つぶした。

### 27.1 貼り替えた古いレイヤーが残る（2箇所）

**(a) 外れる道が1本しかなかった。**
`addTimedTileLayer(def, op, true)` は「新しいタイルが1枚出たら古い方を外す」設計だった。
新しい方が**読み込まれも失敗もしない**とき——表示範囲外、ズーム範囲外、応答が返らない——
古い方は地図に残り続け、**5分ごとの自動更新のたびに積み上がる**。

→ `staleWxLayers` に積み、`WX_DROP_MS`(8秒) で**何があっても外す**逃げ道を足した。
`applyOverlays()` と `closeMap()` でも掃除する。

**(b) `await` の前に古いレイヤーを掴んでいた。**

```js
// 悪い例
const prev = overlayTileLayers[id];   // ← ここで掴むと…
const t = await jmaTimes(url);
const layer = L.tileLayer(...).addTo(map);
```

更新が重なると2つの呼び出しが**同じ** `prev` を掴み、片方が作ったレイヤーは
`overlayTileLayers` からも `staleWxLayers` からも外れて**地図に残り続ける**。

→ `prev` は `await` の**あと**に取る。

### 27.2 雷マークの走査で毎回canvasを作っていた

`paintThunderIcons()` は画面サイズのcanvasを作って `getImageData` していた。
これが **`tileload` ごと（rAF間引き）** に走る。タイルは数十枚単位で届くので、
実質毎フレーム数MBの捨てゴミが出る。

- **canvasを使い回す**（`thunderScanCv`）。閉じるときは `width=0` で裏地を手放す
- **画面の半分の解像度で走査する**（`THUNDER_SCAN_SCALE`=0.5 → 画素は1/4）。
  46pxのマスに区切るだけなので精度は十分
- **rAFではなく250msで間引く**（`THUNDER_DEBOUNCE_MS`）
- マークの上限も 90 → 64 に下げた

### 27.3 テストの落とし穴

**タイル画像だけを止めること。** 最初 `**/jmatile/**` を「応答しない」ルートにしたら
`targetTimes` まで止まり、**レイヤーが1枚も作られず検査が空振り**した
（壊した版でも通ってしまった）。`surf/hrpns` だけ止めるように直してある。

**この検査はレイヤーを貼り直すので、画素を見る検査より後ろに置くこと。**
前に置くと、応答しなかったリクエストが残って絵が安定せず、
現在地スポットライトの画素比較が落ちる。

## 28. 自位置は矢尻で描く（v4.77.0）

「自位置追跡中の画面ではピンは不要。自分の進行方向がわかるように、
車のナビのような矢尻マークで自分の位置を表現」への対応。

### 28.1 丸＋扇 → 矢尻

以前は青い丸（`.me-dot`）の上に半透明の扇（`.me-cone`）を重ねていた。
扇は「だいたいこっち」を表すには良いが、**進行方向そのものには見えない**。

車のナビと同じ矢尻（`.me-arrow`）に置き換えた。SVGの1パスで、
青い塗り＋白フチ＋落ち影。回転は `方位 + 地図の回転` で、
ヘディングアップでは差し引き0になり常に上を向く（この計算は扇のときと同じ）。

```
<path d="M20 4 L32 33 L20 25.5 L8 33 Z"/>   viewBox 0 0 40 40
```

- **回転の軸は矢尻の重心**（viewBoxの `20,22`）。`transform-origin: 50% 55%` と
  `margin: -22px 0 0 -20px` で、そこが現在地の座標に来るようにしてある。
  どちらか片方だけ変えると、回すたびに矢尻が現在地からずれて円を描く
- **方位が取れるまでは丸のまま**（`headingKnown`）。方位センサーの許可前や、
  静止していてGPSの `heading` が来ないときに、でたらめな向きの矢尻を出さないため。
  一度でも方位が取れれば矢尻へ入れ替わり、追跡をやめると（`stopTracking`）丸に戻る
- 矢尻は丸より一回り大きいので、スポットライトの `ME_DOT_R` を 10 → 14 にした（§22）

### 28.2 追跡中は選択地点のピンを出さない

自位置が矢尻で分かる以上、同じ場所に重なるピンは目障りなだけ。
`locateMode !== 'off'` の間はピンの要素を `display:none` にする
（レイヤーからは外さない。位置は裏で更新し続け、戻したときにそのまま出る）。

ただし**自分で地点を選んだときは戻す**。何を選んだのか分からなくなるため。
その合図は `releaseFollow()` に置いた。長押し・検索・お気に入り円柱の
どの経路も「自分の意思で選んだ」ときに必ずここを通るので、
判定を1か所に集められる（`pinPickedByUser`）。
現在地ボタンを押し直す（`setLocateMode`）と、この印は下ろす。
