# SotoKi 地図選択画面 要件定義書

作成日: 2026-07-31
対象: 地図選択画面（レイヤー切替・標高取得・タイルキャッシュ）

> **メモ（実装時に判明）**: 本文冒頭に「§13 の運用ルールを必ず読むこと」とあるが、
> 本文書は §12 で終わっており §13 は存在しない。§2 の制約条件のみを前提に実装した。
> 実装状況と積み残しは末尾の「§14 実装メモ」を参照。

---

## 1. 目的とスコープ

### 1.1 目的
バックカントリーでの地形判読を支援するため、地図選択画面に複数のベースマップと地形オーバーレイを追加する。あわせて選択状態の永続化と、訪問済みタイルの自動キャッシュを実装する。

### 1.2 スコープ内
- ベースマップの切替（5種）
- 地形・情報オーバーレイの重ね合わせ（6種、透過率調整可）
- 赤色立体図風の合成表示
- 選択地点の標高自動取得
- Service Worker によるタイル自動キャッシュ
- 選択状態の localStorage 永続化

### 1.3 スコープ外（別フェーズ）
- MapLibre GL への移行
- 標高タイル演算による赤色立体図・CS立体図の本実装
- 範囲指定によるタイル事前ダウンロード
- ABC判定ロジックの変更

## 2. 制約条件

| 項目 | 内容 |
|---|---|
| 地図ライブラリ | Leaflet を継続使用（移行しない） |
| 気象データ | Open-Meteo のみ |
| 禁止ライブラリ | leaflet-velocity |
| ABC判定ロジック | 一切変更しない |
| コード規約 | ES6+、コメントは日本語、camelCase |
| 破壊的変更 | 実行前に確認 |

## 3. ベースマップ仕様

排他選択（常に1つのみ有効）。

| ID | 名称 | タイルURL | ズーム | 出典表記 |
|---|---|---|---|---|
| `std` | 標準地図 | `https://cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png` | 5–18 | 国土地理院 |
| `pale` | 淡色地図 | `https://cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png` | 5–18 | 国土地理院 |
| `photo` | 航空写真 | `https://cyberjapandata.gsi.go.jp/xyz/seamlessphoto/{z}/{x}/{y}.jpg` | 2–18 | 国土地理院 |
| `osm` | OpenStreetMap | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` | 0–19 | © OpenStreetMap contributors |
| `esri` | 衛星画像 | `https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}` | 0–19 | Esri, Maxar, Earthstar Geographics |

**注記**
- 既定値は `pale`。オーバーレイの下地として最も視認性が高い。
- Esri はURLのタイル座標順が `{z}/{y}/{x}` である点に注意。
- OSM はタイル利用ポリシー上、大量の先読み取得が禁止されている。本件は訪問済みキャッシュのみのため適合するが、事前ダウンロード機能を将来追加する場合は OSM を対象外とすること。

## 4. オーバーレイ仕様

複数同時有効可。各レイヤーに透過率スライダー（0–100%）を持つ。

| ID | 名称 | タイルURL | ズーム | 既定透過率 | 用途 |
|---|---|---|---|---|---|
| `slope` | 傾斜量図 | `https://cyberjapandata.gsi.go.jp/xyz/slopemap/{z}/{x}/{y}.png` | 3–15 | 50% | 斜度判断 |
| `hillshade` | 陰影起伏図 | `https://cyberjapandata.gsi.go.jp/xyz/hillshademap/{z}/{x}/{y}.png` | 2–16 | 50% | 立体感・谷筋把握 |
| `rrimLike` | 赤色立体図風 | 合成（§5参照） | 3–15 | 70% | 微地形判読 |
| `relief` | 色別標高図 | `https://cyberjapandata.gsi.go.jp/xyz/relief/{z}/{x}/{y}.png` | 5–15 | 40% | 標高帯の把握 |
| `gazo1`–`gazo4` | 過去空中写真 | `https://cyberjapandata.gsi.go.jp/xyz/gazo1/{z}/{x}/{y}.jpg` 他 | 地域差あり | 100% | 林相・地形変化 |
| `volcano` | 火山土地条件図 | **実装前に要確認** | 火山域限定 | 60% | 那須・燧・火打 |

### 4.1 ズーム範囲外の扱い
- 各レイヤーに `maxNativeZoom` / `minNativeZoom` を設定する。
- ネイティブ範囲を超えた場合はオーバーズーム表示とし、レイヤーが空白にならないこと。
- 特に傾斜量図は z15 が上限のため、`maxNativeZoom: 15, maxZoom: 18` を必須とする。

### 4.2 排他制御
- `rrimLike` を有効化した場合、`slope` と `hillshade` の単独トグルは自動的に無効化する（二重描画防止）。

## 5. 赤色立体図風 合成仕様

### 5.1 方式
陰影起伏図を下地、傾斜量図を上に `mix-blend-mode: multiply` で重ねる。傾斜量図の赤系彩度と陰影の明暗が乗算され、赤色立体図に近い見え方になる。

### 5.2 実装方針
- Leaflet の専用 pane を作成し、そこに2枚の TileLayer を配置する。
- pane に対して CSS で `mix-blend-mode` を適用する（個別タイル画像ではなく pane 単位）。
- 合成レイヤー全体の不透明度は pane の `opacity` で制御する。
- 有効ズームは傾斜量図に合わせ 3–15（超過分はオーバーズーム）。

### 5.3 留意点
- `mix-blend-mode` は iOS Safari で描画が重くなる場合があるため、実機でスクロール性能を確認する。
- 期待どおりの発色にならない場合は、`multiply` の代わりに `overlay` や、傾斜量図側に CSS フィルタ（`saturate` / `hue-rotate`）を併用して調整する。

## 6. 選択地点の標高自動取得

### 6.1 データソース
国土地理院 標高タイル（PNG形式）
`https://cyberjapandata.gsi.go.jp/xyz/dem_png/{z}/{x}/{y}.png`

### 6.2 処理フロー
1. 選択地点の緯度経度からタイル座標とタイル内画素座標を算出
2. 該当タイルPNGを取得（`crossOrigin = 'anonymous'`）
3. Canvas に描画して該当画素の RGB を取得
4. 標高に換算する
   - `x = R * 65536 + G * 256 + B`
   - `x < 2^23` のとき `標高 = x * 0.01`（m）
   - `x = 2^23` のとき 無効値（NA）
   - `x > 2^23` のとき `標高 = (x - 2^24) * 0.01`（m）

### 6.3 要件
- 取得した標高は地点データとともに保存し、同一地点で再取得しない。
- 取得失敗・無効値の場合は標高欄を非表示にし、地図機能全体は停止しない。
- 取得は非同期で行い、地図描画をブロックしない。
- 負荷は1地点あたりPNG1枚（数KB）であり、既存の地点数であれば無視できる。

## 7. キャッシュ要件

### 7.1 方針
Service Worker による訪問済みタイルの自動キャッシュのみ。事前ダウンロードは実装しない。

### 7.2 詳細
| 項目 | 仕様 |
|---|---|
| キャッシュ名 | `sotoki-tiles-v1`（アプリシェルとは分離） |
| 戦略 | cache-first。ヒット時は即返却し、バックグラウンドで更新しない |
| 対象 | 本要件で定義したタイルドメインのみ |
| 容量上限 | 150MB |
| 削除方式 | 上限超過時に LRU（最終アクセス時刻を IndexedDB で管理） |
| 使用量表示 | `navigator.storage.estimate()` で設定画面に表示 |
| 手動削除 | 設定画面に「タイルキャッシュを削除」ボタンを設置 |

### 7.3 留意点
- iOS の PWA はストレージ上限が厳しく、OS側で削除される可能性がある。上限値は実機計測後に調整する。
- キャッシュ削除は破壊的操作のため、実行前に確認ダイアログを表示する。

## 8. UI要件

### 8.1 レイヤーパネル
- ボトムシート形式。地図画面からボタン1つで開閉。
- 上段: ベースマップ（ラジオ選択、サムネイル付き）
- 下段: オーバーレイ（トグル + 透過スライダー）
- タッチターゲットは全て 44px 以上
- スライダーはドラッグ中もリアルタイムに地図へ反映

### 8.2 出典表記
- 地図右下に常時表示。
- 有効なベースマップとオーバーレイに応じて動的に更新する。
- 地理院タイル・OSM・Esri いずれも出典表示が利用条件であるため、非表示・省略は不可。

### 8.3 テーマ・アクセシビリティ
- `prefers-color-scheme` による light / dark 切替
- WCAG AA コントラスト比を満たす
- パネル内のフォーカス順序が論理的であること

## 14. 実装メモ（v4.46.0 時点）

### 14.1 §11 の要確認事項の扱い

開発環境から `cyberjapandata.gsi.go.jp` などの外部ホストに到達できないため
（プロキシが CONNECT に403）、4項目とも**未確認のまま**である。
推測でURLを埋めることはしていない。実機で確認して埋めること。

| # | 項目 | 実装での扱い |
|---|---|---|
| 1 | 火山土地条件図のタイルID | `MAP_OVERLAYS` に `pending: true` で定義してある。**pendingのレイヤーはUIに出ない**ので、URLとズーム範囲を埋めて `pending` を消せば그대로出る |
| 2 | 過去空中写真のカバー範囲 | `gazo1`〜`gazo4` を定義済み。範囲外は空タイルになるだけで壊れない。UIに「地域により配信なし」と注記を出している |
| 3 | Esri の attribution 文言 | §3 の表にある `Esri, Maxar, Earthstar Geographics` をそのまま使用。正式表記が違えば `MAP_BASES` の `attribution` を直すだけ |
| 4 | iOS のストレージ実測値 | 上限は `TILE_CACHE_LIMIT_BYTES`（sw.js）の1定数。実測後に変更する |

### 14.2 仕様と実装が違う点

- **「設定画面」が存在しない。** 本アプリに設定画面が無いため、キャッシュ使用量の表示と
  削除ボタンは**レイヤーパネルの最下段**に置いた。設定画面を作るならそちらへ移すこと。
- **light/dark 切替はレイヤーパネルと地図画面のみ。** アプリ本体は light 固定の配色で、
  全体のダークテーマ化は本要件の範囲を超える。地図画面は全画面オーバーレイなので、
  ここだけダーク対応しても本体と並んで見えることはない。
- **地図の最大ズームは18。** OSM と Esri は z19 まで配信しているが、地理院のオーバーレイに
  合わせて18で止めている（z19 にすると傾斜量図などの引き伸ばしが4倍になり粗くなるため）。

### 14.3 標高の扱い（既存の値と混ぜないこと）

- `state.elevation` … **Open-Meteo が返すモデル格子の標高**。従来どおり
  `fetchSupplemental` に渡して地形条件を揃えるのに使う。**変更していない**
- `state.demElevation` … 標高タイルから読んだ**実際の地点標高**。表示用
- 表示は `displayElevation()` が DEM を優先し、無ければモデル標高に落ちる

ABC判定は本体の気象データだけで決まり、どちらの標高にも依存しない。

## 15. 気象レイヤー（v4.47.0 で追加）

利用者の依頼で「アメダス・降雨レーダー・雷・風を重ねたい」を追加した。
**§2 の「気象データは Open-Meteo のみ」を緩めている**（降雨レーダー等は Open-Meteo に
配信が無いため気象庁を使う）。定義は `MAP_WEATHER`。

| ID | 名称 | 方式 | 出所 | 状態 |
|---|---|---|---|---|
| `radar` | 降雨レーダー | 時刻つきタイル | 気象庁 高解像度降水ナウキャスト | **実機で表示確認済み**（v4.48.0） |
| `thunder` | 雷 | 時刻つきタイル | 気象庁 雷ナウキャスト | **未表示**（時刻表は取れるがタイルが404。ズーム上限を8に下げて再挑戦中） |
| `amedas` | アメダス | 点（マーカー） | 気象庁アメダス | **実機で表示確認済み**（v4.48.0） |
| `windArrows` | 風向風速 | 点（マーカー） | Open-Meteo | 実装済み |

### 15.1 Windyのようなアニメーション風速は実装していない

§2 の禁止ライブラリ `leaflet-velocity` がまさにその用途のため。代わりに
**画面を5×5に割った代表点の風を Open-Meteo から1リクエストで取り、矢印で置く**方式にした。
アニメーションはしないが、風向と強さは読める。15m/s超は赤（チャート側と同じしきい値）。

矢印の向きは `風向 + 180°`。風向は「吹いてくる方角」なので、進む向きは逆になる。
**`wind_speed_unit=ms` を付けている**（既定km/h。ここでも同じ罠）。

### 15.2 targetTimes は種別ごとに別ファイル

**降水は `targetTimes_N1.json`、雷・竜巻は `targetTimes_N2.json`。**
実機で降水（N1 + `hrpns`）は表示できたが雷（N1 + `thns`）は取得できなかったため、
雷だけ N2 を見に行くようにした（v4.48.0）。**雷はまだ実機未確認。**

レイヤー定義の `timesFile` で切り替える。時刻表は種別ごとにキャッシュする。

### 15.2.1 雷が出ない件（v4.50.0時点）

実機では雷だけタイルが404。**時刻表(N2)の取得は成功している**（失敗していれば
エラー文言に `（HTTP xxx）` が付くが、付いていなかった）ので、残るのはタイルのパスか
ズーム範囲。雷ナウキャストは降水より粗いメッシュと見て `maxNativeZoom` を 10→8 に下げた。

**雷が観測されていない時間帯はタイル自体が無い**可能性もある。区別できないので、
`mayBeEmpty: true` の付いたレイヤーは「取得できません」ではなく
「この範囲に表示なし」と出す。あわせて**失敗したタイルのズーム**を文言に入れてあるので、
まだ出ない場合はその数字で切り分けられる。

### 15.3 ナウキャストのURL

`targetTimes_N1.json` から `basetime` / `validtime` を引いて

```
https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/{element}/{z}/{x}/{y}.png
```

を組み立てている。開発環境から到達できず**URLの形を確認できていない**ため、
`unverified: true` を付けてパネルに「要確認」バッジを出している。
火山土地条件図と違って候補URLがあるので、隠さず出して実機で試せるようにした。

**タイルが1枚も取れなければパネルに「取得できません」と出る**（`tileerror` を数えている）。
黙って空にならないので、URLが違えばすぐ分かる。

### 15.4 気象レイヤーはキャッシュしない

`www.jma.go.jp` を `TILE_HOSTS` に入れていない。レーダーや雷は時間で中身が変わるので、
古いタイルを返すと嘘になる。**ここにホストを足さないこと。**

### 15.5 点で描くレイヤーの間引き

アメダスは全国1,300地点あるので、`z8` 未満では出さず、表示範囲内かつ最大140地点までに絞る。
風は `z7` 未満で出さない。出さないときは理由をパネルに表示する（黙って消えない）。
**UIの文言に「z8」などのズームレベルを出さない。** 利用者に「z7とは？風速？」と
聞かれたので、「もう少し拡大すると表示されます」という言い方に変えた（v4.48.0）。
**選んだ要素を観測していない地点はピンを出さない。**「—」だけのピンが散らかるため。

### 15.6 アメダスは表示する要素を選べる（v4.49.0）

気温／風／降水／積雪／湿度（`AMEDAS_ELEMENTS`）。パネルでアメダスを有効にすると
チップが出る。選択は `sotoki.map.amedasElement` に保存する。
地点ごとに観測項目が違うので、選んだ要素を持たない地点は出ない
（例：雨量計だけの地点は「降水」でしか出ない）。

風のときはピンに向きの矢印も付ける。**アメダスの風向は16方位のindex**で来る
（0=静穏, 1=北北東 … 16=北）。度に直すと `index × 22.5`。
**実機で確認済み（v4.50.0）。** 気象庁の宇都宮「東南東 2.9m/s」に対して矢印が
西北西を向いた（風向は吹いてくる方角なので、矢印は +180° 側へ進める）。
なお速度が気象庁の表と一致しないのは、表が1時間値・マップJSONが10分値のため。
地図を動かすたびに `moveend` / `zoomend` で描き直す。

## 16. 操作まわりの変更（v4.51.0）

利用者からの指摘: 「地図で地点を選ぶと、その地点に飛んでさらに最初の画面に戻ってしまうのが
非常にウザい」「地図画面にも現在地ボタンとお気に入りのロータリーダイヤルが欲しい」
「ダイアルの場所に飛ぶ際は一瞬でジャンプではなくスムーズに移動してほしい」。

### 16.1 地点を選んでも地図は閉じない

タップ／検索／円柱のいずれで選んでも `closeMap()` を呼ばない。
`fetchWeather` は裏で走るので、✕で閉じたときには最新のメテオグラムが出ている。
今どこを選んでいるかは左下のバッジ（地点名＋標高）に出す。

**地図を開いている間は全画面の読込オーバーレイを出さない。**
タップのたびに地図が覆われて操作できなくなるため、`showLoading()` が `isMapOpen()` を
見て抑止し、代わりにバッジへ状態を出す。

### 16.2 現在地ボタンとお気に入り円柱を地図の下へ

`#map-bottom` に「現在地」ボタンと `#map-fav-slot` を置いた。

**円柱のDOMは1つだけ。** 地図を開いている間だけスロットへ引っ越し、閉じたら
ヘッダーへ戻す（`moveFavRotaryTo` / `restoreFavRotary`）。
**2つ作らないこと**——寸法計算（`layoutFavRotary`）と選択確定のロジックが二重になり、
必ず食い違う。幅が変わるぶんの再計算は `#fav-rotary` のResizeObserverが拾う。

「現在地」は `fetchGPS({ keepMap: true })` を呼ぶ。地図を閉じずに現在地へ寄る。

### 16.3 移動はなめらかに

`mapFlyTo()` が `flyTo(..., { duration: 0.8 })` を使う。**`setView` の瞬間移動は使わない。**
どこからどこへ動いたのかが分かるようにするため。

## 17. 地図操作の追加（v4.53.0）

### 17.1 ダブルタップ＋上下ドラッグで拡大縮小

Googleマップと同じ片手操作。Leafletに無い操作なので `bindDoubleTapZoom()` で自前実装した。

- 2回目のタップを**押したまま**上下に動かすと連続的にズーム（`DTAP_PX_PER_ZOOM`=90pxで1段）
- ほとんど動かさずに離したら、ふつうのダブルタップとして1段拡大（着地は整数ズーム）
- **追跡中は自分の位置**、そうでなければ**タップした地点**を基準に拡大縮小する
- なめらかにするため地図は **`zoomSnap: 0`**（小数ズームを許す）
- Leaflet標準の `doubleClickZoom` は**切ってある**（自前の操作と取り合いになるため）

#### なめらかに動かすための肝（v4.54.0）

初版は「毎フレーム `setZoom`」で作ったところ、実機でガクガクだった。原因は2つ。

1. **`setZoom` はそのつどタイルを組み直す**ので指の動きに追いつかない。
   ピンチズームと同じ `map._move(anchor, zoom, {pinch: true, round: false})` で
   **変形だけ**動かし、指を離したときに `_animateZoom()` で一度だけ確定させる。
   更新は `requestAnimFrame` で1フレーム1回に間引く
2. **Leafletのパンと取り合っていた。** 同じ指の動きでパンとズームが同時に走り、
   引っぱり合って震えていた。イベントを**地図の親要素でキャプチャ**して
   `stopPropagation()` し、Leafletのハンドラへ渡さないようにした。
   （同じ要素にあとから足しても、Leafletのハンドラのほうが先に動くので効かない）

Leafletの内部関数（`_move` / `_moveStart` / `_animateZoom` / `_limitZoom`）を使っている。
**Leafletのメジャーバージョンを上げるときはここを確認すること。**

### 17.2 現在地のまわりだけ雨雲を抜く

雨のエリアに入ると自位置が雨雲に埋もれて分からなくなる、という指摘への対応。
`mapNowcast` pane に radial-gradient のマスクを掛け、現在地の周囲だけ雨雲を透明にする。

- `SPOT_CLEAR_PX`(46px) までは完全に抜け、`SPOT_FADE_PX`(130px) で元の濃さに戻る
- **ナウキャストとマーカーは pane を分けること。** マスクはpane単位なので、同じpaneに
  入れると**現在地マーカーごと消える**。そのために `mapNowcast`(380) と
  `mapWeather`(400) を分けてある
- マスクは `move`/`zoom` と現在地の更新のたびに貼り直すが、**rAFで1フレーム1回に間引く**。
  `mask` はpane全体を描き直させるので、毎フレーム貼るとズームがカクつく
- 追跡を止めたら外す

### 17.3 宿題

- **フワッと抜ける範囲の調整**（`SPOT_CLEAR_PX` / `SPOT_FADE_PX`）は、実際に雨が
  降っているときに実機で見て決める

## 18. リアルタイム表示（v4.55.0）

「地図画面で雲とか雨の様子とかをリアルタイムでレイヤリングできたりする？」への対応。
足りていなかったのは**雲そのもの**と**自動更新**の2つ。

### 18.1 衛星の雲（ひまわり）

**レーダーは降っている所しか映らない。** 「曇っているが降っていない」を見るには
別の配信が要るので、ひまわりの雲画像を `satellite` レイヤーとして足した。

```
https://www.jma.go.jp/bosai/himawari/data/satimg/{basetime}/jp/{validtime}/{band}/{prod}/{z}/{x}/{y}.jpg
```

- 時刻表は `targetTimes_jp.json`（ナウキャストとは別ファイル）
- バンドは3つ。パネルのチップで切り替え、`sotoki.map.satBand` に保存する
  | id | 表示 | band/prod | 用途 |
  |---|---|---|---|
  | `REP` | カラー | `REP`/`ETC` | 見たままの雲（既定） |
  | `B13` | 赤外 | `B13`/`TBB` | 夜も見える・雲頂高度が分かる |
  | `SND` | 雲頂 | `SND`/`ETC` | 雲頂強調 |
- ズームは `3〜6`。衛星画像は地形図ほど細かくないのでネイティブ上限が低い
- **URLの形は実機未確認**なので `unverified: true`。ナウキャストと同じく
  タイルが1枚も取れなければパネルに理由が出る
- pane は雨雲と同じ `mapNowcast`。現在地まわりのマスク（§17.2）の対象に入れるため

### 18.2 自動更新

ナウキャストは5分、ひまわりは10分ごとに更新される。地図を開けっぱなしにしていると
古い絵のままになるので、`WX_REFRESH_MS`(5分) ごとに `refreshWeatherLayers()` で貼り直す。

- **時刻表のキャッシュはURLをキーにして捨てられるようにしてある**（`clearWxTimes()`）。
  ここを捨てないと、貼り直しても同じ basetime のままで意味が無い
- **新しいタイルが1枚出るまで古いレイヤーを消さない**（`addTimedTileLayer` の
  `replace` 引数）。先に消すと更新のたびに一瞬まっさらになる。
  逆に、新しい方が取れなかったときも古い方を落とす（`tileerror` 側でも `dropPrev`）
- アメダスは点で描くので、`amedasData` を捨ててから描き直す
- タイマーは**地図を開いている間だけ**。`openMap` で開始し `closeMap` で止める
  （見ていない間は通信しない）。再度開いたときは即座に一度貼り直す

### 18.3 バンド切替も貼り替えと同じ道を通す

`setSatBand()` は `addTimedTileLayer(def, opacity, true)` を呼ぶ。
自動更新と同じ「新しいのが出てから古いのを消す」経路なので、
切り替えても画面が一瞬空にならない。
