# 要件定義書（案）: 降雪の目安・雷雨の目安・衛星の注記

**状態: 承認待ち（実装前）。** 承認されるまで `sotoki_v4.html` は触らない。

## 背景

「雲・降雪を地図でグラフィカルに見たい。ここは新雪が降っていそう、ここは曇っていそう、が分かればよい」
（利用者の要望）。きっかけは SCW（supercweather.com）の雲観測マップだった。

調査の結論（2026-10-01）:

- SCW の雲観測マップは**取り込まない**。公式のタイル配信・API の記述が無く、運営（weather-gpv）は
  画像データの配信・販売を行い、著作権は運営に帰属すると明記している。無料の閲覧は
  「9時間前〜3時間前」に制限され、最新は有料会員のみ。このリポジトリは public で、利用者全員の
  ブラウザからアクセスが飛ぶ。
- SCW の雲形・雲頂高度の**算出方法は公開されていない**。
- SCW 自身の注記: 雲観測マップは**積雪を雲と誤判定することがある**。
  → 雲形から「雪が降っていそう」は言えない。降雪は降水と気温で見る。
- 予報モデルは約500m未満の低層雲（盆地の層雲・雲海）を出さない。これは観測（ひまわり）でしか見えない。

→ SCW を使わず、**気象庁（ひまわり・ナウキャスト）と Open-Meteo（どちらも既に使っている）だけ**で作る。
  新しい送信先は増えない。

## 非目標

- SCW のデータ・画像・URL・配色の取り込み、模倣。
- 雲形7分類・雲頂高度の等値線の再現（手法が非公開）。
- ABC評価（`abcScore` / `abcScoreInv` / `judgePoint` / `THRESH`）への接続。**一切触れない。**
- 新雪ランキング（`snowRanking.js`）の変更。あちらは独立のまま。
- 赤外の着色（`SAT_TINTS`）。iOS で効かず撤去済み → `docs/spec/map.md`「衛星の雲」。作り直さない。

## 共通の制約

- **観測と予報を混ぜない。** 凡例・注記・札に「予報モデルの値」「観測（レーダー）」を必ず出す。
- 目安であって判定ではない。閾値は実験パラメータとして1か所の定数表にまとめ、
  「物理的に正しい値ではない」と明記する（`WIND_SHELTER` と同じ扱い）。
- Open-Meteo は `wind_speed_unit=ms`、`elevation=nan`＋`cell_selection=nearest` の既存の作法に従う（ADR-0005 / ADR-0012）。
- 問い合わせの回数: 風の格子と同じ方式（点ごとの控え・差分取得・429 で1分待つ・1回40点まで）。
  ⚠ 同じ回線の枠を風・ランキングも使う（#14）。変数を足すと1点あたりの重みが増えるので、
  **風の取得に相乗りさせず別の取得にする**か、相乗りさせるなら変数を最小にする。段階0で重みを見積もる。
- iOS: 描画は DOM マーカー（`divIcon`）か既存の方式。canvas の画素読みは**1画素のみ**（`probeTileAlpha`）。
- 記号は `pointer-events: none`（地図のタップを奪わない。ピンと同じ作法）。
- 圏外・取得失敗は**黙らない**（帯に理由を出す。ADR-0011 の教訓）。

## 段階1: 衛星の注記

- 衛星レイヤー（`satellite`）の行に、短い注記を足す。
  - 赤外（B13）は低層雲（雲頂が数百m以下）が黒に近く見えにくい。
  - 盆地の層雲・雲海は**予報（雲量）には出ない**。観測（衛星）で見る。
  - 「雲頂」バンド（SND）は色が雲頂高度。凡例の色目盛は気象庁の定義に従う（段階0で出典を確認できなければ、色の目盛は書かず「色が雲頂高度」とだけ書く）。
- 受け入れ条件: 注記が `layer-ov-note` に出る。既存レイヤーの描画・ズーム・自動更新は変わらない。
  `smoke_legend.mjs` / `smoke_mapui.js` が通る。

## 段階2: 降雪の目安レイヤー（`snowHint`）

**何を出すか**: 風の矢印と同じ格子点に、選択時刻の「雨／みぞれ／雪」の小さな記号を置く。
降水がある点だけ（降水が無い点は何も置かない）。

**入力（予報モデルの値）**: 点ごとの `temperature_2m`・`precipitation`（1時間）・モデル標高。
**稜線付近の目安**として、標高は風の AUTO と同じ基準標高 `z_ref`（`terrainRef`）を使う。
気温は**標高補正**する: `T = T2m + 0.0065 × (モデル標高 − z_ref)`。
（`freezing_level_height` が返るなら、それを検証の相方にする。段階0で決める。）

**雨雪の分け方（仮置き・実験パラメータ。`SNOW_HINT`）**: T ≦ 0.5℃ 雪、0.5〜2.0℃ みぞれ、2.0℃ 超 雨。
⚠ 物理的に正しい値ではない。実機の見え方（実際に雪だったか）で調整する。

**観測との関係**: 降雨レーダー（観測）を重ねて見る前提。レイヤーの注記に
「予報モデルの値。実際の降水は降雨レーダーで確認」と出す。
**レーダーで絞る案**（点の位置の1画素を `probeTileAlpha` で読み、レーダーが空の点は記号を消す）は、
格子が約11km、レーダーが1kmで代表性が合わないので、**この段階では入れない**（決めてほしい点1）。

**時刻**: 風と同じ `state.sliderIndex`。地図のタイムスライダー（`updateMapTime`）の出す条件に含める。
**間引き**: ズームが粗い間は出さない（風の `WIND_MIN_ZOOM` と同じ考え方。出さない理由は `setLayerNote` で出す）。
**札**: 記号を押すと、気温（補正前・補正後）・標高・降水量・採用した閾値を出す（風の根拠表示と同じ作法）。

受け入れ条件:
- 凡例（雨・みぞれ・雪の記号と意味）がレイヤー行に出る。
- 取得に失敗したときは理由を出し、点を黙って消さない。
- 429 を受けたら1分待つ（既存の仕組みを使う）。
- ABC評価・ランキングの出力が変わらない（既存テストで確認）。

## 段階3: 雷雨の目安レイヤー（`thunderHint`）

**定義（SCW の説明に倣う。計算はこちら）**: ショワルター安定指数 SSI = T500 − T_P。
T_P は 850hPa（約1,500m）の空気塊を 500hPa（約5,500m）まで持ち上げた温度
（乾燥断熱 → 飽和後は湿潤断熱）。分類: SSI > 0 安定、0 以下で不安定、−3 以下 雷雨の可能性、
−6 以下 激しい雷雨の可能性、−9 以下 激しい雷雨の可能性大。
入力は 850hPa の気温と露点、500hPa の気温（段階0で JMA が返すことを確認する）。
返らなければ `cape` / `lifted_index` で代用するか、段階3自体を見送る（決めてほしい点3）。

- 表示は降雪の目安と同じ格子点・同じ時刻（スライダー）・同じ間引き。
- 雷ナウキャスト（観測）とは別。**予報の目安**と明記する。
- ⚠ SSI は雷雨の「ポテンシャル」で、降水がなくても出る。雨量・雲量が予測されていなくても
  対流性の雲が出ることがある、という意味で使う（SCW の説明と同じ）。
- 山岳での注意（冬の日本海側の雷雪など）は、文言で触れるにとどめる。

受け入れ条件: 段階2と同じ。加えて、SSI の計算は固定入力の単体テストで答え合わせする（検査用の値は別の道具で作る）。
